# BUG-057 — Авто-скачивание НЕ срабатывает на рейтинг-оверлей (регрессия BUG-014)

## Окружение
- Версия приложения: 1.11 (versionCode 12), build bfc8f41a
- Эмулятор: ao3_test_api34 (emulator-5554), Android 10 API 29
- Режим: replay (AO3_MODE=replay, ~RUN-20260805-0437 условия)
- Тема: не указана (по умолчанию)

## Шаги воспроизведения (Given-When-Then)

**Given**
1. Приложение запущено с чистыми данными (fresh database, clean cache)
2. Settings: опция "Auto-download saved works" ВКЛЮЧЕНА
3. Открыта страница работы с валидной download-ссылкой
4. Работа ещё не имеет рейтинга (первичная простановка Favorite)

**When**
1. На странице работы (Browser tab) открывается рейтинг-оверлей (Rating overlay из листинговой страницы либо через Rate-button)
2. Пользователь тапит опцию "Loved" (Rating.SAVE)

**Then (ожидалось)**
- Авто-скачивание ЗАПУСКАЕТСЯ: файл работы загружается в Downloads
- В Library вкладке Loved карточка получает open-иконку (`downloadPath` заполнена)

**Actual (фактически)**
- Авто-скачивание НЕ запускается
- Карточка в Library остаётся с download-иконкой (файл не скачан)
- Этот же сценарий при поднятии вручную ("Download work") работает корректно

## Частота
Всегда при условиях репро (тест TC-032 100% падает на сборке).

## Анализ (failure-analyst)

### Корень дефекта (по исходному коду app-under-test)

Файл: `app/src/main/java/com/example/ao3_wrapper/ui/browser/BrowserViewModel.kt`

Функция `onRateWorkRequested` (вызывается при любом выборе рейтинга из оверлея) содержит дефект чтения "прошлого" рейтинга:

```kotlin
// Строка 1031: записываем НОВЫЙ рейтинг в БД
repo.upsertWorkRating(
    WorkRating(
        ao3Id = workId,
        rating = rating,  // ← НОВОЕ значение
        ...
    )
)
// Строки 1063–1066: проверяем предикат для авто-скачивания
val previousRating = repo.getWorkRating(workId)?.rating   // ← читаем ПОСЛЕ апсерта
if (previousRating != Rating.SAVE && rating == Rating.SAVE && autoDownloadSaved) {
    downloadWork(workId)
}
```

**Проблема**: `previousRating` читается ПОСЛЕ `upsertWorkRating`, поэтому `previousRating` содержит УЖЕ НОВОЕ значение (`rating`), а не старое состояние до сохранения. Условие `previousRating != Rating.SAVE` НИКОГДА не будет истинно, когда `rating == Rating.SAVE`, так как обе переменные содержат одно и то же значение.

**Парное корректное место** для сравнения:
- `savePanelRating` (строка 742–760) — читает `existing` ДО `upsertWorkRating` (строка 742), затем сравнивает `existing.rating` c новым `rating` в строке 756. Фикс коммита 77d65bc применён верно к этому месту.

### Почему severity: major

1. **Полная потеря функции на одном из основных путей ввода** — пользователь не может скачать работу автоматически при первичной простановке Loved через рейтинг-оверлей (основной UI-путь взаимодействия на листинговых страницах)
2. **Нарушение ожидаемого поведения** — пользователь включает Auto-download в Settings, ожидая, что это сработает при простановке Loved, но функция не активируется
3. **Регрессия от незавершённого фикса BUG-014** — коммит 77d65bc декларирует «same transition-only guard as savePanelRating» для ВСЕх мест, но трёхместное покрытие предиката (`savePanelRating:760`, `onRateWorkRequested:1064`, `applyRating:866`) было выполнено неполно

## Связь с BUG-014

BUG-014 описывает класс ошибки: **edge-vs-level** (проверка переходного состояния vs проверка текущего состояния предиката). Коммит 77d65bc попытался исправить дефект, но:

- ✅ `savePanelRating` (line 756) — исправлено правильно (читает `existing` ДО апсерта)
- ❌ `onRateWorkRequested` (line 1063) — всё ещё дефектно (читает ДО апсерта НЕ сделано)
- ❌ `applyRating` (line 866) — не тронуто (уже было дефектно в BUG-014)

Эта задача — отдельный баг для ОДНОГО из трёх мест (`onRateWorkRequested`), так как она впервые проявляется на сборке 1.11 (12) и должна пустить непосредственно в разработку с регрессионной информацией.
