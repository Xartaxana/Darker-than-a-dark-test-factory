# BUG-017 — Быстрое закрытие вкладок → долгий парад снекбаров; подозрение на потерю Undo

## Окружение
- Версия приложения: 1.10 (versionCode 11), built_at 2026-07-02T02:39:46
- Эмулятор/устройство: тестировано ручно на реальном ПО (воспроизведено оператором)
- Режим: live (вручную через UI)

## Фасет 1: Парад снекбаров при быстром закрытии нескольких вкладок

### Шаги воспроизведения (Given-When-Then)

**Given:** открыто ≥4 вкладки в браузере

**When:** пользователь быстро закрывает 3+ вкладки подряд через TabStrip (свайп-вверх по чипу или крестик без задержки между закрытиями)

**Then (ожидалось):**
- Либо один агрегированный снекбар со счётчиком закрытых вкладок (например «3 tabs closed»), обновляемый при последующих закрытиях
- Либо каждый снекбар немедленно вытесняет предыдущий, максимум один видим одновременно

**Actual (фактически):**
- После каждого закрытия запускается отдельная корутина со `showSnackbar(..., duration=Short)` (~2.0–2.7 с)
- Compose's `SnackbarHostState` показывает снекбары **строго последовательно** (внутренний mutex)
- N закрытий = очередь из N снекбаров, суммарная длительность ≈ N × 2–2.7 сек
- При N=6 пользователь видит парад уведомлений ~12–16 секунд, перекрывающий контент и затрудняющий работу с приложением

### Частота
**Возникает при ЛЮБОМ быстром закрытии 3+ вкладок подряд** (повторяется 100% при таком входе; воспроизведено оператором)

### Корневая причина (из кода приложения)

**MainActivity.kt, строки 246–260** — метод `onCloseTab`:
```kotlin
val onCloseTab: (Int) -> Unit = { index ->
    val token = browserViewModel.closeTab(index)
    if (token != null) {
        coroutineScope.launch {                    // ← КАЖДОЕ закрытие = новая корутина
            val result = snackbarHostState.showSnackbar(
                message = "Tab closed",
                actionLabel = "Undo",
                duration = SnackbarDuration.Short,  // ← ~2.0–2.7 сек на этой сборке
            )
            if (result == SnackbarResult.ActionPerformed) {
                browserViewModel.restoreClosedTab(token)
            }
        }
    }
}
```

Compose's `SnackbarHostState` (внутренняя реализация) **показывает снекбары в очереди** (mutex-синхронизация). N одновременных корутин = N снекбаров в очереди. Каждый ждёт свой ~2–2.7 сек → парад.

## Фасет 2: Подозрение на потерю Undo-токенов при длительной задержке показа

### Описание подозрения

При быстром закрытии 6+ вкладок произойдёт следующее:

1. Закрытие 1–5: токены сохраняются в `closedTabSnapshots` (буфер ёмкостью 5, BrowserViewModel.kt:330)
2. Закрытие 6: сгенерирован токен, но его снапшот вытеснен FIFO (старейший удалён)
3. Закрытие 6 запустило 6-ю корутину со `showSnackbar`, но она ждёт своей очереди в `SnackbarHostState` ~2–2.7 × 5 ≈ 10–13 сек
4. Пока 6-й снекбар ждёт показа: его токен ВЫЖЕ обнулен (не существует в буфере с момента вытеснения)
5. Пользователь видит живый снекбар с кнопкой "Undo" → нажимает её → `restoreClosedTab(token)` возвращает `null` (токен забыт) → молча ничего не делает

**Контроль:** TC-024 тестирует 6 закрытий в **спокойном режиме** (каждый снекбар просто исчезает без нажатия Undo). Сценарий БЫСТРОГО показа 6+ снекбаров с попыткой Undo НЕ ТЕСТИРУЕТСЯ никаким TC.

### Код-анализ (BrowserViewModel.kt, строки 336–346)

```kotlin
/** Reinserts the tab closed under [token], roughly at its original position. No-op if expired/unknown. */
fun restoreClosedTab(token: Long) {
    val snapshot = closedTabSnapshots.remove(token) ?: return  // ← return если токен забыт
    val state = _uiState.value
    if (state.tabs.size >= MAX_TABS) return                    // ← молчит, не уведомляет
    tabHistories[snapshot.tab.id] = snapshot.history
    val insertAt = snapshot.index.coerceIn(0, state.tabs.size)
    val newTabs = state.tabs.toMutableList().apply { add(insertAt, snapshot.tab) }
    _uiState.update { it.copy(tabs = newTabs, activeTabIndex = insertAt) }
    saveTabsToPrefs()
}
```

`closedTabSnapshots` — это `mutableMapOf<Long, ClosedTabSnapshot>()` (BrowserViewModel.kt:304). Ёмкость ограничена 5 (строка 330–332):
```kotlin
while (closedTabSnapshots.size > 5) {
    closedTabSnapshots.remove(closedTabSnapshots.keys.min())
}
```

При исчезновении токена нет сообщения об этом пользователю — функция просто возвращается (`?: return`). Ожидание: если Undo невозможен, приложение должно либо (а) заблокировать кнопку на снекбаре, либо (б) показать уведомление («Undo has expired»), как это делается в других приложениях.

## Связь с BUG-016

**BUG-016** («Undo закрытия вкладки на потолке 10 молча теряет вкладку») — другой сценарий молчаливого отказа Undo:
- **BUG-016**: Потолок MAX_TABS достигнут (10 вкладок) → попытка Undo → снапшот еще в буфере, но `if (state.tabs.size >= MAX_TABS) return` молчит
- **BUG-017, фасет 2**: Буфер переполнен (6+ закрытий) → попытка Undo → токена уже нет в буфере → `closedTabSnapshots.remove(token) ?: return` молчит

Оба — класс R-16 по критерию владельца: «молчаливая потеря функции / состояния пользователя, ожидание — видимое сообщение об отказе». Это соседи по симптому, требуют рассмотрения как системного дефекта Undo.

## Предложение по исправлению (suggested_fix, решение за разработчиком)
