# BUG-078 — Файл, скачанный на одном устройстве, не докачивается автоматически на других; нарушает требование R-18

## Окружение
- Версия приложения: dev-local (versionCode 12)
- Сборка: debug, source_commit aa377e0e (2026-06-28)
- Тип анализа: code inspection LibraryJson.kt, SyncRepository.kt

## Требование владельца (R-18, docs/01-test-strategy.md §5)
> Должна работать так, как будто человек читает одну и ту же книжку на всех устройствах.

Конкретизация для скачиваний:
> Скачанное на одном устройстве докачивается на остальных.

## Проблема

**LibraryJson.kt (синхронизация)** намеренно исключает путь скачивания из синка:

Комментарий на строке 34:
```kotlin
/** downloadPath is always null — it never travels between devices. */
```

Реализация на строке 35-54 (`workFromJson`):
```kotlin
downloadPath = null,  // строка 51: явно обнуляет путь при десериализации
```

**Причина явного исключения** указана в документации SyncRepository.kt строка 30:
```kotlin
/**
 * ...`downloadPath` never travels — it is device-local.
 */
```

**SyncRepository.kt (публикация)** не включает информацию о скачивании:

Строка 206 при публикации синка:
```kotlin
repo.getAllWorkRatings().forEach { 
    arr.put(LibraryJson.workToJson(it, includeDownloadFile = false)) 
}
```

Флаг `includeDownloadFile = false` означает, что информация о скачанном файле никогда не отправляется на другие устройства.

**Отсутствуют вызовы** для автоматического скачивания при синке:
```
Grep по downloadWork в SyncRepository.kt
→ 0 совпадений (нет механизма автоматической докачки при слиянии удалённого синка)
```

## Шаги воспроизведения (Given-When-Then)

**Given** 
1. Пользователь на устройстве A открывает работу и скачивает её (Files tab → работа → Download)
2. Устройство A хранит файл локально, WorkRating имеет `downloadPath = "/storage/…/work_123.epub"`

**When**
1. Пользователь активирует синхронизацию (Library sync настройка включена)
2. Устройство A публикует свою библиотеку (синк прогонял)
3. Устройство B получает ту же работу из синка (синк слил, работа добавлена в Room)
4. Пользователь на устройстве B открывает ту же работу

**Then (ожидалось по R-18)**
Устройство B автоматически докачивает файл, если его нет локально (по пути из синка или по src-URL работы)

**Actual (фактически)**
1. Синк не передаёт информацию о скачивании (downloadPath = null из LibraryJson)
2. Устройство B не знает, что файл был скачан на A
3. Пользователь B видит работу в Files tab, но она помечена как "not downloaded" (или требует повторного скачивания)
4. Нет встроенного механизма автоматического скачивания при синке

## Анализ

Класс дефекта: расхождение с требованием владельца R-18. 

Требование говорит: "скачанное на одном устройстве докачивается на остальных". Текущая реализация **намеренно исключает** информацию о скачивании из синка, что прямо противоречит требованию.

**Текущая логика:**
- `downloadPath` — это абсолютный путь на файловой системе устройства (`/storage/emulated/0/Documents/work_123.epub`)
- Этот путь не имеет смысла на другом устройстве с другой file layout
- Поэтому он обнуляется при синке (не путешествует)

**Пути реализации:**
1. **Отправить URL скачивания:** вместо абсолютного пути отправить URL-ссылку на скачивание (`https://archiveofourown.org/works/123/download?format=epub`)
2. **Добавить флаг:** отправить флаг `wasDownloaded: Boolean` и при синке на другом устройстве автоматически скачать по URL
3. **Отправить имя файла:** отправить рекомендуемое имя файла и дать пользователю выбор при синке ("Работа была скачана на другом устройстве. Скачать сейчас?")

Фича критична для:
- Многоустройственных домов (планшет + телефон, оба имеют локальное хранилище)
- Синхронизации работ "для автономного чтения" (пользователь скачал работу на планшет дома, ожидает найти её на телефоне в дороге)

> 
> Вместо синхронизации файлов добавлено явное действие **«Send to my other devices»** в long-press-меню Library. Смысл: не «всё скачанное растекается по устройствам», а «пользователь осознанно отправляет конкретную работу на свои остальные устройства».
> 
> Как устроено:
> 
> - по сети едет **только запрос** (`sendRequestedAt` в payload), файл — никогда: снипет GitLab это текстовый документ, который каждое устройство перечитывает на каждом проходе, и EPUB-ы раздували бы его на мегабайты;
> - каждое устройство качает свою копию само через `DownloadRepository.downloadWork`, используя `url` работы, который и так синхронизируется;
> - идентификатор устройства не нужен: отправитель сразу проставляет себе `sendHandledAt` (действие адресовано «другим» устройствам, себе оно ничего не качает), а каждое другое устройство видит запрос новее своего `sendHandledAt` и отрабатывает его;
> - `sendHandledAt` device-local и не синхронизируется, поэтому удаление файла позже **не** приводит к повторной закачке по старому запросу; «Send … again» ставит новое время, которое отрабатывают все устройства, включая уже скачавшие;
> - запрос мержится по-полевому (`withNewerSendRequest`, побеждает более позднее время) и **не** двигает `timestamp`: отправка не является правкой рейтинга или заметки и не должна выигрывать merge у реального изменения с другого устройства;
> - отработка идёт после merge (`fulfillSendRequests`), поэтому пришедший запрос обрабатывается в том же проходе; неудачная закачка остаётся необработанной и повторяется на следующем проходе (обычно это просто «сети ещё нет»);
> - прибытие сообщается снекбаром (`SyncRepository.received`): автосинк результата не показывает — см. BUG-074 — иначе файлы появлялись бы без объяснения.
> 
> Миграция Room 9→10 (`sendRequestedAt`, `sendHandledAt`), проверена на заполненной БД.
> 
> Проверено на эмуляторе: действие присутствует в меню, отправка проставляет `sendRequestedAt` и `sendHandledAt`, `timestamp` при этом не меняется. Первая версия правки, к слову, оставляла `sendHandledAt` пустым, и устройство-отправитель скачало бы работу само себе — поймано на этой проверке и исправлено.
> 
> **Не проверено:** приёмная сторона (закачка на другом устройстве по приходу запроса и снекбар о прибытии) и полевой merge — нужны два устройства с настроенным GitLab-синком, а сама закачка идёт на AO3.
