# BUG-016 — Undo закрытия вкладки на потолке молча теряет вкладку

## Окружение
- Версия приложения: 1.10 (versionCode 11), built_at 2026-07-02T02:39:46
- Эмулятор: emulator-5554 (ao3_test_api34, API 34)
- Режим: replay (tab_markers.mitm, listing_basic.mitm)
- Тема: Dark (переключалась посреди сессии, дефект от неё не зависит)

## Шаги воспроизведения (Given-When-Then)

**Given:** Открыты 10 вкладок в браузере (достигнут потолок MAX_TABS)

**When:**
1. Закрыть одну вкладку (стало 9 вкладок)
2. Снекбар «Tab closed / Undo» подтверждённо жив на экране
3. Освободившийся слот заполнить новой вкладкой (вернуться к 10 вкладкам)
   - Вариант А: нажать кнопку `+` на TabStrip
   - Вариант Б: глубокая ссылка (deep-link) на новую работу
4. Нажать кнопку `Undo` на снекбаре

**Then (ожидалось):**
Либо закрытая вкладка вернётся на свой слот и откроется, либо приложение покажет пользователю, почему это невозможно (как при попытке открыть 11-ю вкладку через диалог «You have 10 tabs open. Close some tabs before opening a new one.»)

**Actual (фактически):**
1. Закрытая вкладка НЕ возвращается
2. Пользователю НЕ показано никакого сообщения (ни снекбар, ни диалог)
3. Повторный Undo невозможен — токен снапшота уже сожжён
4. Вкладка утеряна молча

## Частота
**3 из 3 воспроизведений** (раунды 1, 2, 3 в сессии CH-005 раздел «R2. Seed 2 "Коллекционер на потолке"» шаг R2.3-4).

**Контроль:** Тот же путь БЕЗ занятия слота (закрыть вкладку → сразу Undo с задержкой 2.6 с) — Undo работает штатно, вкладка возвращается (R2.4).

Вывод: проблема вызвана именно комбинацией «потолок + занятой слот», а не истечением времени жизни снекбара.

## Анализ (корневая причина из кода приложения)

**Это баг приложения, не теста или окружения**, потому что:

1. **Дефект реализации в BrowserViewModel.kt:**
   - Метод `restoreClosedTab` (строка 338) выполняет `closedTabSnapshots.remove(token)` **ДО** проверки потолка `if (state.tabs.size >= MAX_TABS) return` (строка 340)
   - Т.е. снапшот удаляется из памяти даже если Undo не может быть выполнен
   - При повторном нажатии Undo нечего восстанавливать — токен сожжён

2. **Асимметрия поведения на одном и том же потолке:**
   - Метод `openTab` (строки 261-266) при попытке открыть 11-ю вкладку показывает AlertDialog: «You have 10 tabs open. Close some tabs before opening a new one.»
   - Метод `restoreClosedTab` при той же ситуации молчит и просто возвращает false
   - Ожидание пользователя: если Undo невозможен, приложение должно сообщить об этом, как при openTab

3. **Контроль воспроизведения доказывает специфичность:**
   - Без занятия слота (R2.4): Undo срабатывает за 2.6 с — работает штатно
   - С занятием слота (R2.3, 3 раунда): Undo молчит — дефект только в этой комбинации

4. **Потеря данных:**
   - Пользователь потерял доступ к вкладке, и повторить Undo невозможно
   - Молчаливый отказ создаёт UX-ловушку: пользователь нажимает Undo, ничего не происходит, но причина скрыта
