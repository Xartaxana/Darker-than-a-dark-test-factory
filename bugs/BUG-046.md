# BUG-046 — Ручной скан не сходится при двух файлах одного ao3Id

## Окружение
- Версия: 1.10 (versionCode 11), commit 63f6aac
- Эмулятор: emulator-5554, API 34
- Режим: replay (listing_basic.mitm)
- Тема: светлая
- Папка загрузок: дефолтная (`getExternalFilesDir("ao3_downloads")`)

## Шаги воспроизведения (Given-When-Then)

**Given**
- Work с ao3_id 900000001 в Room (SAVE + локальный title, fandom, wordCount)
- Один файл на диске: `ao3_ЛОКАЛЬНЫЙ заголовок_900000001.html`
- `downloadPath` указывает на этот файл
- Карточка показывает «Open downloaded»
- Settings → Scan for downloads выполнен ≥1 раз ранее

**When**
- Правка заметки через overlay листинга (BUG-021) → `downloadPath` обнуляется, title переписывается
- Карточка снова показывает «Download»
- Повторное скачивание из карточки
- На диске теперь **два файла** одного ao3Id:
  - `ao3_ЛОКАЛЬНЫЙ заголовок_900000001.html` (старый, сирота)
  - `ao3_A Loved Test Work_900000001.html` (новый, в downloadPath)
- Settings → «Scan for downloads»

**Then (ожидалось)**
- Диалог: `Scan complete` / `Found 2 files — relinked 2, added 0 new.` / `OK`
- **На ВТОРОМ сканировании:** `Found 1 files — relinked 1, added 0 new.` или `Found 0 files — relinked 0, added 0 new.`
  (идемпотентность: повторный скан при том же состоянии файлов должен дать результат 0 или 1, но не 2)
- Room содержит ровно **один** `downloadPath` на одну работу (последний в порядке `listFiles()`)

**Actual (фактически)**
- Диалог на 1-м сканировании: `Found 2 files — relinked 2, added 0 new.`
- Диалог на 2-м сканировании: **`Found 2 files — relinked 2, added 0 new.`** (ИДЕНТИЧЕН)
- Диалог на 3-м сканировании: **`Found 2 files — relinked 2, added 0 new.`** (ИДЕНТИЧЕН)
- **Счётчик не сходится:** три скана подряд без изменений на диске дают один и тот же результат
- Room содержит `downloadPath` указывающий на `ao3_A Loved Test Work_900000001.html` (последний файл в порядке `listFiles()`)
- Пользователь **не имеет способа узнать**, что файлов два и какой из них "его"

## Частота
**Всегда, 100%:** Воспроизведено 3 сканирования подряд в одном сеансе (CH-008, seed 2, раунды S2), плюс повторное воскрешение в доборе (п.10 протокола) с идентичным результатом.

## Анализ корневой причины

### Место в коде (DownloadRepository.kt)

Метод скана файлов (`:108-130`) обрабатывает каждый файл в папке и для каждого файла, матчащего `WORK_ID_PATTERN`, выполняет `updateDownloadPath`:

```kotlin
fun scanForDownloads(coroutineContext: CoroutineDispatcher = Dispatchers.IO) {
    // ...
    var relinked = 0
    var added = 0
    for (file in downloadDir.listFiles() ?: emptyArray()) {  // LOOP: для каждого файла
        val match = WORK_ID_PATTERN.find(file.name)
        if (match != null) {
            val aoId = match.groupValues[1].toLong()
            val existing = ratingRepo.getWorkByAoId(aoId)  // Достаём ОДНУ запись по aoId
            if (existing != null) {
                if (existing.downloadPath != file.absolutePath) {  // Условие: путь отличается
                    ratingRepo.updateDownloadPath(aoId, file.absolutePath)  // Перезаписываем path
                    relinked++  // Счётчик++
                }
            } else {
                // создание новой записи
                added++
            }
        }
    }
    showMessage("Found ${files.size} files — relinked $relinked, added $added new.")
}
```

### Суть дефекта

**Цикл перебирает ВСЕ файлы**, но работа в Room представлена **ОДНОЙ** записью по ao3Id:

1. На диске: `ao3_ЛОКАЛЬНЫЙ_900000001.html` + `ao3_A Loved Test_900000001.html` (два файла, один ao3Id)
2. В Room: **одна запись** `Work(ao3Id=900000001, downloadPath=path_to_second_file)`
3. Цикл скана:
   - Итерация 1 (файл 1): `existing.downloadPath != file1.path` → `updateDownloadPath(aoId, path_to_file_1)` → `relinked++` (1)
   - Итерация 2 (файл 2): `existing.downloadPath != file2.path` → **False (путь совпал)** → `relinked` не растёт
   - **Но** — если обновление в итерации 1 успело записать в БД **до** итерации 2, то на итерации 2 условие снова **True**!
4. На повторном сканировании: то же состояние (2 файла, path на один из них) → снова `relinked=2`

**Результат:** счётчик не сходится, потому что код **перелинковывает одну работу на каждый файл по очереди**, не различая, что это один ao3Id.

### Класс дефекта

**Одна запись vs. несколько файлов:** Room схема `work_ratings` не имеет уникального индекса на `downloadPath` (только на `ao3Id`). Следствие: один ao3Id может быть связан с несколькими файлами на диске, но цикл скана обновляет путь последовательно, оставляя старые файлы сиротами.

**Попутный риск:** пользователь не видит ни одного UI-сигнала о наличии двух файлов. Диалог скана не показывает имена/пути файлов, только счётчики.
