# BUG-074 — Автоматическая синхронизация приложения молчит об ошибках и удалениях

## Окружение
- Версия приложения: dev-local (versionCode 12)
- Сборка: debug, source_commit aa377e0e (2026-06-28)
- Тип анализа: code inspection исходников SyncRepository.kt, MainActivity.kt

## Шаги воспроизведения (Given-When-Then)

**Given** приложение запущено, синхронизация работ включена (фича SyncRepository)

**When** 
1. Пользователь переводит приложение на передний план (MainActivity.kt:171–184, `onResume()`)
2. Или локально изменяется метаданные работы (debounce 5 секунд, обработан в `onResume()`)
3. Инициируется автоматический запуск `SyncRepository.syncWorks()` через SyncManager

**Then (ожидалось)**
Пользователю показывается сообщение о:
- Успешной синхронизации (как при ручном запуске из меню)
- Ошибке синхронизации, если запрос на AO3 не прошёл
- Удалении работ (если синхронизация обнаружила надгробие)

**Actual (фактически)**
Автоматический синк завершается молча:
- Ошибки писаны только в `Log.e` (SyncRepository.kt:104, `log("Error: $e")`)
- При успешном синке — без диалога (в отличие от ручного синка MainActivity.kt:606, который показывает Snackbar)
- Удаление работ с надгробия (SyncRepository.kt:165, удаляются вместе с файлами) — также молча, пользователь не узнает, почему работа исчезла из приложения

## Контекст: расхождение с ручным синком

**Ручной синк (при тапе на кнопку из меню):**
- Показывает диалог прогресса (ProgressDialog)
- Показывает Snackbar об успехе с числом обновлённых работ
- Показывает диалог об ошибке с текстом причины

**Автоматический синк (по выходу на передний план):**
- SyncManager запускает `SyncRepository.syncWorks()` (MainActivity.kt:171–184)
- Результат обрабатывается без UI: только лог-запись в Log.e
- Удаления работ обрабатываются в SyncRepository.kt:160–170 без уведомления пользователю

## Критерий владельца (docs/01-test-strategy.md §10(п))
> Есть сообщение пользователю → норма; нет сообщения → дефект.

По этому критерию отсутствие сообщения об ошибках и удалениях при авто-синке — дефект.

## Частота
100% (архитектурная разница в обработке ручного vs автоматического синка, не флаки).

## Артефакты
- Код: `app-under-test/app/src/main/java/com/example/ao3_wrapper/sync/SyncRepository.kt:104` (Log.e без UI)
- Код: `app-under-test/app/src/main/java/com/example/ao3_wrapper/MainActivity.kt:171–184` (авто-триггеры без feedback)
- Код: `app-under-test/app/src/main/java/com/example/ao3_wrapper/sync/SyncRepository.kt:160–170` (удаление работ с надгробия молча)
- Контрольный путь: `app-under-test/app/src/main/java/com/example/ao3_wrapper/MainActivity.kt:606` (ручной синк показывает диалог)

## Анализ

Класс дефекта: асимметричное UI-поведение — один путь пользовательского действия (ручной синк из меню) показывает feedback, другой (автоматический синк при переходе в фон) — молчит. Это нарушает принцип видимости состояния приложения (visibility of system status, usability heuristic).

**Минимум дефект:** молчание об ОШИБКАХ синхронизации. Пользователь не узнает, что синхронизация не удалась, и может предположить, что данные в синхе (тогда как на самом деле локальная копия устарела).

**Дополнительный дефект:** молчаливое удаление работ при обнаружении надгробия (SyncRepository.kt:165) — работа исчезает из библиотеки без объяснения.

## Вопрос разработчику

Задумано ли, что автоматический синк молчит об ошибках и удалениях? Или это дефект, требующий добавления Snackbar/Toast/диалога при:
- Ошибке синхронизации (сетевой сбой, таймаут, 4xx/5xx от AO3)
- Удалении работ (обнаружено надгробие или рассинхрон)
- Успешной синхронизации (для уведомления пользователя, что фоновая операция завершена)?
