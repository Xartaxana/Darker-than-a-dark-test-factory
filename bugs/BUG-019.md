# BUG-019 — Back после автопрыжка плотности не выводит назад

## Окружение
- Версия: 1.10 (versionCode 11), built_at 2026-07-02T02:39:46
- Эмулятор: emulator-5554 (ao3_test_api34, API 34)
- Режим: replay (`listing_paginated.mitm` + `seed_library`)
- Сборка: debug
- Параметры: infinite-scroll ON, hide_disliked ON (дефолт)

## Шаги воспроизведения (Given-When-Then)

**Given**
1. Приложение открывает листинг из фикстуры `listing_paginated.mitm` (5 страниц, по 1 работе на странице)
2. Infinite-scroll включен (тумблер ON в Settings)
3. Фильтр hide_disliked включен (ON в Settings; дефолт)
4. Через seed_library одна или несколько работ на странице 1 помечены DISLIKE
5. Пользователь открывает страницу 1

**When**
1. Приложение видит, что ВСЕ видимые работы страницы скрыты фильтром
2. Автоматически выполняет ПОЛНУЮ навигацию на страницу 2 (функция `checkPageDensity`, ao3_bridge.js:617-629)
3. Пользователь пытается вернуться назад (нажимает Back, кнопка в браузере)

**Then (ожидалось)**
- Пользователь должен вернуться на страницу 1
- История должна двигаться линейно: forward → 1 точка в истории

**Actual (фактически)**
1. Back мгновенно возвращает на страницу 1
2. **Страница 1 перезагружается и мгновенно автоматически прыгает вперёд на страницу 2** (checkPageDensity срабатывает заново)
3. Маркер документа теряется (`document.identity` сбрасывается — страница реально перезагрузилась)
4. **`history.length` растёт на 2 за каждое нажатие Back** (2 → 4 → 6 → ...)
5. **Пользователь заперт на странице 2:** три Back подряд (или более) не сдвинули со страницы (остались на странице 4 при цепочке из 3 пустых страниц)
6. Приложенческая история в prefs (`historyIndex=2`) расходится с WebView-историей

## Частота
**3 воспроизведения:**
- Seed 2a (CH-006): одна DISLIKE-работа на странице 1 → автопрыжок на page 2 → Back 1× не помогает (пункт 10 протокола)
- Seed 2b (CH-006): DISLIKE на работах страниц 1, 2, 3 → цепочка из 3 автопрыжков на page 4 → Back 3× не помогает (пункты 9-10)
- Дизамбигуация (отдельный прогон, пункт 10): маркер `window.__ch006Marker` и замер `history.length` на каждом Back доказывают, что страница реально перезагружается и checkPageDensity срабатывает заново

## Анализ (баг приложения)

Корень — цикл автопрыжка при Back.

**Процесс:**
1. Пользователь нажимает Back: `history.back()`
2. WebView-история отводит на страницу 1
3. Страница 1 **перезагружается** из-за механики History API
4. Загрузка завершена → срабатывает `applyAllFilters` (ao3_bridge.js:123)
5. Функция `checkPageDensity` проверяет, пусты ли видимые работы (ao3_bridge.js:617-629)
6. ВСЕ работы скрыты (фильтр hide_disliked) → гейт `if (__ao3InfiniteScroll === false) return` не срабатывает (infinite ON)
7. Приложение выполняет **ПОЛНУЮ навигацию** `location.href = _effectiveNextUrl` → на страницу 2
8. Навигация добавляет НОВУЮ запись в историю (не модифицирует текущую, а добавляет)
9. **`history.length` вырос на 2:** Back на стр.1 (1 запись) + новая автонавигация на стр.2 (ещё 1 запись)
10. Пользователь остаётся на стр.2 (не может Back-ом вернуться на стр.1, т.к. стр.1 теперь ведёт на стр.2)

**Семантика дефекта:**
- Это тот же класс дефекта, что `checkPageDensity` по дизайну (R-17-класс, находка #3): приложение **САМО ПРИНИМАЕТ РЕШЕНИЕ** о навигации, не запрашивая пользователя
- **На Back это создаёт ловушку**: пользователь пытается отменить нежелаемую навигацию, но приложение вынуждает его остаться на странице через автоматическое прыгание
