# BUG-020 — Простановка DISLIKE уводит пользователя со страницы

## Окружение
- Версия: 1.10 (versionCode 11), built_at 2026-07-02T02:39:46
- Эмулятор: emulator-5554 (ao3_test_api34, API 34)
- Режим: replay (`listing_paginated.mitm` + `seed_library`)
- Сборка: debug
- Параметры: infinite-scroll ON, hide_disliked ON (дефолт)

## Шаги воспроизведения (Given-When-Then)

**Given**
1. Приложение открывает листинг из фикстуры `listing_paginated.mitm` (5 страниц, по 1 работе на странице)
2. Infinite-scroll включен (тумблер ON в Settings)
3. Фильтр hide_disliked включен (ON в Settings; дефолт)
4. Страница 1 содержит **единственную видимую работу** (или все остальные работы уже помечены DISLIKE)
5. Пользователь видит листинг со своей работой и открытый bottom-sheet рейтинга этой работы

**When**
1. Пользователь нажимает кнопку DISLIKE в листинговом bottom-sheet (или rate-overlay на странице работы)
2. Приложение выполняет `applyAllFilters` → `checkPageDensity` (ao3_bridge.js:123, :617-629)

**Then (ожидалось)**
- Bottom-sheet рейтинга остаётся открытым или закрывается по действию пользователя
- Страница остаётся на странице 1, контент перзагружается (работа скрывается фильтром)
- Пользователь видит оставшиеся работы или баннер «Some works may be hidden…»
- Если страница пустеет, пользователь должен получить **явное сообщение** о переходе на следующую страницу или оставаться на пустой странице с явным указанием причины

**Actual (фактически)**
1. **Пользователь остаётся в bottom-sheet рейтинга** (оверлей открыт)
2. **Приложение мгновенно выполняет ПОЛНУЮ навигацию на страницу 2** (смена location.href, заголовка, содержимого)
3. **Оверлей закрывается** ПОСЛЕ навигации, и пользователь видит, что он уже на странице 2
4. Никакого подтверждения, диалога или сообщения нет — действие происходит под открытым оверлеем, создавая иллюзию, что оверлей сам себя закрыл и страница переменялась
5. Пользователь дезориентирован: ожидал сохранить рейтинг-оверлей открытым, остался на той же странице; вместо этого получил немедленное перемещение

## Частота
**2 из 2 независимых прогонов:**
- Seed 2d, прогон 1 (CH-006, пункт 12): чистая страница 1 открыта, работа видима → пользователь ставит DISLIKE из листингового bottom-sheet → страница уходит на page 2 прямо под открытым оверлеем (s2d-02, s2d-03)
- Seed 2d, прогон 2 (независимый повтор): идентичный результат

Контроль: без hide_disliked (фильтр OFF), автопрыжка на пустой странице не происходит (seed 2c, пункт 11, гейт `:619`).

## Анализ (баг приложения)

Корень — незапрошенная автонавигация при live-push фильтра.

**Процесс:**
1. Пользователь ставит DISLIKE через листинговый bottom-sheet
2. Приложение вызывает `applyAllFilters` (ao3_bridge.js:123) — обновление фильтра на **ТЕКУЩЕЙ загрузке** (live-push)
3. Функция `checkPageDensity` проверяет, остались ли видимые работы (ao3_bridge.js:617-629)
4. ВСЕ работы скрыты (единственная работа была скрыта, hide_disliked ON) → буфер `visible` = `[]`
5. Гейт `if (__ao3InfiniteScroll === false) return` не срабатывает (infinite ON)
6. Приложение **без спроса** выполняет `location.href = _effectiveNextUrl` (строка ~629) → **ПОЛНАЯ навигация на страницу 2**
7. **Это происходит в разгар взаимодействия пользователя с оверлеем** — навигация разрушает контекст оверлея

**Семантика дефекта:**
- **R-17-класс** по критерию владельца: «приложение действует вместо пользователя»
- Отличие от находки #2 (Back-ловушка): здесь навигация происходит **ПОСРЕДИ явного действия пользователя** (простановка рейтинга), а не как побочный эффект Back
- **Класс дефекта:** `checkPageDensity` срабатывает **ВСЕГДА** при `applyAllFilters`, без разбора контекста (открыт ли оверлей, ожидает ли пользователь результата рейтинга)
- Сосед **BUG-015** (авто-клик kudos на AO3 — незапрошенное действие на стороннем сайте); обе находки — незапрошенные действия вместо пользователя, но **разные механизмы** (рейтинг → kudos-клик vs рейтинг → навигация)
