Статус программы: **In Progress** (старт — слово оператора 2026-08-20;
прежняя конструкция «П3 за П1/П2» снята оператором: протокол замера П1

## Цель

  остаётся за фабрикой /qa-loop (smoke/regression/verification).
- **Стек 2 (новый):** клон-AVD `ao3_corridor_api34` (имя БЕЗ общего

## Констрейнты конструкции (по эмпирике критик-раунда)

1. **RAM:** хост 15.9 GB, свободно при живой фабрике 3.4 GB;
   `hw.ramSize = 2G` у api34 (клон унаследует) + qemu + второй
   node/pytest — арифметика упирается в abort-порог (B9). Поэтому:
   `-Memory` появляется в `Start-Emulator` (N1); ДО клонирования —
   дешёвая RAM-проба на СУЩЕСТВУЮЩЕМ `ao3_test_api29` (N0); замер
   free до/после, abort при free < 1.0 GB. Вопрос оператору (11а):
   «докупка RAM vs посменный режим» — с честной оговоркой: посменный
   режим НЕ снимает циркулярную блокировку, ради которой запущена
   программа, — только удешевляет переключение.
2. **systemPort:** при НЕзаданном systemPort UiAutomator2 сам
   аллоцирует из 8200-8299 под кросс-процессным lock-guard
   (session.js:11-53) — параллельные сессии НЕ коллидируют. Поэтому
   дефолт `AO3_SYSTEM_PORT` = ПУСТО → капабилити НЕ выставляется
   (авто-аллокация сохраняется); явное значение — только опция
   детерминизма/диагностики (B2). Мусорное значение env не роняет
   импорт settings (класс `int(os.environ...)` на импорте — новый
   экземпляр не плодим: безопасный парс с явной ошибкой).
3. **Жнецы (правило 4) — ЧЕТЫРЕ, не один:**
   (а) `Stop-NodeProcesses` — массовый килл node: нужна селективность
   `-Port`/`-OwnerPid`; без селектора при >1 живом Appium — отказ с
   перечнем (при одном — прежнее поведение).
   (б) substring-килл qemu по `$AvdName` (tasks.ps1:273-278) — якорить
   матч `-avd\s+<name>\b` + имя клона без общего префикса (B5).
   (в) **DeviceLivenessGuard/recovery** (driver_factory.py:258-276):
   читает ОБЩИЙ `state/emulator-session.json` (один на хост,
   tasks.ps1:193) и перезапускает «последний записанный» AVD с
   `-WritableSystem` — recovery одного стека убивает другой (B7).
   State ключуется по AVD/стеку; recovery берёт AVD своего стека.
   (г) `--clean-alluredir` в pytest.ini addopts с ОТНОСИТЕЛЬНЫМ
   `allure-results` — старт прогона стека 2 стирает отчёт живого
   прогона фабрики; `ALLURE_RESULTS` env это НЕ перекрывает (питает
   только вложения reporting.py:46) (B4). Изоляция: `--clean-alluredir`
   ОСТАЁТСЯ в addopts (вынос без call-site = копящийся мусор в отчётах
   фабрики, B15); изолируется САМ КАТАЛОГ — `--alluredir` пер-стек +
   согласованный `settings.ALLURE_RESULTS`, дефолт = прежний путь
   (обратная совместимость стека 1 без правок).
4. **Голый adb без `-s` ломает ОБА стека при втором устройстве (B3):**
   оракул буда Start-Emulator считает ЛЮБОЕ устройство (tasks.ps1:
   245-247 — объявит стек поднявшимся по чужому эмулятору),
   `getprop sys.boot_completed` без `-s` при 2 устройствах → stderr +
   null-Trim → краш (:286), `Set-GuestIPv4Pin`, `Install-App`,
   `Wait-PackageServiceReady`, `install-mitm-ca.sh:27` (`ADB` без
   серийника — а recovery ВСЕГДА идёт с `-WritableSystem` →
   контейнмент AT-BUG-026 умирает у обоих). Класс-фикс — `ANDROID_SERIAL`
   (env, adb понимает нативно; закрывает getprop/Install-App/
   Set-GuestIPv4Pin/install-mitm-ca одним ходом, `adb devices` её
   игнорирует — Get-DeviceSerials/Get-Device не ломаются); пообъектный
   `-s` — только там, где env-путь не годится. Оракул буда чинится
   отдельно (по своему серийнику). Всё это — скоуп N1: второй девайс
   НЕЛЬЗЯ даже подключать надолго до N1.
5. **API-уровень:** очередь автоматизации таргетит api34 → коридору
   нужен клон api34 (`ao3_corridor_api34`); api29 — только E3/
   compatibility.
6. **Момент коммита N1 = момент деплоя:** tasks.ps1 дот-сорсится на
   каждом вызове — правку подхватит СЛЕДУЮЩИЙ вызов фабрики. Мерж N1 —
   только вне live device-прогона фабрики (окно между проходами),
   porcelain-чек обязателен.
7. **Replay/mitm — non-goal стека 2:** `mitm.py:28` `_PORT = "8080"` —
   константа модуля; два параллельных replay невозможны. **Стек 2 =
   live-only** до отдельного узла параметризации mitm (очередь);
   replay-кейсы коридор стабилизирует на стеке 1 в окна фабрики.

  арбитража N4/N5 — «нет одновременного вождения»: живой pytest_pid
  блокирует и адопцию, и `-Resume` безусловно.
  Предикаты живости — ТОЛЬКО страховка от брошенной
  лизы, их окна покрывают реальные разрывы жизненного цикла:

  tasks.ps1) обновляют timestamp лизы своего стека → grace остаётся

  холодный bring-up легитимно длиннее (только

  «неактивна»: отдельное idle-окно (**~30 мин — ОЦЕНКА (F-30),
  калибруется witness'ом пауз N4**) покрывает паузы «прогон → правка →
  прогон» внутри тикета; реклейм — только по истечении idle-окна.
  (3) **heartbeat фактический**: timestamp обновляется на КАЖДОМ
  create_driver — точка чокпоинта поэтому function/driver-scoped
  (решение зафиксировано в определении чокпоинта выше; session-scoped
  фикстура heartbeat не даёт);

  верхняя страховка, срабатывает только если heartbeat реально замолк.
  PID процесса ВЗЯТИЯ предикатом не является (одноразовый
  PowerShell-процесс, констрейнт 6). Реклейм — с громкой строкой в
  лог (log_append orchestrator; вызов fail-soft — отсутствие
  интерпретатора не роняет сессию, пишется только по факту реклейма).
  Поведение вызывающего при отказе (B26; отказ бывает только от ЧУЖОЙ
  лизы — своя из idle принимается): чужая лиза АКТИВНА (heartbeat
  живой) → сразу Blocked с именем владельца, ждать нечего; чужая в
  `idle` → ожидание ≤ остатка idle-окна, затем реклейм либо Blocked —
  не тихое вечное ожидание и не красный кейс (для N5 это разница
  «кейс подождал» vs «кейс упал» — в промпт test-runner).
  Сводка окон (под юнит-детектор): grace между шагами bring-up ~10 мин

  класс стыковых дефектов B21-B28):**

  idle/TTL)`; замыкающие стрелки: `active|idle → free` по

## Решение оператора по RAM (2026-08-20, вопрос закрыт)

RAM НЕ докупаем. Политика — **динамический гейт по замеру**: перед
стартом стека 2 меряем free RAM; если память занята слишком сильно —
второй эмулятор НЕ запускаем (прогон едет посменно/на стеке 1), если
хватает на два — запускаем. Операционализация: pre-start free ≥
ожидание клона (~2-2.5 GB) + буфер 1.0 GB; post-start abort-порог
free < 1.0 GB остаётся (констрейнт 1). Гейт — в Use-DeviceStack/N2,
замер дословным witness'ом каждого bring-up.
