Слово оператора 2026-08-16: «Невидимая фабрика в фоне меня не устраивает…
в идеале heartbeat просто подталкивает фабрику в открытом окне». Решения
оператора: архитектура «окно-фабрика + сторож»; бюджет — режимы `N
проходов` (±1–2, без самовольного раннего стопа) и `безлимит`; стоп
грациозный; **лимит срабатываний одного прохода окна = 5** (опрос
2026-08-16; «оператор в петле» — правило 6); стоячее «20»
(rules.yaml:16) остаётся дефолтом конвейера. Фон отключён оператором
(`schtasks /disable`, Next Run Time: N/A).

v5 — переработка по критик-раунду 4 (Б-Ⅰ…Б-Ⅴ + CAS-nonce; v1–v4 —
некоммиченные ревизии этого файла, провенанс — вердикты критик-раундов
в routing-log; коммит спеки — предусловие N4). Прежняя ветка
`scratchpad/spec-heartbeat-window-first-*.md` — SUPERSEDED (см. N7).

## Целевая архитектура

### К1. Скилл `factory` — вождение в открытом окне

`.claude/skills/factory/SKILL.md`. Команды: `/factory N` (budgeted),
`/factory` (unlimited), «остановись» (грациозный стоп).

1. **Владение вождением — compare-and-swap по nonce.** mode-файл (К2)
   несёт `session_nonce`; **ЛЮБАЯ запись в mode-файл легальна только
   если nonce в файле == собственный** (перечитать перед записью);
   чужой nonce → прекратить вождение строкой в сводке. Это наблюдаемый
   критерий владения (ts-сравнения нет — после компакции оно
   ненаблюдаемо) и ограничение двойного вождения одним интервалом
   пульса. Старт /factory при чужом активном mode-файле — назвать
   владельца/updated_ts и СПРОСИТЬ оператора; слово «перехвати» =
   takeover: новый nonce, счётчики passes_done/budget_total
   НАСЛЕДУЮТСЯ (бюджет один, сменился водитель; ключ К5з
   passes_done==0 применяется только к свежему старту). **Якорь nonce
   вне контекста сессии (r5): собственный nonce несётся В ТЕКСТЕ
   wakeup-prompt** (нейтральный текст + токен) — проснувшаяся сессия
   восстанавливает СВОЙ nonce из разбудившего сообщения, не из файла;
   файл несёт чужой → CAS честно фейлит → прекратить вождение +
   погасить СВОЙ таймер (stop:true). **Усыновление файлового nonce
   ЗАПРЕЩЕНО**: нет своего nonce ни в контексте, ни в wakeup →
   спросить оператора (ветка «чужой активный mode-файл»), не вести
   молча. Takeover — ЕДИНСТВЕННОЕ легальное исключение из CAS-запрета
   записи (по слову оператора). Нечитаемый mode-файл при чтении
   СКИЛЛОМ → НЕ писать поверх (пересоздание со своим nonce вернуло бы
   двойное вождение) — вопрос оператору. Прекращение вождения по
   чужому nonce — НЕ терминальный путь enum: mode=stopped не пишется
   (запись запрещает сам CAS).
2. **Пульс вождения — КЛАССОВОЕ определение (r4): каждый шаг
   качественного изменения состояния прохода** — диспатч воркера,
   приёмка, начало длинного недиспатчевого шага (смок/регресс/
   pre_steps), **каждая BUSY-попытка/пауза** (`heartbeat_note` =
   «ждём лок holder=…») — обновляет `updated_ts`/`heartbeat_note`
   mode-файла. DoD N4: юнит-ревизия скилла на КАЖДУЮ ветку без пульса
   (беспульсовая ветка = дефект). Молчание mode-файла тем самым ≈
   молчание фабрики.
3. Проход: вызов скилла qa-loop с ЯВНЫМ лимитом **5**; интерактивная
   ветка лока (SKILL.md:76-78).
4. Классификация прохода:
   - **BUSY** — проход не состоялся; пауза 600с (каждая попытка —
     пульс, К1 п.2 — ложный STALL в ожидании исключён); после 3 BUSY
     подряд (≈20 мин) — **ВОПРОС оператору в окне**, ожидание
     продолжается паузами 600с; стоп `busy_giveup` — при накопленных
     **120 мин** без слова оператора (нижняя граница: ≥ максимума
     завершённых проходов 84.5 мин; выборка цензурирована на 100 и
     масштабирование на лимит 5 даёт 115–170 — но оператор в петле с
     20-й минуты, поэтому нижней границы достаточно). BUSY-вопрос
     оператору НЕСЁТ holder/ts лока и называет опцию
     `python scripts/loop_lock.py release --force` (флаг существует).
     **Остаточный риск (явно): busy_giveup (120 мин) < TTL лока
     (240 мин)** — окно может сдаться раньше, чем сирота протухнет;
     компенсатор — тот же вопрос оператору с 20-й минуты.
   - **doctor-FAIL** — проход состоялся как деградированный (k растёт,
     сводка несёт строку деградации); тревога по нему не объявляется.
   - **Пустой** = состоялся И 0 срабатываний И «отложено» пусто И
     дельта ре-скана 4а пуста.
5. Продолжение: budgeted до N состоявшихся (ранний стоп при 2 пустых
   подряд; перебор до N+2 при рождённых k=N срабатываниях); unlimited —
   симметрично. **Каждый терминальный путь пишет `mode=stopped` +
   `stopped_reason`** из enum: `operator_stop | budget_done |
   two_empty | busy_giveup` (Б-4 — ложный STALL после штатного
   финиша исключён) + гасит wakeup-таймер + итоговая сводка.
   Аварийный обрыв (смерть сессии) stopped_reason НЕ пишет — это по
   построению вход сторожа, не пятое значение enum.
6. Паузы: непустой — 60с; пустой/BUSY — 600с. Инвариант: STALL_NO_LOCK
   (60 мин) > max пауза (10 мин) + каденция (30 мин). Wakeup-prompt
   нейтральный, гашение таймера на стопе (урок
   no-command-as-wakeup-prompt).

### К3. `scripts/factory_watchdog.py` — сторож

`scripts/heartbeat.cmd` → `python scripts/factory_watchdog.py` (новая
шапка без echo в heartbeat.log и без протухшей ссылки docs/11).
Каденция PT30M сохраняется.

Состояние `state/factory-watchdog.json` (gitignored):
last_lock_snapshot, last_mode_snapshot, last_progress_ts,
last_alert_ts, last_state. **Обновляется на КАЖДОМ тике, ВКЛЮЧАЯ тихие
ветки** (mode нет/stopped — state-файл всё равно пишется: это
heartbeat самого сторожа для чека К5а); запись неброcающая (образец
_write_singleton_escalation, класс BL-4).

Прогресс = изменение loop.lock (появился/исчез/holder/ts) ИЛИ
изменение mode-файла (updated_ts/passes_done) относительно снапшотов;
изменение → last_progress_ts = now. Bootstrap: записать снапшоты,
last_progress_ts=now, тихий exit. Журнальные mtime не используются.

**Матрица (приоритет сверху вниз, однозначно — Б-3):**
0. **Битые JSON-состояния (класс, все три файла сторожа):**
   mode-файл нечитаем → трактовать как «файла нет» (тишина + пометка
   в state-файле + строка orchestrator-log); `state/loop.lock`
   нечитаем/без ts → **сирота-кандидат** (согласовано с семантикой
   loop_lock: REAPED :262-272, CORRUPT в status :325-326) — в ветке
   п.2 считается протухшим, в вычислении прогресса — «лок есть,
   сравнение по сырым байтам файла», **и для предиката п.3 битый лок =
   «лок есть» (порог 90 мин)**; `state/factory-watchdog.json`
   нечитаем → **bootstrap** (как «снапшотов нет»). Каждый из трёх
   битых случаев оставляет строку в orchestrator-log (не только mode).
   Ни одна ветка не роняет процесс — exit 0 всегда; юниты на все
   три — DoD N4.
1. mode-файла НЕТ → тишина (ручной /qa-loop без вождения — штатен;
   carve-out явный), state-файл обновить, exit 0.
2. mode=stopped → тишина (риск «оператор забыл» принят явной строкой;
   детектор дрейфа — чек session-handoff «mode согласован с намерением
   оператора»), НО: лок ЕСТЬ при mode=stopped И **возраст САМОГО лока
   (now − lock.ts; ts фиксируется в acquire и не обновляется —
   loop_lock.py:277) > loop_lock_ttl_hours (4ч)** → «лок без вождения»
   → STALLED-ветка (единственный вход сироты ПРИ ОТСУТСТВИИ попыток
   acquire — любой стартовавший /qa-loop снимет протухший лок сам,
   REAPED + reap-streak, и ветка штатно не сработает). Порог — возраст
   лока, НЕ last_progress_ts: пульса при stopped нет by construction,
   а здоровый ручной проход (62–100+ мин) не должен тревожить; 4ч
   совпадает с REAP-семантикой К4 — сирота и есть кандидат REAP;
   тревога этой ветки наступает НА границе REAP (+каденция), не
   раньше — «сторож раньше REAP» верно только для in-pass ветки п.3.
3. mode активный:
   - лока нет И now−last_progress_ts > **STALL_NO_LOCK = 60 мин** →
     STALLED;
   - лок есть И now−last_progress_ts > **STALL_IN_PASS = 90 мин** →
     STALLED (пульс К1 п.2 идёт на каждом срабатывании, поэтому 90 мин
     тишины при живом локе = двукратный запас над самым долгим
     наблюдённым одиночным воркером ~40 мин). **Остаточный риск (явно):
     одиночный воркер, молчащий >90 мин, даст ложную тревогу;
     named-детектор самого риска — эта же тревога (кулдаун 4ч
     ограничивает шум), пересмотр порога — по замеру первых реальных
     лимит-5 проходов после N6 (пункт DoD N6).**
   Env-перекрытия AO3_FACTORY_STALL_MIN / _INPASS_MIN.
4. Переход ok→stalled: тост (кулдаун 4ч на ЛЮБОЙ тост) +
   singleton-эскалация `[factory:stalled]` (**текст несёт текущий ts** —
   факт 8) + строка orchestrator-log; stalled→ok: строка
   orchestrator-log + **гашение эскалации маркером
   `[resolved:factory-watchdog-recovered]`** (штатный формат). Отказ
   тоста не роняет; exit всегда 0.

### Д. Ночной резерв — КОНСОЛИДИРОВАННАЯ РЕДАКЦИЯ (операционная)

**Этот блок — ЕДИНСТВЕННЫЙ операционный текст ночного резерва.
Все дельты ниже (v5/v4/v3/v2, Д2) — АРХИВ раундов; при любом
конфликте побеждает этот блок.** Сведено после 4 критик-раундов и
трёх слов оператора 2026-08-16 (до исчерпания бюджета; ночью новую
внешнюю работу не мониторить; дремоты нет).

1. **Триггер:** STALLED (mode активный, night_fallback ≠ off)
   держится ≥ FALLBACK_DELAY_MIN=15 (следующий тик) И предикаты
   fastdeath/slowdeath чисты → ОДИН резервный проход. State-файл
   сторожа пишется ДО спавна.
2. **Точка входа:** `run_fallback_pass(child_args,
   budget_enabled=False, on_spawn, on_pass_done, claude_cmd,
   lock_file, reaps, escalations, sla, log_path)` → исход
   `{outcome: busy|spawned|spawn_failed|timeout_kill, child_rc,
   fast_death, holder, mode_write}`. Общее ядро `_run_child`
   (acquire/kill-tree/tasklist/release/REFUSED/**fastdeath-учёт**);
   `run_pass` — тонкая обёртка с прежним контрактом (0) и пинами,
   дублирование запрещено. Бюджет-ветка отключена КОДОМ. child_args
   `['-p','/qa-loop 5','--model','sonnet']`. Вызов блокирующий
   (тиков нет — PT30M+IgnoreNew). Вывод ребёнка → файловый
   дескриптор `logs/fallback-YYYYMMDD.log` (НЕ PIPE, класс B4);
   M4-артефакт = этот лог на ВСЕХ исходах; fastdeath-сообщение
   указывает на него.
3. **Бюджет (слово оператора):** единственный рабочий лимит —
   `passes_done < budget_total`; unlimited — лимита работы нет.
   Коллбэки: `on_spawn` — инкремент fallback_runs/24h в state ПОСЛЕ
   acquire ДО Popen (BUSY не инкрементирует by construction;
   spawn_failed — компенсирующий non-throwing откат под локом);
   `on_pass_done` — при spawned+rc==0 CAS-инкремент passes_done в
   mode-файле ДО release (перечитка + nonce + mode не stopped),
   non-throwing (BL-4). fallback_runs* — ТЕЛЕМЕТРИЯ, не гейт.
   Поля записи резерва: passes_done, updated_ts,
   driver="watchdog-fallback", last_fallback_ts, heartbeat_note,
   **плюс mode=stopped + stopped_reason=two_empty — единственный
   случай записи mode резервом (п.5)**. Скилл КАЖДОЙ своей записью
   ставит driver="factory-skill". Модель записи честная:
   last-writer-wins по некритичным полям (окно пульсирует и на
   BUSY-попытках), критичные — CAS-перечитка.
4. **Атрибуция:** `_mode_snapshot` += session_nonce; сторож хранит
   self_write_snapshot (= mode_write исхода) и fallback_holder; свои
   сигналы — свой mode-write И лок резерва (ОБА фронта, включая
   протёкший после timeout_kill) — прогрессом ОКНА не считаются;
   эпизод закрывает только прогресс окна (смена nonce / пульс
   не-резервного писателя).
5. **Конец работы (дремоты НЕТ — слово оператора):** «пустой» —
   строгое 4-условное определение К1 п.4. **Канал пустоты из
   headless-ребёнка:** шаг 6 qa-loop пишет
   `state/last-pass-summary.json {ts, triggered, deferred,
   rescan_delta}` (единственная новая правка qa-loop SKILL; файл
   gitignored); сторож читает по возврату, сверяя ts с окном
   прохода (битый/протухший ts = «неизвестно» = НЕ пустой). 2
   пустых ПОДРЯД резервных прохода (`empty_streak` в state сторожа) →
   резерв пишет mode=stopped/two_empty → сторож штатно молчит
   (матрица п.2) — терминатор и для unlimited. **Guard записи
   two_empty — ТРИ условия под локом (B12 r4: окно может ожить с ТЕМ
   ЖЕ nonce и BUSY-пульсировать, пока лок у резерва):** (а) nonce не
   менялся; (б) mode != stopped; **(в) driver ==
   "watchdog-fallback"** — любой пульс окна (включая BUSY-пульс)
   ставит factory-skill и ОТМЕНЯЕТ финиш; оживление окна сбрасывает
   empty_streak. **Порядок оценки (Б1 r5, обязующе): все три условия
   оцениваются по ОДНОЙ перечитке файла, сделанной ДО собственной
   записи резерва этого прохода (та же перечитка, что у
   CAS-инкремента); инкремент passes_done и mode=stopped/two_empty —
   ОДНА запись, не две подряд** (иначе guard читает driver, который
   резерв сам только что записал — условие (в) истинно всегда).
   DoD-юнит: «BUSY-пульс окна во время прохода отменяет two_empty».
   **Канал пустоты — ts штампует СКРИПТ (Б5 r5):** шаг 6 qa-loop
   вызывает `python scripts/pass_summary.py --triggered N --deferred
   M --rescan K` — скрипт сам ставит ts и пишет JSON (машинный ts,
   дом пина формата). Пустоту резерв вычисляет ПО ТОЙ ЖЕ перечитке,
   что и guard (до собственной записи on_pass_done, r6-фикс 2). **Детектор отказа канала:** `unknown_streak` в
   state сторожа — 3 «неизвестных» подряд → notes + тост «канал
   сводки прохода сломан» (иначе отказ канала молча снимал бы
   терминатор unlimited: пустые проходы дают rc==0, slowdeath не
   взводится, passes_done растёт). Пустые проходы (макс 2 до стопа)
   жгут passes_done как у окна (симметрия); сводка ОБЯЗАНА нести
   разбивку «спавнов всего / результативных». Новая ВНЕШНЯЯ работа
   ночью не мониторится — перезапуск утром рукой оператора.

**Решение.** Отдельный класс исхода `usage_limit`, НЕ fastdeath:

1. `heartbeat_wrap.parse_usage_limit` распознаёт строку вендора и
   вычисляет момент сброса (`2am (Europe/Paris)` → ближайший будущий

   `[factory:fallback]`/`[factory:child-death]` НЕ звучат, slowdeath НЕ
   копится. Ровно ОДИН тост на вход (`[factory:usage-limit]`).
4. В момент сброса — ровно ОДИН `[factory:limit-back]` «толкни окно» и
   grace-окно `LIMIT_GRACE_MIN` (45 мин, env `AO3_FACTORY_LIMIT_GRACE_
   MIN`): приоритет ЖИВОМУ окну на полном ярусе. Оператор не пришёл —
   дальше прежние правила ночного резерва.
5. Живой прогресс окна закрывает лимитное окно (`episode_closed_by_

**Почему окно не поехало само (класс, D-0043).** Окно ведёт себя
цепочкой `ScheduleWakeup`, где следующее звено ставит только УСПЕШНО
завершившийся ход. Лимит срывает ход → звено не поставлено → цепочка
порвана НАВСЕГДА, и толкнуть окно снаружи нечем (у сторожа нет канала в
чужую интерактивную сессию). Это признанное свойство, а не баг
реализации: v8 его не чинит, а делает ВИДИМЫМ (возвратный тост) —
починка потребовала бы канала «сторож → открытое окно», которого в
харнессе нет. Пункт остаётся открытым в docs/HANDOFF.md.
