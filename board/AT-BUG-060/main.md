## Суть

При заведении test_debt-бага о недостающей replay-записи для
`SettingsViewModel.fetchMissingMetadata` (`app-under-test/.../SettingsScreen.kt:231-264`,
блокер TC-186/TC-187) следующий свободный номер был выбран Glob'ом только
по `bugs/AT-BUG-*.md`, без сверки с `bugs/BUG-*.md` — но именно к этому
моменту сессии параллельный bug-reporter уже создал `bugs/BUG-060.md`
(кандидат CH-009 found_bugs #1, «фоновая вкладка на удалённый локальный
файл теряет опознаваемость»). Нумерация ОБОИХ префиксов — сквозная, общий
счётчик (`docs/templates/bug-report.md` шапка) — слот «060» уже был занят.

Обнаружено СРАЗУ (в том же ходе, до передачи артефакта дальше по конвейеру),
исправлено переносом реального содержания в `bugs/AT-BUG-061.md`
(корректный следующий свободный номер на момент исправления). Инструмент
этой роли не позволяет удалить файл — `initial: [Open]` в
`schemas/transitions.yaml` не даёт test-designer завести файл сразу
`Rejected`, а переход `Open -> Rejected` разрешён только `by: [human]`.
Поэтому: `test_cases` здесь ОБНУЛЁН (не блокирует реальные кейсы),
`severity: minor` (минимум допустимого схемой значения), `duplicates:
["AT-BUG-061"]` — координатор/человек
может формально перевести этот файл в `Rejected` штатным переходом
(`D4: не баг / не воспроизводится` — по сути «не баг вовсе», дубль номера);
до этого момента файл висит `Open`, но `test_cases: []` не даёт ему
фигурировать ни в одном B4-триаже конвейера. Скрипт-валидатор
(`scripts/validate_frontmatter.py`) НЕ проверяет сквозную уникальность
номера между префиксами (сверено чтением) — коллизия не всплывёт как
ERROR/WARNING автоматически, поэтому явная пометка в теле обязательна.
