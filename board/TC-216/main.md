# Повторный синк без изменений не пишет в сниппет и показывает «Everything already in sync.»

# TC-216 — Идемпотентность публикации + дословный «Everything already in sync.»

## Предусловия
- Синхронизация настроена, только что выполнен успешный «Sync now» (снимок
  и локальное состояние идентичны, ничего не менялось после).

## Сценарий (Given-When-Then)

**Given** локальное состояние и содержимое удалённого сниппета побайтово
совпадают с результатом последнего успешного синка

**When** пользователь запускает «Sync now» повторно

**Then** новый запрос на ЗАПИСЬ сниппета НЕ отправляется (mitm видит только
`GET`, ни одного `PUT`/`POST` за этот прогон)
**And** диалог «Sync complete» показывает дословно «Everything already in
sync.»
**And** подпись «Last synced …» в Settings всё равно обновляется на текущее
время (проверка сходимости — прогон не «завис» и не считается ошибкой)

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Состояние | идентично последнему успешному синку |
| Сетевые вызовы за прогон | 1 GET, 0 записывающих запросов |
| Диалог | «Everything already in sync.» |

## Заметки для автоматизации
- Требует того же mitm-перехвата исходящих запросов, что TC-215 (для
  подтверждения ОТСУТСТВИЯ записывающего запроса) — информация для
  test-automator, не блокер.
- Это же свойство — оракул сходимости для N устройств: собственные записи
  слияния взводят `dirty` и вызывают ещё один проход, который обязан прийти
  именно к этому Then («нечего применять»).
