# BUG-075 — Действие "Open in background tab" на .epub-файле нарушает свою подпись (уводит из приложения)

## Окружение
- Версия приложения: dev-local (versionCode 12)
- Сборка: debug, source_commit aa377e0e (2026-06-28)
- Тип анализа: code inspection MainActivity.kt

## Шаги воспроизведения (Given-When-Then)

**Given** пользователь находится в приложении (любой экран)

**When** на карточке скачанной работы с .epub-файлом (Files tab или результат поиска):
1. Long-press по карточке → выбрать «Open in background tab» (MainActvity.kt:606)
2. Прочитать подпись: "Opens without leaving the library, so you can queue up several works."

**Then (ожидалось по подписи)**
Приложение остаётся на экране Library / Browse (user stays in the library), работа открывается в фоновой вкладке для последующего чтения

**Actual (фактически)**
При тапе на опцию приложение переключается на вкладку с .epub-файлом и перенаправляется на внешнее приложение для чтения (Adobe Reader, Calibre, другой читатель epub):
- Пользователь УХОДИТ из приложения AO3-wrapper
- Остаться в Library нет возможности

## Дополнительное наблюдение: openFileExternally без диалога

Похожее поведение (тихое завершение) наблюдается в соседних путях:
- **MainActivity.kt:764, 776** — `openFileExternally(path)` при пустом пути или несуществующем файле молча выходит без сообщения об ошибке (нет Toast, нет диалога, приложение просто закрывается)

## Контекст

Действие "Open in background tab" расположено рядом с другой опцией того же контекстного меню (чтение для других фаловых форматов). Подпись явно говорит: "Opens **without leaving** the library" — это обещание пользователю, что действие не приведёт к выходу из приложения.

На пути для интернет-работ (открытие в WebView) — действие действительно открывает работу в фоновой вкладке, оставляя пользователя в Library/Browse (реализовано через механизм вкладок приложения, не через intent).

На пути для локальных .epub-файлов — действие вызывает `openFileExternally` (MainActivity.kt:764), который перенаправляет в системную резолюцию intent'а для MIME-типа application/epub+zip, приводя к выходу из приложения.

## Частота
100% (архитектурная разница между путём WebView и путём `openFileExternally`, не флаки).

## Артефакты
- Код: `app-under-test/app/src/main/java/com/example/ao3_wrapper/MainActivity.kt:606` (пункт меню и подпись)
- Код: `app-under-test/app/src/main/java/com/example/ao3_wrapper/MainActivity.kt:764–776` (обработчик `openFileExternally`)

## Анализ

Класс дефекта: расхождение между обещанной подписью UI-элемента и фактическим поведением реализации. Пользователь читает "Opens without leaving the library", тапает, и приложение закрывается.

**Мягкий вариант:** ошибка подписи (она верна только для интернет-работ; для локальных файлов нужна другая подпись, например "Open externally" вместо "Open in background tab").

**Жёсткий вариант:** ошибка реализации (действие "Open in background tab" должно открывать файл в способе, не покидая приложение — либо через встроенный читатель, либо через систему уведомлений с механизмом возврата в приложение, как Telegram для видео).

Дополнительный дефект: `openFileExternally` при пустом/битом пути молча выходит без feedback (MainActivity.kt:764, 776).

## Вопрос разработчику

Является ли молчаливый выход при "Open in background tab" на .epub-файле задуманным поведением? Или требуется:
1. Изменить подпись действия (разделить для интернет-работ и локальных файлов)?
2. Изменить поведение (открывать файл способом, не покидая приложение)?
3. Добавить диалог подтверждения перед выходом из приложения (например: "This will open the file in an external reader. Continue?")?
