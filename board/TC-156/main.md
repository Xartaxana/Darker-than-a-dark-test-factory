# Скачанная работа без рейтинга (rating=null, downloadPath!=null) видна ТОЛЬКО на вкладке FILES и ни на одной рейтинговой вкладке Library

# TC-156 — Скачанная работа без рейтинга видна только на вкладке FILES

## Предусловия
- Работа W (`ao3_id 900000001`) скачана (`downloadPath != null`, файл на
  диске), `rating = null`, `comment = null`, `tags = null` (легальное
  состояние: `removeRating` при пустых заметке/тегах оставляет строку живой
  только благодаря `downloadPath`, `RatingRepository.kt:33-40`).
- Открыт экран Library.

## Сценарий (Given-When-Then)

**Given** работа W скачана и не имеет рейтинга (`rating=null`,
`downloadPath != null`, `comment=null`, `tags=null`)

**When** пользователь по очереди открывает вкладки FAVORITE, KUDOSED, READ,
PENDING, DISLIKED и FILES экрана Library

**Then** работа W НЕ отображается ни на одной из рейтинговых вкладок
(FAVORITE/KUDOSED/READ/PENDING/DISLIKED показывают «Nothing here yet» или не
содержат W среди прочих работ)
**And** работа W отображается ИМЕННО на вкладке FILES, с иконкой «Open
downloaded»
**And** тап по карточке W на FILES открывает скачанный локальный файл (то же
поведение, что для скачанных работ с рейтингом — путь не заблокирован
отсутствием рейтинга)

**Инвариант:** видимость работы в Library определяется ДВУМЯ независимыми
множествами — рейтинговые вкладки индексируются по `rating` (работа видна
только во вкладке, соответствующей её текущему `rating`, `rating=null` не
входит ни в одну), а вкладка FILES индексируется по факту
`downloadPath != null` независимо от `rating`; работа с `rating=null` и
`downloadPath != null` — представитель пересечения «нет рейтинга, но есть
файл», единственная непустая вкладка для которого — FILES.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа W | `ao3_id 900000001`, `rating=null`, `downloadPath != null`, `comment=null`, `tags=null` |
| Проверяемые вкладки | FAVORITE, KUDOSED, READ, PENDING, DISLIKED, FILES |

## Заметки для автоматизации
- **БЛОКЕР (test_debt), тот же баг, что у TC-151/TC-152/TC-155** — заведён
  `bugs/AT-BUG-046.md` в этом же ходе, дополнена третья грань: baseline
  `rating=null + downloadPath != null` (CH-008 baseline C) не сеется напрямую
  ни одной существующей функцией `seed_db.py` — `seed_with_download`
  типизирована как `rating: str` (не `str | None`), а её внутренняя
  `_insert_rows_with_download` жёстко ассертит `rating in _RATING_ENUM`
  (`seed_db.py:379`, `None` в это множество не входит и провалит assert);
  `_insert_rows_full` (используется `seed_with_comment`) допускает
  `rating=None`, но НЕ принимает `downloadPath` вовсе (жёстко пишет `None`,
  `seed_db.py:190`). Обход без фикса фреймворка — построение дверями (seed
  SAVE+download → panel deselect при пустых заметке/тегах, CH-008 baseline
  B), рабочий, но зависимый от корректности самой панельной двери (предмет
  проверки TC-151, не должен быть предпосылкой её же фикстуры). `test_cases:
  [TC-151, TC-152, TC-155, TC-156]` в баге.
- Проверка «нет ни на одной рейтинговой вкладке» — `library_steps.
  assert_work_not_in_tab` по каждой из пяти вкладок (существующий generic
  паттерн, использован TC-091/TC-016).
- Открытие файла с FILES — существующий путь (`library_screen.py`, кнопка/
  иконка «Open downloaded», тот же локатор, что TC-035 использует для
  baseline).
- Дельта: это первый design-кейс на факт, который CH-008 измерил как **ok**
  (Г3, не находка) — сегодня НИ ОДИН кейс не фиксирует это поведение явно;
  без него регрессия («скачанная работа без рейтинга нигде не видна»)
  прошла бы незамеченной ни одним существующим тестом.
- Область — комбинаторная (рейтинги/видимость по вкладкам, прямое совпадение
  со стартовым банком CLAUDE.md «работа с рейтингом X видна только в
  соответствующей вкладке») — строка `Инвариант:` присутствует.
- Область не содержит правило-реакцию в смысле батареи (переключение вкладок
  — навигация, не авто-триггер side-effect) — н-п.
