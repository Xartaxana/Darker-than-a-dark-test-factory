# TC-230 — Авто-триггер с ошибкой: полное молчание пользователю

## Предусловия
- Синхронизация настроена (валидный токен), Snippet ID указывает на
  несуществующий сниппет (мок отвечает 404 на `GET`) — та же ошибка, что
  TC-224, но по АВТОМАТИЧЕСКОМУ пути.

## Сценарий (Given-When-Then)

**Given** авто-триггер настроен на условие ошибки 404 (как TC-224)

**When** приложение выходит на передний план (авто-триггер срабатывает и
получает 404)

**Then** пользователю НЕ показано НИЧЕГО — ни диалога, ни snackbar/toast, ни
бейджа ошибки где-либо в UI; факт ошибки виден ТОЛЬКО в logcat
(`Log.e`, тег `SyncRepository`) — контраст с TC-224, где ТА ЖЕ ошибка на
ручном пути даёт явный диалог «Sync failed»
**And** подпись «Last synced …» НЕ обновляется (прогон не засчитан успешным)

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Ошибка | 404 (та же ситуация, что TC-224) |
| Путь | авто-триггер, не ручной |
| Ожидаемая видимость пользователю | ноль (сравнить с TC-224) |

## Заметки для автоматизации
- Sync-фикстура отсутствует — тот же класс, что TC-224, применённый к
  авто-пути (свернуть/развернуть вместо тапа по «Sync now»).
- **Наблюдаемость негативного Then:** отсутствие диалога проверяется явным
  `assert_no_dialog_visible` (или эквивалент) СРАЗУ после перехвата
  mitm-запроса с кодом 404 к сниппету — то есть тест сначала подтверждает,
  что ошибка РЕАЛЬНО произошла (сетевой факт), и только затем — что она не
  просочилась в UI; это не «просто не искать диалог», а различающая
  проверка при доказанно достигнутой ошибке.
- Это ключевая асимметрия, ради которой стратег поднял область в P1
  (docs/01-test-strategy.md §9) — вопрос разработчику уже вынесен в §10
  (щ) п.3, баг не заводится этим design'ом.
