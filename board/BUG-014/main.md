# BUG-014 — Авто-скачивание Favorite срабатывает ретроактивно при изменении тега

## Окружение
- Версия: 1.10 (versionCode 11), живое приложение
- Устройство: не указано (репродукция на живом приложении)
- Сборка: сборка приложения

## Шаги воспроизведения (Given-When-Then)

**Given**
1. Приложение установлено и запущено
2. Настройка "Скачивание любимых работ по умолчанию" (тумблер auto-download HTML при рейтинге Favorite/SAVE) ВЫКЛЮЧЕНА
3. На странице работы установлена отметка Favorite (SAVE рейтинг) — работа НЕ скачивается (корректное поведение)

**When**
1. Пользователь включает тумблер "Скачивание любимых работ по умолчанию"
2. Пользователь возвращается на ту же работу
3. Пользователь добавляет новый тег к работе (сохраняет через рейтинг-overlay)

**Then (ожидалось)**
- При включении тумблера: существующие Favorite-работы НЕ скачиваются (тумблер не должен retroactively применяться)
- При правке тега ранее отмеченной работы: работа НЕ скачивается, так как рейтинг не менялся (рейтинг был SAVE до, остался SAVE после — это правка метаданных, не простановка нового рейтинга)

**Actual (фактически)**
- При включении тумблера: существующие Favorite-работы НЕ скачиваются (корректно)
- При правке тега на работе с УЖЕ установленным рейтингом Favorite: работа СКАЧИВАЕТСЯ, хотя не должна

## Частота
Всегда при условиях репро.

## Артефакты
Ручной репорт владельца (живое приложение, 2026-07-28), нет скриншотов/логов из автоматического прогона.

## Анализ (баг приложения)

Корень лежит в коде авто-скачивания при рейтингах типа SAVE (Favorite). Проблема: класс бага — **edge-vs-level** (граница vs предикат).

### Точка в коде
- Файл: `app/src/main/java/com/example/ao3_wrapper/ui/browser/BrowserViewModel.kt`
- Функция: `savePanelRating` (строка ~756) и `applyRating` (строка ~862)
- Проблема:

```kotlin
// savePanelRating, строка 756-758
if (rating == Rating.SAVE && autoDownloadSaved) {
    downloadWork(workId)
}
```

Функция вызывается при ЛЮБОМ изменении метаданных работы (рейтинг, комментарий, теги). На строке 746-752 работа upsert'ится в БД с СУЩЕСТВУЮЩИМ рейтингом (если есть), просто с изменёнными полями:

```kotlin
repo.upsertWorkRating(
    existing.copy(
        rating = rating,               // rating здесь — СУЩЕСТВУЮЩИЙ рейтинг из БД
        comment = savedComment,
        tags = effectiveTags,         // tags изменились, но rating — нет
        timestamp = System.currentTimeMillis(),
    )
)
```

Затем на строке 756 код проверяет `if (rating == Rating.SAVE && autoDownloadSaved)` — это ПРЕДИКАТ (проверка текущего состояния), а не ПЕРЕХОД СОСТОЯНИЯ (был ли рейтинг только что установлен на SAVE впервые при включённом тумблере).

### Семантика дефекта

Ожидаемое поведение: авто-скачивание должно срабатывать только при **переходе** "рейтинг становится SAVE/Favorite при включённом тумблере", а не при **проверке** "рейтинг==SAVE && тумблер==On" на каждом сохранении метаданных.

Текущий код срабатывает при любом обновлении записи БД, где rating уже SAVE и тумблер включен — это захватывает и правку тега, и правку комментария, хотя эти операции не меняют рейтинг и не должны инициировать скачивание.

### Почему severity: major

1. **Неожиданная активность пользователя** — пользователь добавляет тег (текстовая операция), а не меняет рейтинг, но приложение тайком скачивает файл (сетевая операция + запись на диск)
2. **Нарушение семантики настройки** — включение тумблера не должно ретроактивно применяться к ранее отмеченным работам
3. **Побочный эффект при ставке обновления** — любая правка тега/комментария Favorite-работы вызывает скачивание, что замедляет UI и может неожиданно потратить трафик/батарею
