# TC-244 — Повторное сохранение той же оценки не дублирует побочные эффекты

## Предусловия
- Работа W УЖЕ имеет рейтинг Favorite (SAVE) и уже скачанный файл
  (auto-download сработал при первичной простановке, вне этого кейса).
  Устройство под mitm-прокси.

## Сценарий (Given-When-Then)

**Given** работа W уже Favorite, файл уже скачан

**When** пользователь открывает «Rate / edit note» из Library и меняет
ТОЛЬКО заметку (тег/текст), рейтинг оставляет прежним (SAVE), сохраняет

**Then** заметка сохранена с новым текстом
**And** повторное скачивание файла НЕ инициируется (файл на диске — тот же,
`downloadPath`/`timestamp` файла не изменились)
**And** повторный kudos НЕ отправляется (mitm — 0 новых kudos-запросов за
это сохранение)

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа W | SAVE, файл уже скачан, было Kudosed-эквивалентно (SAVE ⊂ kudos-набор) |
| Действие | правка ТОЛЬКО заметки, рейтинг не меняется |
| Ожидаемые побочные эффекты | 0 (ни скачивания, ни kudos) |

## Заметки для автоматизации
- Это прямой guard класса BUG-014/BUG-015 («edge vs level»: предикат
  состояния в общем save-пути) — ЧЕТВЁРТЫЙ путь сохранения
  (`rateFromLibrary`), который переиспользует `applyRating`/
  `onRatingTransition`; предыдущий фикс BUG-015 выровнял три пути, этот
  кейс проверяет, что четвёртый — новый — путь тоже соблюдает переходную
  семантику (`isKudos && !wasKudos`), а не голый факт присвоения рейтинга.
- Требует mitm-наблюдения (как TC-243) для негативного kudos-Then.
