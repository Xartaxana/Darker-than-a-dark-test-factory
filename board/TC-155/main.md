# TC-155 — Панель work-страницы не теряет состояние скачанной работы при смене рейтинга и добавлении тега

## Предусловия
- Работа W (`ao3_id 900000001`) скачана (`downloadPath != null`, файл на
  диске), локальные `title="ЛОКАЛЬНЫЙ заголовок"`, `fandom="Мой фандом"`,
  `wordCount=777777`, рейтинг `SAVE` (Favorite), личная заметка `"note A"`,
  личный тег `"tagA"`.
- Открыта страница работы `/works/900000001`, панель `RatingMenu` раскрыта,
  Favorite показан выбранным.
- Режим replay (`listing_basic.mitm`).

## Сценарий (Given-When-Then)

**Given** работа W скачана, имеет рейтинг Favorite, заметку `"note A"` и тег
`"tagA"`; панель work-страницы раскрыта, Favorite выбран

**When** пользователь через панель меняет рейтинг Favorite → Kudosed (Liked),
затем раскрывает раздел тегов и добавляет ВТОРОЙ личный тег `"tagB"`

**Then** рейтинг меняется на Kudosed (Liked); работа переезжает из вкладки
FAVORITE во вкладку KUDOSED Library (базовое поведение, как TC-016)
**And** `downloadPath` остаётся НЕИЗМЕННЫМ на протяжении ОБОИХ шагов (смены
рейтинга и добавления тега) — карточка на новой вкладке по-прежнему
показывает «Open downloaded»
**And** заметка `"note A"` и первый тег `"tagA"` остаются без изменений;
новый тег `"tagB"` добавляется к уже существующим (итог: оба тега сохранены)
**And** `title`/`fandom`/`wordCount` остаются ЛОКАЛЬНЫМИ значениями на
протяжении обоих шагов (панель не перезаписывает их скрейпом страницы,
`existing.copy` меняет только затронутые поля)

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа W | `ao3_id 900000001`, локальные метаданные |
| Смена рейтинга | SAVE → LIKE (через панель) |
| Существующий тег | `"tagA"` |
| Добавляемый тег | `"tagB"` |
| downloadPath | реальный файл на диске |

## Заметки для автоматизации
- Это ОСТАТОК follow-up-кандидата CH-008 «панель не теряет пользовательское
  состояние» ПОСЛЕ вычета deselect-части (её закрывает TC-151, тот же
  baseline A, тот же файл): здесь — смена рейтинга и правка ТЕГОВ, а не
  снятие рейтинга.
- **БЛОКЕР (test_debt)** — тот же, что у TC-151/TC-152: `bugs/AT-BUG-046.md`
  (`read_work_ratings()` не отдаёт `title/author/downloadPath`; `seed_db` не
  умеет сеять baseline A одной строкой — построение через панель под
  измерением). `test_cases: [TC-151, TC-152, TC-155]` в баге, не дублирую
  заведение.
- Смена рейтинга через панель — существующий `rating_steps.rate_current_work
  (driver, "LIKE")` (образец TC-016).
- Добавление второго тега через панель — `rating_steps.add_tag_via_panel`
  (введён test-automator для TC-114, `framework/steps/rating_steps.py:36`) —
  переиспользовать напрямую, без нового локатора.
- Дельта к TC-008 (deselect на панели, нет файла, нет проверки полей) и TC-016
  (смена рейтинга между вкладками, обычные метаданные, файла нет, теги не
  трогаются) — этот кейс комбинирует файл + смену рейтинга + правку тегов,
  которую ни один из них не покрывает.
- Область не комбинаторная — строка `Инвариант:` не требуется (точечный
  сценарий одной двери — панель, комбинация двух её операций в одной
  пользовательской сессии, не перечислимое множество фильтров/сортировок/
  вкладок/тем).
- Область не содержит правило-реакцию в смысле батареи (смена рейтинга и
  добавление тега — прямые действия, не авто-триггер на событие) — н-п.
