# TC-229 — Батарея: propagation авто-триггера на открытый экран

## Предусловия
- Синхронизация настроена. Работа X засеяна с `rating=LIKE`, экран Library
  открыт и виден пользователю (карточка X отображена в соответствующей
  вкладке).
- Удалённый снимок (мок) несёт для X более новый `rating=DISLIKE`.
- Удалённый снимок с более новым DISLIKE подставляется УЖЕ ПОСЛЕ того, как
  экран Library открыт, и триггер обязан пройти гейт
  `SyncRepository.kt:99-105` (`!dirty && <60 с` подавляет прогон): либо
  между прогонами выдержано >60 с, либо непосредственно перед When сделано
  локальное изменение БД (взводит `dirty` через `MainActivity.kt:176-184`).
  Без этого When не порождает проверяемого эффекта.

## Сценарий (Given-When-Then)

**Given** экран Library уже открыт и показывает карточку X во вкладке LIKE,
удалённо есть более новая версия X с рейтингом DISLIKE

**When** приложение выходит на передний план (авто-триггер сливает удалённое
изменение) — пользователь НЕ покидает экран Library и не тянет
pull-to-refresh

**Then** карточка X сама переезжает из вкладки LIKE в вкладку DISLIKE НА
УЖЕ ОТКРЫТОМ экране Library, без ручного обновления/повторного захода —
изменение из авто-слияния доходит до видимого UI так же, как обычное
локальное изменение рейтинга

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа X | LIKE локально → DISLIKE удалённо (новее) |
| Экран во время триггера | Library, уже открыт |

## Заметки для автоматизации
- Sync-фикстура отсутствует — тот же класс, что предыдущие кейсы. Требует
  свернуть/развернуть приложение (`app_steps.send_app_to_background`/
  `bring_app_to_foreground`) БЕЗ навигации прочь с экрана Library — сам
  экран должен пережить цикл фон/передний план (обычное поведение Compose,
  не смерть процесса).
