# TC-194 — Clear all ratings остаётся необратимым: панель без правок не воскрешает запись при закрытии

## Предусловия
- Работа W (`ao3_id 900000001`) оценена Favorite (`rating=SAVE`), без
  заметки и тегов (`seed_db.seed`).
- Открыта страница работы `/works/900000001`, нижняя навигация раскрыта —
  панель показывает Favorite выбранным.
- Режим replay (`works_multi.mitm`, тот же, что оригинальный witness
  BUG-022).

## Сценарий (Given-When-Then)

**Given** работа W оценена Favorite; панель work-страницы раскрыта и
показывает Favorite выбранным, без набранных правок заметки/тегов

**When** пользователь переключается на вкладку Settings
(`BottomNav.open("Settings")` — панель демонтируется БЕЗ правок,
`hasUnsavedEdits=false`, dispose-guard ложен, запись не тронута) → нажимает
«Clear all ratings» и подтверждает (`settings_steps.clear_all_ratings`,
работа W удаляется из `work_ratings`) → возвращается на вкладку Browse
(`BottomNav.open("Browse")` — `onSelect` ставит `selectedTab=BROWSE` и
`navExpanded=false` одним апдейтом, `MainActivity.kt:426-429`; панель
монтируется на мгновение со стухшим `currentPageRating=SAVE` и тут же
демонтируется тем же переходом — транзиентный mount+dispose)

**Then** `work_ratings` для работы W остаётся ПУСТОЙ (0 строк) сразу после
возврата на Browse (`read_work_ratings_full()`) — Clear all ratings остаётся
необратимым, запись НЕ воскресает (регресс-замок BUG-022: до фикса тот же
переход писал `rating=SAVE` с новым timestamp)

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа W | `ao3_id 900000001`, `rating=SAVE` (baseline) |
| Действие | Settings → Clear all ratings (подтверждено) → возврат на Browse |
| Ожидаемый итог | 0 строк `work_ratings` для W (проверяется только Room, не панель — см. заметки) |

## Заметки для автоматизации
- **Убран Then про UI-состояние панели (критик-вход rework, B1).** Attempt 1
  нёс второй Then «повторное раскрытие панели показывает рейтинг
  невыбранным» — он был ЛОЖНО-КРАСНЫМ и противоречил принятому владельцем
  поведению: панель читает `activeTab.currentPageRating` (`BottomBar.kt:108/
  230`), это поле обновляют ТОЛЬКО пути загрузки страницы (`BrowserViewModel.
  kt:489/511`) и записи рейтинга (`:931`/`:1105`) — Clear all
  (`SettingsScreen.kt:501-503`) его не трогает. Без `reload` панель ещё
  покажет `SAVE` — это РОВНО принятое `Intended`-поведение `bugs/BUG-012.md`
  и уже проверенный Then(а) `test-cases/settings/TC-020.md`. Единственный
  оставшийся Then (0 строк в `work_ratings`) — самостоятельный и достаточный
  замок BUG-022: проверяет ТОЛЬКО Room (реально удалённые пользователем
  данные не воскресают), не UI-отражение этого факта, которое — отдельный,
  уже спроектированный и принятый как `Intended` вопрос (TC-020/BUG-012).
- **Регресс-замок BUG-022** — репро дословно повторяет Given-When-Then тела
  бага; ДО фикса (`test-maintainer` 2026-08-02, `AT-BUG-042` checkpoint 5,
  тот же порядок шагов) запись воскресала со `SAVE` и НОВЫМ timestamp сразу
  на возврате в Browse; красный результат Then про 0 строк `work_ratings`
  (единственный Then этого кейса) при повторном прогоне на будущей сборке
  триажится как РЕГРЕССИЯ класса BUG-022, не как ожидаемое поведение.
- Уже верифицировано ОДИН РАЗ device-driven пробником fix-verifier
  (`test_bug_022_dispose_no_edits_probe.py`, удалён после использования,
  `bugs/BUG-022.md` раздел «Верификация») — этот кейс формализует ТОТ ЖЕ
  сценарий как постоянный дизайн-артефакт (design-only на момент Review,
  `automated_by` пуст), закрывая пробел `test_cases: []` в самом баге.
- Навигация: `BottomNav(driver).ensure_visible()` → `open("Settings")` →
  `settings_steps.clear_all_ratings(driver)` → `BottomNav(driver).
  open("Browse")` (или `go_browse()`) — все примитивы уже существуют.
- Оракул — `seed_db.read_work_ratings_full()` трижды: до Clear all / сразу
  после Clear all (Settings) / сразу после возврата на Browse — три
  чекпоинта делают транзиентный mount+dispose различимым от простого
  отсутствия эффекта (тот же паттерн, что оригинальный witness
  test-maintainer 2026-08-02).
- **Батарея правил-реакций (CLAUDE.md)** — этот кейс закрывает
  **edge-vs-level** И **off-инвариант** ОДНИМ Then (оба bank-пункта
  совпадают в предикате `hasUnsavedEdits`: пере-mount БЕЗ семантического
  перехода = «off»-состояние флага): негативный Then явный («0 строк»),
  не отсутствие проверки. Позитивный путь,
  идемпотентность/ретроактивность/propagation — см. companion-кейс TC-193
  (обоснование н-п там же, не дублирую).
- Область НЕ комбинаторная — строка `Инвариант:` не требуется (та же
  причина, что TC-193).
- Блокеров автоматизации не обнаружено.
