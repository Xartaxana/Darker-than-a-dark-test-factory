# TC-154 — Удаление скачанного файла не воскрешает работу сканом при остатке второго файла (ожидаемо-красный, BUG-047)

## Предусловия
- Работа W (`ao3_id 900000001`) в Room с рейтингом SAVE, `downloadPath`
  указывает на файл `ao3_A_900000001.html` в дефолтной папке загрузок.
- В той же папке лежит ВТОРОЙ файл того же `ao3Id` — `ao3_ЛОКАЛЬНЫЙ_
  900000001.html` (сирота, не в `downloadPath`).
- Открыт экран Library, вкладка FAVORITE показывает карточку W с иконкой
  «Open downloaded».

## Сценарий (Given-When-Then)

**Given** работа W скачана (`downloadPath` = `ao3_A_900000001.html`), на
диске лежит ещё один файл того же `ao3Id` (`ao3_ЛОКАЛЬНЫЙ_900000001.html`,
не связан с Room)

**When** пользователь long-press по карточке W → «Delete downloaded file» →
затем Settings → «Scan for downloads»

**Then** файл `ao3_A_900000001.html` удалён с диска, `downloadPath` работы W
обнулён, карточка W показывает Download-иконку (не Open) — это ожидаемая,
незатронутая багом часть (путь TC-035)
**And** сирота `ao3_ЛОКАЛЬНЫЙ_900000001.html` остаётся на диске (удаление
затрагивает ровно один файл)
**And** ПОСЛЕ ручного скана `downloadPath` работы W должен ОСТАТЬСЯ пустым
(или скан обязан явно предупредить о найденном файле, а не молча привязать
его) — явно удалённая пользователем связь «строка↔файл» не должна
восстанавливаться сканом БЕЗ участия пользователя
**And** карточка W должна ОСТАВАТЬСЯ на Download-иконке после скана, не
переключаться обратно на «Open downloaded»

**ОЖИДАЕМОЕ ПАДЕНИЕ на текущей сборке:** по коду (`DownloadRepository.kt:
108-130`) скан не различает «файл — сирота, которую пользователь никогда не
трогал» и «файл, который пользователь только что явно удалил из-под этой же
работы» — цикл найдёт `ao3_ЛОКАЛЬНЫЙ_900000001.html`, свяжет его с работой W
(`updateDownloadPath`) и рапортует `Found 1 files — relinked 1, added 0
new.`; карточка снова покажет «Open downloaded» — явно удалённое пользователем
скачивание «оживёт» файлом, который пользователь считал удалённым. Красный
результат триажится как **APP_BUG/BUG-047**, не как расхождение теста со
спекой; ссылка: `bugs/BUG-047.md`.

## Заметки для автоматизации
- Сетап — тот же приём, что TC-153 (adb-push двух файлов, матчащих
  `WORK_ID_PATTERN`, БЕЗ зависимости от BUG-021), не блокер.
- Удаление через overlay карточки — существующий путь TC-035
  (`library_screen.py:66-68`, точный текст «Delete downloaded file», не
  «Delete work»).
- Дельта к TC-035: TC-035 знает только сценарий с ОДНИМ файлом (после
  удаления папка пуста и скан не воскрешает ничего); этот кейс — специфично
  про ОСТАТОК второго файла и последующий скан.
- Область — та же реконсиляция «файлы на диске ↔ одна строка Room», что
  TC-153 (сиблинг-кейс, тот же класс BUG-046/047, одна и та же папка/сид).
  Здесь фокус — на пользовательском НАМЕРЕНИИ (явное удаление), а не на
  идемпотентности счётчика — отдельный сценарий, не дублирует TC-153.
- `download_oracle` — та же настройка, что в TC-153 (маркер ожидаемого числа
  файлов на сетапе).
