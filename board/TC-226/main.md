# TC-226 — Батарея: ретроактивность авто-триггера

## Предусловия
- Приложение запущено с чистыми данными, синхронизация НЕ настроена
  (пустой токен). Работа X оценена локально (обычным путём, до какой-либо
  настройки синка).
- Пользователь заполняет instance/token/snippet ID (Snippet ID можно
  оставить пустым — создастся новый, как в TC-223) и сворачивает приложение
  в фон.

## Сценарий (Given-When-Then)

**Given** работа X была оценена ДО того, как синхронизация вообще была
настроена; синхронизация только что настроена (токен заполнен)

**When** приложение впервые выходит на передний план после настройки (HOME
→ повторный запуск)

**Then** авто-триггер срабатывает НЕМЕДЛЕННО на этом первом выходе на
передний план (без ожидания локального изменения БД) и публикует работу X
в сниппет — `dirty` стартует `true`, поэтому предыдущая по времени оценка
работы X участвует в первой же авто-синхронизации наравне с только что
сделанными изменениями

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа X | оценена ДО настройки синхронизации |
| Момент настройки | после оценки X |
| Ожидаемый эффект | X попадает в тело первого авто-триггера |

## Заметки для автоматизации
- Sync-фикстура (мок снимка) отсутствует — тот же класс, что кейсы области
  1. Наблюдение факта — перехват mitm на исходящий запрос записи, содержащий
  X, СРАЗУ после `send_app_to_background`/`bring_app_to_foreground_without_deep_link` (готовые
  примитивы `app_steps.py`), без дополнительного изменения БД.
