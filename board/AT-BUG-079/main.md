# AT-BUG-079 — Asymmetric shell-quotation: run_as_file_or_raise и push_app_file БЕЗ кавычек

## Окружение

Долг тестовой системы (`type: test_debt`, `debt_kind: broken_environment`) — не зависит от сборки приложения, весь код в `framework/core/adb.py` и вызывающих функциях.

## Суть долга

Сиблинг-класс AT-BUG-069 (B4-фикс `pull_app_file` квотирования, коммит `6bc81f3`). При анализе полноты class-coverage квотирования remote-shell-команд найдены ДВЕ функции, строящие команды БЕЗ защиты от пробелов/метасимволов в путях:

1. **`framework/core/adb.py:378` (`run_as_file_or_raise`)**
   ```python
   out = shell(
       f"run-as {_PKG} sh -c 'cat {path} 2>/dev/null; "
       f"echo {_RUN_AS_FILE_RC_SENTINEL}$?'",
       timeout=timeout,
   )
   ```
   Интерполяция `{path}` без кавычек. Вызывается из `app_steps.py:323` через `_TABS_PREFS_PATH` (`framework/data/consts.py` или эквивалент).

2. **`framework/core/adb.py:556` (`push_app_file`)**
   ```python
   cp_copy = _run(["-s", settings.DEVICE_NAME, "shell", 
       f"run-as {_PKG} cp {tmp} {rel_path}"])
   ```
   Интерполяция `{tmp}` и `{rel_path}` без кавычек. Вызывается из `seed_db.py:557` и других мест инициализации БД.

Класс уязвимости идентичен тому, что чинили в `pull_app_file` (B4, AT-BUG-069 фикс): пробел/пустая строка/метасимволы в `path`/`rel_path` вызовут неправильный парсинг shell'ом и могут привести к hang, потере данных или неопределённому поведению.

## Статус достижимости

**Недостижимо СЕЙЧАС** (latent debt):
- Критик перечислил все ТЕКУЩИЕ вызывающие стороны обеих функций — все передают module-константы без пробелов и метасимволов (`_TABS_PREFS_PATH`, `_DB_REL`, `_WAL`, `_SHM`, где все пути = строки типа `"files/ao3_ratings.db"`)
- `push_app_file` вдобавок громко фейлит (returncode проверяется и выбрасывает `RuntimeError` при ошибке), что снижает вероятность undetected-отказа
- Приоритет низкий, но поверхность для будущих регрессий существует

## Анализ

**Почему это test_debt, а не просто оставить:**

1. **Класс дефекта известен:** AT-BUG-069 (B4-фикс) установил precedent квотирования всех интерполяций в shell-командах. Эти ДВЕ функции остались неполные по той же логике.

2. **D-0043 (CLAUDE.md, "Чини класс, а не экземпляр"):** Дефект-класс = "unquoted shell interpolation в adb-командах". Узкий экземпляр (`pull_app_file`) уже зачинен; остальные узкие экземпляры того же класса (`run_as_file_or_raise`, `push_app_file`) требуют симметричного лечения, иначе молчаливое оставление аналога = нарушение.

3. **Не регрессия AT-BUG-069:** Код-трассировка показывает, что `run_as_file_or_raise` и `push_app_file` остались неизменёнными после B4-фикса `pull_app_file` (другие функции, не затронутые коммитом `6bc81f3`).

## Рекомендация фикса

Добавить кавычки (простые `'` внутри f-string, или использовать f-string + экранирование):

```python
# run_as_file_or_raise (line 378):
out = shell(
    f"run-as {_PKG} sh -c 'cat '{path}' 2>/dev/null; "
    f"echo {_RUN_AS_FILE_RC_SENTINEL}$?'",
    timeout=timeout,
)
# или более безопасно — экранировать одинарные кавычки в пути:
safe_path = path.replace("'", "'\\''")
out = shell(
    f"run-as {_PKG} sh -c 'cat '{safe_path}' 2>/dev/null; "
    f"echo {_RUN_AS_FILE_RC_SENTINEL}$?'",
    timeout=timeout,
)
```

```python
# push_app_file (line 556):
cp_copy = _run(["-s", settings.DEVICE_NAME, "shell", 
    f"run-as {_PKG} cp '{tmp}' '{rel_path}'"])
# или с экранированием:
safe_tmp = tmp.replace("'", "'\\''")
safe_rel = rel_path.replace("'", "'\\''")
cp_copy = _run(["-s", settings.DEVICE_NAME, "shell", 
    f"run-as {_PKG} cp '{safe_tmp}' '{safe_rel}'"])
```

## Обсуждение

**[test-maintainer @ 2026-08-18T07:58:00Z] B4: Open → Fixed.**

Прочитан артефакт целиком (Суть долга/Рекомендация фикса/Связанные находки),
прочитан `pull_app_file` (AT-BUG-069 rework attempt 2, фактическая
реализация в коде, не только докстринг-рекомендация бага) перед копированием
паттерна.

**Обе функции чинятся ПО-РАЗНОМУ, потому что удалённый транспорт у них
разный** (это важное уточнение относительно буквальной рекомендации бага,
которая предлагала одинаковый `f"... cp '{tmp}' '{rel_path}'"`-паттерн для
обеих):

- **`run_as_file_or_raise`** идёт через `shell()` — ОДНА pre-joined
  python-строка, отправляемая `adb shell <строка>` ОДНИМ argv-элементом.
  Удалённая сторона парсит её ДВАЖДЫ: implicit remote shell (извлекает
  аргумент `-c`) и затем явный ВНУТРЕННИЙ `sh -c` (парсит СВОЙ аргумент как
  отдельную команду заново). Буквальная рекомендация бага
  (`f"... sh -c 'cat '{path}' 2>/dev/null...'"`) квотирует ТОЛЬКО внутренний
  уровень и НЕ переживает внешний парсинг для path с пробелом (проверено:
  `shlex.split()` такой строки реально разбивает path на два токена уже на
  ВНЕШНЕМ уровне, до того как внутренний `sh -c` вообще получит свой
  аргумент). Фикс — ДВА слоя: одинарные кавычки вокруг `path` (внутренний
  уровень, как у `pull_app_file`) + `shlex.quote()` всей собранной
  `-c`-строки (внешний уровень, гарантирует, что implicit remote shell
  доставит её внутреннему `sh -c` буквально, не разбив на аргументы).
- **`push_app_file`** эксекает `cp` НАПРЯМУЮ через `run-as` (без явного
  `sh -c` внутри) — единственный уровень удалённого shell-парсинга, тут
  буквальная рекомендация бага (одиночные кавычки вокруг `tmp`/`rel_path`)
  корректна и применена как есть, плюс `rm -f '{tmp}'` (не названная в баге
  строка очистки, но та же переменная `tmp` — квотирование распространено
  туда же по D-0043, класс дефекта один и тот же).

Обе функции fail-closed отклоняют `ValueError` на embedded одинарную
кавычку ДО первого похода на устройство — тот же приём, что
`pull_app_file` (AT-BUG-069 rework attempt 2): кавычка внутри пути сломала
бы само квотирование, а не просто дала неверный результат.

**Красная проба** (device-free, без устройства): для каждой функции —
тест, строящий СТАРУЮ (до этого фикса) незаквоченную форму команды
напрямую по тексту бага, применяющий тот же приём `shlex.split()` (дважды
для `run_as_file_or_raise` — внешний+внутренний слой, один раз для
`push_app_file`), и показывающий, что путь с пробелом РЕАЛЬНО расщепляется
на несколько токенов на старой форме — доказательство, что основной тест
различает квотированную/неквотированную версию, а не просто ищет
подстроку с кавычками где-то в строке (тем самым избегая маскировки:
assert проверяет структуру, а не наличие символа `'`).

**Регресс проверен**: весь relevant test-файл (`test_adb_bug079_shell_
quoting_unit.py`, 7 тестов) + существующие сиблинги adb.py (`test_adb_run_
as_file_or_raise_unit.py`, `test_pull_app_file_fail_closed_unit.py`,
`test_adb_install_package_wait_unit.py`, `test_subprocess_timeout_unit.py`
