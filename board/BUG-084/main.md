# BUG-084 — Пять touch-target'ов нарушают порог 48dp (side panel, TabStrip)

## Окружение
- Версия приложения: dev-local (versionCode 12)
- Сборка: debug, source_commit fdd3f728
- Тип анализа: автоматизированный a11y свип (TC-148) — инспекция bounds accessibility-дерева через UiAutomator2
- Плотность экрана: 420 dpi (порог 48dp = 126.0px)
- Разрешение: 1080×2400

## Шаги воспроизведения (Given-When-Then)

**Given** приложение запущено в чистом состоянии, маршрут Library → Browse (side panel свёрнут и раскрыт) → Settings пройден, TabStrip виден с ≥2 вкладками

**When** accessibility-дерево читается через UiAutomator2 (без взаимодействия с элементами, только инспекция `bounds`) для набора интерактивных целей нативного хрома

**Then (ожидалось)** для каждой цели: `bounds.width >= 48dp` И `bounds.height >= 48dp` (Android accessibility guideline; 48dp переводится в device px по плотности 420 → 126px)

**Actual (фактически)** 5 из 26 проверяемых целей ниже порога:
1. Side panel: handle «Expand panel» — **84×168px = 32.0×64.0dp** (ниже порога по ширине; кликабельный контейнер Box в BrowseSidePanel.kt:118-157)
2. TabStrip: кнопка «New tab» — **109×126px = 41.5×48.0dp** (ниже порога по ширине; **обрезана краем экрана** — экран 1080×2400, `971+109=1080` за границей; координата X=971, Width=126, X+Width=1097 > 1080; компонент вероятно объявлен полными 48dp, но физически упирается в правый край, см. `TabStrip.kt:72-73`)
3. Side panel: переключатель темы (Contrast-иконка, content-desc «Switch to dark mode») — **63×126px = 24.0×48.0dp** (ниже порога по ширине; **обрезан ПЕРЕКРЫТИЕМ соседнего узла** хэндла «Collapse panel» [`[63,496][189,664]`], реальный кликабельный контейнер темы шире, но accessibility-дерево отдаёт обрезанный bounds)
4. Side panel: кнопка размера шрифта «A-» — **117×95px = 44.6×36.2dp** (ниже порога по обеим осям, видно в SettingsScreen.kt:1596-1624, FontSizeRow)
5. Side panel: кнопка размера шрифта «A+» — **117×95px = 44.6×36.2dp** (ниже порога по обеим осям)

## Частота
Детерминированно воспроизводится: 2 независимых полных прогона теста TC-148, оба падения ПОБАЙТОВО идентичны.

## Анализ (failure-analyst)

Это баг приложения, не теста:

1. **Тест работает правильно.** TC-148 проверяет ФАКТИЧЕСКИЕ bounds из accessibility-дерева (то же, что видит TalkBack и UiAutomator2), а не эмоциональный размер иконки. Свойство «touch-target >= 48dp» требуется от ПРИЛОЖЕНИЯ, не от теста.

2. **Приложение реально нарушает порог.** Замеры воспроизведены дважды подряд в одинаковом виде; физические размеры элементов на экране подтверждены независимым `uiautomator dump`. Это НАБЛЮДАЕМОЕ поведение, не артефакт раннера.

3. **Два типа нарушений.**
   - **Объявленный размер ниже порога** (находки 1, 4, 5): BrowseSidePanel.kt и SettingsScreen.kt содержат компоненты, объявленные с размерами ниже 48dp. Это вопрос дизайна компонента.
   - **Фактический размер урезан** (находки 2, 3): компоненты объявлены как 48dp, но bounds в accessibility-дереве меньше из-за внешних физических ограничений. TabStrip«New tab» упирается в край экрана (1080px); переключатель темы перекрыт соседним узлом хэндла. ДЛЯ РАЗРАБОТЧИКА: не достаточно открыть код и увидеть `48dp` — нужна проверка ФАКТИЧЕСКИХ bounds через accessibility-дамп (uiautomator dump / page_source), потому что rendering и overlap могут урезать то, что объявлено.

4. **Порог — стандарт Android.** 48dp — минимальный размер touch-target по Android accessibility guideline (docs/01-test-strategy.md §9); это не произвольный порог теста.

5. **Область и риск:** accessibility (риск R-13). Нарушение может препятствовать доступу пользователей с моторными ограничениями.
