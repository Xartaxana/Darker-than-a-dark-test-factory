# TC-262 — Back на Library и на Settings переводит на Browse, не выходит из приложения

## Предусловия
- Приложение запущено с чистыми данными (`clean_app`).
- Почему не L2: реальная системная кнопка/жест Back и `BackHandler` на
  уровне `MainActivity` — устройство обязательно.

## Сценарий (Given-When-Then)

**Given** приложение запущено, активна нижняя вкладка Browse (дефолт)

**When** пользователь переключается на нижнюю вкладку Library и нажимает
системный Back

**Then** нижняя навигация переключается на Browse (селектор активной
вкладки — Browse), приложение НЕ завершается/не уходит в фон
(`query_app_state(APP_PACKAGE) == 4`, остаётся foreground)

**When** (тот же прогон, пересидинг легален — переключение вкладки не меняет
стоимость Given) пользователь снова переключается, на этот раз на Settings,
и нажимает системный Back

**Then** нижняя навигация СНОВА переключается на Browse, приложение
по-прежнему foreground

**Инвариант:** `BackHandler(enabled = selectedTab != BROWSE)` перехватывает
Back на ЛЮБОЙ НЕ-Browse вкладке нижней навигации ОДИНАКОВО (переход на
Browse, не выход) — свойство проверено на ДВУХ разных исходных вкладках
(Library, Settings), не на одном примере.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Исходная вкладка → после Back | Library → Browse; Settings → Browse |
| Состояние приложения после обоих Back | foreground (`query_app_state==4`) |

## Заметки для автоматизации
- Переключение нижней вкладки — существующий `app_steps.open_tab(driver,
  "Library"/"Settings"/"Browse")` (используется повсеместно, TC-204 и др.).
- Системный Back — `contexts.to_native(driver)` + `driver.back()`, тот же
  приём, что TC-261/BUG-019-верификация.
- Определение активной нижней вкладки после Back — существующий
  a11y-локатор нижней навигации (селектор выбранного `NavigationBarItem`,
  используется в шагах `app_steps.open_tab`/аналогичных ассертах текущей
  вкладки — тот же локатор, вызванный «в обратную сторону», не новый
  примитив).
- `query_app_state(APP_PACKAGE)==4` — контрольная проверка, что Back НЕ
  унёс в фон (симметричный контроль к TC-261, где 4→<4 на дне стека
  Browse); переиспользует тот же приём, что `send_app_to_background`.
- Блокера автоматизации нет — все примитивы существуют.
