# TC-112 — Favorite не скачивает файл при выключенном Auto-download

## Предусловия
- Приложение запущено с чистыми данными; тумблер «Auto-download favorite works» НЕ
  включён (дефолтное состояние `autoDownloadSaved=false` — просто не вызывать
  `settings_steps.enable_auto_download`, explicit-выключение не требуется).
- Работа W засеяна как placeholder БЕЗ рейтинга, но с полными title/author/fandom/
  wordCount (тот же приём, что `placeholder_seeded_work`/TC-007 — переводит панель
  на ветку «обновить существующую строку» без сетевого скрейпа живой страницы).
- Открыта страница работы `/works/{id}` (live-навигация, replay не требуется —
  тумблер выключен, `downloadWork` не вызывается вовсе, сетевого скачивания в
  сценарии нет).

## Сценарий (Given-When-Then)

**Given** тумблер «Auto-download favorite works» выключен, работа W (placeholder, без
рейтинга) открыта на странице `/works/{id}`, панель `RatingMenu` раскрыта

**When** пользователь нажимает кнопку рейтинга «Favorite» (SAVE) на панели

**Then** рейтинг сохраняется — работа W появляется во вкладке FAVORITE экрана Library
**And** карточка работы W показывает download-иконку (НЕ open-иконку) — файл не
скачан, `downloadPath` не выставлен
**And** работа W НЕ появляется во вкладке FILES экрана Library
**And** в download-директории приложения (`getExternalFilesDir("ao3_downloads")`) не
появляется ни одного нового файла — оракул побочных эффектов (`download_oracle`,
`framework/tests/conftest.py`) не фиксирует незапрошенное скачивание (тест НЕ несёт
`@pytest.mark.produces_download`, ожидание по умолчанию — 0 файлов)

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа W | placeholder-сидинг (см. `placeholder_seeded_work`/TC-007), например `W.LOVED` |
| Тумблер Auto-download | OFF (дефолт после `clean_state`) |

## Заметки для автоматизации
- Позитивный симметричный кейс — TC-032 (тот же панельный вход `rate_current_work`,
  но тумблер включён и используется `work_with_download.mitm` для реального
  скачивания). Здесь replay НЕ нужен: `downloadWork()` при выключенном тумблере не
  вызывается вовсе (`BrowserViewModel.kt:756-758` — предикат `autoDownloadSaved`
  ложен), поэтому нет ни одного сетевого вызова, который нужно было бы
  инсценировать записью.
- Отрицательный Then про отсутствие файла ЯВНЫЙ (карточка/вкладка FILES) — НЕ
  полагается только на молчаливое отсутствие проверки; `download_oracle`
  дополнительно и независимо ловит любой файл, появившийся в download-директории,
  даже если UI-ассерт по какой-то причине пропущен — двойная защита того же
  инварианта (класс BUG-014, docs/02-framework-architecture.md §5а).
- **Батарея правил-реакций (off-инвариант):** это и есть off-инвариант-кейс,
  требуемый калибровкой №4 (CLAUDE.md, «off-инвариант: при выключенной настройке —
  ЯВНЫЙ негативный Then»). Остальные пункты батареи (edge-vs-level, ретроактивность,
  идемпотентность, propagation) закрыты соседними TC-113..117, см. их заметки.
- Шаги: `rating_steps.open_work_page` + `rating_steps.rate_current_work(driver,
  "SAVE")` — уже существуют, использовались в TC-007/TC-032, дополнительных
  локаторов не требуется. Проверка вкладки FILES — `library_steps.
  assert_work_not_in_files_tab` (уже существует, используется в TC-035).
