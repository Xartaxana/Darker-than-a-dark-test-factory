# TC-141 — Асимметрия путей: панель work-страницы не кликает kudos даже там, где листинг кликает (баг)

## Предусловия
- Приложение запущено, режим replay (`work_with_download.mitm`, после фикса
  `bugs/AT-BUG-035.md` — та же запись, что TC-114/116/117, несёт валидную
  work-страницу + download-транзакцию для W.LOVED).
- Работа W = `LOVED` (900000001) засеяна напрямую в Room с рейтингом SAVE
  (Favorite), без личных тегов (`app_steps.seed_library([(W.LOVED, "SAVE")])`).
- Открыта страница работы W `/works/{id}` (панель `RatingMenu` раскрыта, уже
  показывает Favorite выбранным — рейтинг прочитан из Room при загрузке).
- Узел `#kudo_submit` на этой же странице без `data-kudo-clicked` (baseline).

## Сценарий (Given-When-Then)

**Given** работа W уже имеет рейтинг Favorite (SAVE); открыта её work-страница,
встроенная панель показывает Favorite выбранным; узел `#kudo_submit` без
`data-kudo-clicked`

**When** пользователь раскрывает раздел тегов ВСТРОЕННОЙ панели (не bottom-sheet
листинга) и добавляет личный тег «panel-kudos-probe» (правка метаданных, рейтинг
НЕ меняется, остаётся Favorite) — идёт веткой `savePanelRating`, `existing != null`
(`:743-758`), тот же вход, что TC-114 для авто-скачивания

**Then** тег «panel-kudos-probe» сохраняется среди выбранных (наблюдаемая суть
операции)
**And** узел `#kudo_submit` на ТОЙ ЖЕ (единственной открытой) work-вкладке НЕ
получает `data-kudo-clicked` — Then фиксирует различие между путями КАК ЕСТЬ, не
как решение: то же по смыслу действие (правка тега уже-оценённой работы),
сделанное через панель work-страницы, kudos-кликом не сопровождается вовсе,
тогда как тот же класс действия через листинг (TC-139) кликает (баг, ядро
BUG-015) — асимметрия путей задокументирована исполняемым кейсом, не только
код-ревью

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа W | `W.LOVED`, засеяна напрямую с rating=SAVE, tags=[] |
| Добавляемый тег | «panel-kudos-probe» |
| Replay | `rb.WORK_WITH_DOWNLOAD_FILENAME` (`work_with_download.mitm`) |

## Заметки для автоматизации
- **БЛОКЕР (test_debt) — общий для области:** `bugs/AT-BUG-035.md`; `automated_by`
  пуст. Обоснование общее для всех семи кейсов — см. TC-138
  (`test_cases: [TC-138..TC-144]`). Здесь фикс касается
  `render_work_page_html`, которую использует и `build_work_with_download` —
  один и тот же фикс закрывает узел на ОБЕИХ базовых записях (`listing_basic.mitm`
  и `work_with_download.mitm`).
- **Позитивный контроль панельного пути — TC-144 (B3, critic attempt2).** Этот
  кейс проверяет негатив на ветке `savePanelRating`, `existing != null` (запись
  УЖЕ в Room) — панель никогда не кликает kudos на этой ветке. Соседняя ветка
  ТОГО ЖЕ панельного механизма (`onRateWorkRequested`/`pendingPanelSave`,
  `:1053-1054`, запись ЕЩЁ НЕ в Room — первое сохранение) кликает — это TC-144,
  спроектированный ИМЕННО как позитивный контроль: доказывает, что панельный
  путь, инструментация узла и механика чтения `#kudo_submit` работоспособны в
  принципе, когда правило-реакция ДОЛЖНО сработать. Без TC-144 зелёный TC-141
  неотличим от «панель никогда физически не может кликнуть/узел недостижим со
  страницы работы» — та же логика, что связка TC-138↔TC-139/140/142/143 для
  листингового пути.
- Добавление тега через встроенную панель — готовый `rating_steps.add_tag_via_panel`
  (использован TC-114).
- **Наблюдаемость негативного Then:** тот же класс обоснования, что уже закрыт
  для авто-скачивания на TC-114/116/117 (2026-07-29/30, critic-вход) — сама ветка
  `:743-758` структурно НЕ содержит вызова с kudos, но негативный Then проверяет
  отсутствие эффекта ГИПОТЕТИЧЕСКОГО бага (например, ошибочное смешение веток
  panel/listing), а не отсутствие штатного поведения; узел `#kudo_submit`
  инструментирован и присутствует НА ТОЙ ЖЕ странице, поэтому если бы гипотетический
  баг всё же дошёл до клика — тест бы его поймал. Не вакуумный негатив.
- Известная СИБЛИНГ-находка (в скоуп этого кейса не входит, докладываю по D-0043):
  та же ветка `:756-758` этой функции запускает авто-скачивание при
  `rating == SAVE && autoDownloadSaved` — это ДРУГОЙ дефект (BUG-014,
  edge-vs-level авто-скачивания), уже покрыт TC-114 на ЭТОЙ ЖЕ фикстуре; не
  путать assert'ы между двумя правилами-реакциями одной ветки кода.
- **Батарея правил-реакций** (место вызова `:743-758`, панельный путь):
  - edge vs level — **н-п для ЭТОГО места вызова**: предикат kudos-клика здесь
    отсутствует СТРУКТУРНО (ни на edge, ни на level этот код-путь не кликает) —
    это не edge-vs-level дефект, а асимметрия ПУТЕЙ, что и есть предмет кейса.
  - ретроактивность/off-инвариант — **н-п**, см. TC-138 (нет тумблера,
    управляющего kudos; здесь дополнительно нечему быть ретроактивным — путь
    вообще не участвует в правиле).
  - идемпотентность — **н-п**: сайт никогда не кликает, нечему дублироваться.
  - propagation — **н-п**: эффекта нет, соответственно нет и потребителей.
