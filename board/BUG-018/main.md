# BUG-018 — DOM-ссылка «Next →» указывает на уже показанную страницу

## Окружение
- Версия: 1.10 (versionCode 11), built_at 2026-07-02T02:39:46
- Эмулятор: emulator-5554 (ao3_test_api34, API 34)
- Режим: replay (`listing_paginated.mitm`)
- Сборка: debug

## Шаги воспроизведения (Given-When-Then)

**Given**
1. Приложение открывает листинг из фикстуры `listing_paginated.mitm` (5 страниц, по 1 работе на странице)
2. Infinite-scroll включен (тумблер ON в Settings)
3. Пользователь находится на странице 1

**When**
1. Скролл к самому низу → каскад подгрузок и эвикция окна `PAGE_WINDOW=3` (ao3_bridge.js:594-605)
2. После каскада в DOM находятся блёрбы страниц 2, 3, 4 (страница 1 эвиктирована)
3. DOM-ссылка «Next →» остаётся видимой (`.next` не прячется ни в каком состоянии, ao3_bridge.js:541-545)

**Then (ожидалось)**
- DOM-ссылка «Next →» должна указывать на первую **нефактическую** страницу (например, страница 5)
- Тап по ссылке должен загрузить НОВЫЙ контент, которого нет в DOM
- Внутренний `_effectiveNextUrl` отражает реальное состояние

**Actual (фактически)**
- DOM-ссылка «Next →» по-прежнему `…&page=2` — то есть на первую же следующую страницу НОМЕРОМ
- Содержимое страницы 2 **уже находится в DOM** (она подгружена каскадом)
- Тап по «Next →» загружает страницу 2 ПОВТОРНО, переводя пользователя **НАЗАД** на контент, который он только что пролистал
- Внутренний `_effectiveNextUrl` при этом корректен (например, `…&page=5`), но пользователь видит некорректную ссылку

## Частота
**3 из 3 наблюдений:**
- Seed 1 (CH-006): DOM-снимок после каскада показывает, что «Next →» указывает на `…&page=2` (s1-03, пункт 7 протокола)
- Seed 3a (CH-006): реальный тап по «Next →` загружает страницу 2 (s3a-03, пункт 13 протокола)
- Seed 3b (CH-006): после подгрузки на странице 2, новый каскад эвиктирует блёрб страницы 2, а следующая «Next →» остаётся указывать на `…&page=3` вместо следующей нефактической (пункт 14 протокола)

Контроль: без каскада (свежая загрузка с одной страницей) ссылка корректна.

## Анализ (баг приложения)

Код-гипотеза по ao3_bridge.js:

**Строки 506-508 (шапка):**
```javascript
// Prev/Next are overridden … sessionStorage
```

**Строки 538-545 (тело):**
Здесь должен быть код переписывания `href` элементов `.next` и `.previous`, но его нет. Ссылки остаются нативными (непеписанными).

Причина: когда загружаются новые страницы в infinite-scroll, массив `_loadedPages` растёт, но **DOM-ссылки `href` не обновляются** под текущий контекст окна (какие страницы реально в DOM). Внутренний `_effectiveNextUrl` правильно отслеживает логическую позицию (`_loadedPages.length + 1`), но этот URL не переписывается в DOM.

Результат: пользователь видит ссылку на первую же следующую НОМЕРНУЮ страницу (не логическую), которая уже в DOM, создавая иллюзию кругового движения.
