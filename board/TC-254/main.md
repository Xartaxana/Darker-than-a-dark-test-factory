# TC-254 — Перехват громкости шире заявленного: работает поверх оверлея

## Предусловия
- Настройка «Page with volume buttons» ON. Пользователь на вкладке Browse,
  поверх открыт rating-overlay (например, через overlay действие) — оверлей
  визуально закрывает WebView.

## Сценарий (Given-When-Then)

**Given** настройка ON, выбранная нижняя вкладка — BROWSE, поверх WebView
открыт rating-overlay (модальный элемент)

**When** пользователь нажимает VOLUME_DOWN, желая изменить РЕАЛЬНУЮ
громкость устройства (например, для звонка)

**Then** нажатие ВСЁ РАВНО перехвачено приложением — scroll активной
вкладки под оверлеем сдвигается, системный индикатор громкости НЕ
появляется, РЕАЛЬНАЯ громкость устройства не меняется — пользователь не
может воспользоваться клавишей по системному назначению, пока стоит на
вкладке Browse, чем бы он там ни занимался (rating-overlay, side panel,
диалог — предикат смотрит только на `selectedTab`, не на фактическую
видимость WebView)

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Настройка | ON |
| Выбранная вкладка | BROWSE |
| Открытый элемент поверх | rating-overlay (модальный) |
| Ожидаемый результат | перехват сработал, системная громкость не изменилась |

## Заметки для автоматизации
- **Блокер автоматизации — `bugs/AT-BUG-072.md`** (тот же класс). Кейс
  оставлен в `Review`.
- Это КЛЮЧЕВАЯ асимметрия, ради которой область поднята в P1 (docs/01
  §9) — дефолт настройки ВКЛЮЧЁН, поэтому граница задевает пользователей
  без единого действия с их стороны. Вопрос разработчику уже вынесен в
  §10 (щ) п.3, баг не заводится этим design'ом.
- side panel и диалог — тот же код-путь (одна и та же проверка
  `selectedTab==BROWSE`), отдельных кейсов на каждый конкретный оверлей не
  заводится (не BUG-014-класс — единая точка предиката, не несколько
  асимметричных путей).
