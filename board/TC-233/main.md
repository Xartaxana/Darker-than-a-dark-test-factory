# TC-233 — Токен уходит на любой введённый хост

## Предусловия
- Устройство под mitm-прокси (весь трафик наблюдаем). В Settings введён
  НЕСТАНДАРТНЫЙ хост инстанса (не `gitlab.com`, например
  `https://gitlab.internal.test` или заведомая опечатка), токен и Snippet ID
  заполнены.

## Сценарий (Given-When-Then)

**Given** instance-поле указывает на нестандартный/непроверенный хост,
токен непуст

**When** пользователь запускает «Sync now»

**Then** исходящий запрос уходит ИМЕННО на введённый хост (не на
`gitlab.com` по умолчанию, не отфильтрован никаким allowlist'ом)
**And** запрос несёт заголовок `PRIVATE-TOKEN` со значением токена в
открытом виде — токен уходит на ЛЮБОЙ хост, который ввёл пользователь, без
проверки его легитимности приложением

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Instance | нестандартный хост (не gitlab.com) |
| Заголовок | `PRIVATE-TOKEN: <значение токена>` |
| Целевой хост запроса | совпадает с введённым, без подмены |

## Заметки для автоматизации
- Требует mitm-перехвата ИСХОДЯЩЕГО запроса (хост + заголовки) — тот же
  класс инфраструктурного долга, что sync-кейсы области sync (мок ответа
  необязателен, здесь важен факт запроса, ответ может быть любым, включая
  ошибку соединения на несуществующий хост — если приложение делает попытку
  подключения, факт уже наблюдаем на уровне мitm ДО ответа).
