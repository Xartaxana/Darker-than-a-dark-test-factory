# Тап по НЕ-whitelisted узлу с собственным обработчиком в теле work-страницы запускает ОБА эффекта (guard-пробой, replay)

# TC-120 — Тап по не-whitelisted узлу со своим обработчиком запускает и зону, и обработчик (replay)

## Предусловия — БЛОКЕР (заведён test_debt-багом AT-BUG-030 в этом же ходе)
- Приложение запущено с чистыми данными, `tap_to_scroll` включён в Settings.
- Открыта replay work-страница (`recording_builder.py::render_work_page_html`)
  — **фикстура СЕЙЧАС НЕ содержит НИ ОДНОГО узла вне whitelist guard'а со
  своим обработчиком** (`div[onclick]`/`[role]` с не-whitelisted тегом) — нужен
  фикстурный узел (например, `<div onclick="this.setAttribute('data-tapped',
  '1')" style="...">`), расположенный в СРЕДНЕЙ трети viewport (см.
  AT-BUG-030, критерий совпадает с TC-119).
- Нижняя панель свёрнута, открыто >=2 вкладок, высота документа >= 3×
  `innerHeight`.

## Сценарий (Given-When-Then)

**Given** приложение открывает replay work-страницу с `tap_to_scroll=ON`;
нижняя панель свёрнута, >=2 вкладки, документ высокий; в теле страницы
присутствует фикстурный `<div data-tap-marker>` БЕЗ whitelisted-тега/role,
несущий собственный `onclick`-обработчик, расположенный в средней трети
текущего viewport

**When** пользователь тапает по этому узлу (координата попадает на сам
элемент, средняя треть экрана, не ниже `wv.y + wv.height + 53`)

**Then** зональное действие СРЕДНЕЙ трети (`Android.toggleFullscreen()`)
ВЫЗЫВАЕТСЯ — TabStrip/системные бары переключают состояние (наблюдаемо тем же
прокси, что TC-058)
**And** ОДНОВРЕМЕННО собственный обработчик узла СРАБАТЫВАЕТ (`data-tapped`
установлен) — guard НЕ отсёк тап, хотя у узла есть собственный обработчик,
потому что тег/role узла не входит в whitelist (`ao3_bridge.js:1155`) — оба
потребителя одного физического тапа получили событие (CH-005 находка 2)

**Инвариант:** решение guard'а — функция ТОЛЬКО от членства `e.target.
closest(...)` в whitelist тегов/role, не от наличия собственного обработчика
(см. сиблинг TC-119: та же «есть обработчик» = true, но «в whitelist» = true
⇒ подавлено; здесь «в whitelist» = false ⇒ НЕ подавлено — единственная
варьируемая переменная объясняет разницу Then).

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Тумблер | `tap_to_scroll` = ON |
| Целевой узел | фикстурный `<div data-tap-marker onclick=...>` (НЕ входит в whitelist тегов/role) |
| Зона тапа | средняя треть viewport |
| Ожидаемый Then | toggleFullscreen ВЫЗВАН И собственный обработчик узла ВЫЗВАН — оба |

## Заметки для автоматизации — БЛОКЕР (заведён test_debt-багом AT-BUG-030 в этом же ходе)
- **Суть блокера:** тот же фикстурный пробел, что у сиблинга TC-119 (см. там),
  плюс отдельно — отсутствие НЕ-whitelisted интерактивного узла с собственным
  обработчиком. Один баг `bugs/AT-BUG-030.md` покрывает ОБА узла (button +
  div[onclick]) одним фиксом `render_work_page_html`, `test_cases: ["TC-119",
  "TC-120"]` — не два отдельных тикета на один и тот же метод фикстуры.
- До готовности фикстуры кейс остаётся `status: Review` (не `Blocked`), тот же
  паттерн, что TC-115/AT-BUG-029.
- Это единственный кейс области, доказывающий САМ ДЕФЕКТ guard'а (двойное
  потребление) на детерминированном узле — TC-118 (числовая проба на живом
  AO3) без этого кейса неинтерпретируема (число кандидатов есть, но неизвестно,
  реально ли guard их пробивает).
- `data-tapped` — самый дешёвый наблюдаемый маркер собственного обработчика
  (без побочных навигационных эффектов, в отличие от `<a href>`) — не путать
  с проверкой факта клика через сетевой запрос/навигацию.
- Маркер: без `@pytest.mark.live` (полностью replay/детерминированный).
- **Батарея правил-реакций (оценка применимости):** этот механизм — НЕ
  тумблер-эффект в терминах батареи CLAUDE.md (auto-download/kudos/broadcast и
  т.п.), а DOM-guard с бинарным Then на статическую разметку страницы;
  пункты edge-vs-level/ретроактивность/idempotency/propagation — н-п: нет
  состояния, сохраняемого между сохранениями/перезапусками, и нет других
  потребителей эффекта кроме самой открытой WebView. off-инвариант — уже
  часть ЭТОЙ же области отдельным TC (`tap_to_scroll=OFF` — негативный
  инвариант «тап ничего не делает» дизайнится в needs-design области
  reading-UX жесты `settings-tap-to-scroll-toggle`, docs/01 строки ~758-764 —
  НЕ в owns этого диспатча).
