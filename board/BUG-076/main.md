# BUG-076 — Перехват кнопок громкости работает при перекрытом Browse (диалоги, overlay, панели)

## Окружение
- Версия приложения: dev-local (versionCode 12)
- Сборка: debug, source_commit aa377e0e (2026-06-28)
- Тип анализа: code inspection MainActivity.kt

## Шаги воспроизведения (Given-When-Then)

**Given** 
1. Приложение запущено
2. Пользователь находится на вкладке Browse (или в позиции, где Browse видна)
3. Настройка "Volume buttons for paging" включена (дефолт: ON) (SettingsScreen.kt)

**When** поверх Browse открывается системный компонент или компонент приложения:
- Диалог (AlertDialog, BottomSheetDialog)
- Side panel (боковая панель Browse)
- Overlay (модальная панель)
- Любой другой UI-слой, блокирующий взаимодействие с основным контентом Browse

И пользователь нажимает кнопку громкости (KEYCODE_VOLUME_UP или KEYCODE_VOLUME_DOWN)

**Then (ожидалось)**
- **Вариант А:** перехват ОТКЛЮЧАЕТСЯ (громкость работает как обычно системная громкость)
- **Вариант Б:** перехват ОСТАЁТСЯ АКТИВНЫМ, но приложение показывает сообщение о том, что громкость перехвачена для листания

**Actual (фактически)**
Перехват активен и приложение обрабатывает нажатие как команду листания, НЕСМОТРЯ НА то, что Browse скрыт за диалогом/overlay/панелью:
- Громкость НЕ регулируется (системная громкость не меняется)
- Кнопка листания срабатывает на невидимом контенте (если внутри диалога есть input, громкость не нажимается, но это не видимо пользователю как целенаправленное действие)
- **Нет сообщения об этом** — пользователь не понимает, почему нажатие громкости ничего не делает

## Код, описывающий проблему

**MainActivity.kt:304** — предикат, проверяющий только АКТИВНУЮ нижнюю вкладку:

```kotlin
fun onKeyDown(keyCode: Int, event: KeyEvent?): Boolean {
    if ((keyCode == KeyEvent.KEYCODE_VOLUME_DOWN || keyCode == KeyEvent.KEYCODE_VOLUME_UP) &&
        uiState.activeTabIndex == TAB_INDEX_BROWSE &&  // ← только если АКТИВНА вкладка Browse
        settingsViewModel.volumeButtonPaging) {
        // обработка листания
        return true
    }
    return false
}
```

Проблема: проверка `activeTabIndex == TAB_INDEX_BROWSE` гарантирует, что вкладка Browse ВЫБРАНА, но **НЕ гарантирует, что она ВИДИМА** (может быть перекрыта диалогом или overlay).

**Дополнительная проблема:** нет НИ ОДНОГО сообщения пользователю о том, что громкость перехвачена (нет Toast, нет визуального индикатора). Пользователь нажимает громкость и получает молчаливый отказ (кнопка не регулирует громкость, и это непонятно почему).

## Дефолт-поведение настройки

Согласно коду (SettingsScreen.kt), настройка "Volume buttons for paging" **включена по умолчанию** — пользователь может случайно нажать громкость, ожидая её регуляции, и получить непредсказуемое поведение.

## Анализ

Класс дефекта: асимметрия между логикой приложения (проверка активной вкладки) и пользовательским ожиданием (громкость должна регулировать громкость, если она не используется другим компонентом).

**Проблема 1:** перехват слишком широк. Проверка `activeTabIndex == TAB_INDEX_BROWSE` недостаточна — нужна также проверка **видимости** Browse (нет ли диалогов/overlay над ней).

**Проблема 2:** молчание о перехвате. Пользователь не знает, перехвачена ли громкость; при нажатии в диалоге он не видит никакого feedback.

**Проблема 3:** дефолт включен. Без явной настройки пользователь может случайно нажать громкость и получить неожиданное поведение (листание вместо регулировки громкости).

## Вопрос разработчику

Является ли перехват при перекрытом Browse задуманным? Или требуется:
1. Проверять не только активность вкладки, но и её видимость (отсутствие диалогов/overlay)?
2. Добавить сообщение пользователю при перехвате (Toast / Snackbar: "Volume buttons are used for paging" или аналог)?
3. Изменить дефолт на выключено (чтобы пользователь явно включил эту функцию)?
