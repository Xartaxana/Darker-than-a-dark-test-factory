# TC-198 — Баннер отсутствует в чистом Dim-режиме, хотя работа затемнена

## Предусловия
- Приложение запущено, `seeded_library` (в т.ч. `DISLIKED`, `rating=DISLIKE`).
- В Settings → Content Visibility → Display mode выбран **Dim**
  (`settings_steps.set_display_mode(driver, "Dim")`) ДО первой навигации на
  листинговую страницу в этой вкладке — тот же порядок, что TC-092 (флаг должен
  попасть через инъекцию при `onPageFinished`, не через реактивный live-push).
- Disliked остаётся в hidden-set (дефолт `hiddenRatings={DISLIKE}`) — тумблеры
  per-rating не трогаем.
- Фильтр-профиль не выбран (`activeFilterId=null` дефолт) — `ao3FilterActive=false`.
- Открыта листинговая страница (replay `listing_basic.mitm`).

## Сценарий (Given-When-Then)

**Given** приложение запущено с `seeded_library`, Display mode в Settings уже
установлен в Dim, Disliked в hidden-set, фильтр-профиль не выбран

**When** пользователь открывает листинговую страницу, содержащую блёрб DISLIKED

**Then** узел `#ao3-companion-hidden-notice` ОТСУТСТВУЕТ в DOM целиком — условие
создания требует `ratedHidden || filterActive` (`ao3_bridge.js:479`), а
`ratedHidden` в Dim-режиме всегда `false` (`MainActivity.kt:282-283` жёстко
проверяет `filterDisplayMode == "hide"`), `filterActive` тоже `false` (фильтр не
выбран) — оба условия ложны
**And** при этом блёрб DISLIKED НЕ удалён из разметки, а визуально затемнён:
`display != 'none'`, `opacity: 0.3` (тот же наблюдаемый факт, что TC-092) — работа
так же реально исключена пользовательским фильтром, но баннер об этом молчит

**Наблюдение / кандидат в вопрос разработчику (НЕ решение test-designer, см.
docs/01-test-strategy.md §9 текст задачи):** формулировка баннера намеренно или
случайно не покрывает dim-режим — условие `ratedHidden` в `MainActivity.kt:282`
жёстко требует `filterDisplayMode == "hide"`. Пользователь в Dim-режиме теряет
единственный канал уведомления «часть выдачи скрыта» (критерий владельца §10(п)
«есть сообщение — норма, нет сообщения — дефект») именно в тот момент, когда
визуально работы ВСЁ ЕЩЁ на странице (просто полупрозрачные) — это может быть
МЕНЕЕ заметно пользователю, чем полное удаление карточек в Hide-режиме, где
баннер как раз есть. Финальное решение (баг или намеренное поведение) — за
владельцем/Lead, эту грань test-designer не решает и не переоткрывает наощупь.

**Инвариант:** присутствие баннера обусловлено ИСКЛЮЧИТЕЛЬНО значением
`filterDisplayMode` через флаг `ratedHidden`, а не фактом визуального исключения
работы со страницы; для ЛЮБОЙ работы, чей рейтинг входит в hidden-set при
`filterDisplayMode='dim'` и нет активного AO3-фильтра, баннер не появится, даже
если карточка реально dim'ится — асимметрия между «работа скрыта» и «пользователь
уведомлён об этом», доказанная здесь на представителе DISLIKED.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа | `DISLIKED` из `framework/data/works.py`, `rating=DISLIKE` |
| Display mode | Dim |
| `ratedHidden` | false (несмотря на непустой hidden-set — гейт по режиму) |
| `ao3FilterActive` | false |
| Баннер | отсутствует |
| Блёрб DISLIKED | `display != 'none'`, `opacity: 0.3` |

## Заметки для автоматизации
- Не блокер: метод чтения баннера — см. заметку TC-197 (переиспользуется тут же).
- `opacity_of`/`is_dimmed` уже существуют в `ListingPage` (`framework/web/listing_page.py`,
  добавлены для TC-092/093) — переиспользовать без доработки.
- `settings_steps.set_display_mode` уже существует (обёртка над
  `SettingsScreen.tap_display_mode`, использована TC-092/093).
- Порядок действий — тот же, что TC-092: `app_steps.open_tab(driver, "Settings")`
  → `settings_steps.set_display_mode(driver, "Dim")` → `app_steps.open_tab(driver,
  "Browse")` → `browser_steps.open_listing(driver, rb.LISTING_BASIC_URL)`.
- Использовать `seeded_library` (уже содержит DISLIKED) — отдельного сидинга не
  требуется.
- **Батарея правил-реакций:** off-инвариант этого кейса — ЯВНЫЙ негативный Then
  (баннера нет) — уже покрыт основным сценарием. Остальные пункты — см. общую
  оценку в TC-201/203/204 (эта запись про грань hide/dim не добавляет новых
  мест вызова правила, использует тот же call-site `updateHiddenBanner` на
  page-load, что и TC-197).
