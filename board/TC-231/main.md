# TC-231 — Авто-триггер молча удаляет работу и файл по надгробию

## Предусловия
- Синхронизация настроена. Та же ситуация, что TC-209 (работа Y с
  заметкой/тегами/скачанным файлом, входящее более свежее надгробие), но
  триггер — АВТОМАТИЧЕСКИЙ (выход на передний план), а не ручной тап.

## Сценарий (Given-When-Then)

**Given** локальная работа Y с заметкой/тегами/скачанным файлом и более
свежее входящее надгробие Y (как в TC-209)

**When** приложение выходит на передний план (авто-триггер сливает
надгробие)

**Then** работа Y исчезает из Library и её файл физически удаляется с диска
(тот же разрушительный эффект, что TC-209)
**And** пользователю НЕ показано НИ ОДНОГО уведомления об этом удалении — ни
диалога, ни snackbar/toast — контраст с явными подтверждающими диалогами
локального «Delete work»/Clear all ratings, которые пользователь САМ
инициирует осознанно

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа Y | comment+tags+downloadPath (как TC-209) |
| Путь | авто-триггер |
| Ожидаемая видимость пользователю | ноль |

## Заметки для автоматизации
- Sync-фикстура отсутствует — тот же класс, что TC-209, применённый к
  авто-пути.
- Наблюдаемость негативного Then — тот же приём, что TC-230: сначала
  подтвердить, что удаление РЕАЛЬНО произошло (файл физически отсутствует
  на диске — `adb shell ls`), затем — что UI не показал предупреждения.
- Второй, самый острый красный флаг области (наряду с TC-230) — вопрос
  разработчику уже вынесен в §10 (щ) п.3, баг не заводится этим design'ом.
