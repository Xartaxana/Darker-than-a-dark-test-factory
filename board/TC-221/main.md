# TC-221 — Ручной прогон с изменениями: индикация + итоговый диалог

## Предусловия
- Синхронизация настроена. Локально есть 1 работа, требующая публикации
  (изменённый рейтинг после последнего синка). Удалённый снимок (мок) несёт
  ОТДЕЛЬНОЕ изменение — другую работу с более новым `timestamp` (входящее
  изменение) и удалённый фильтр-профиль с более новым `timestamp`.

## Сценарий (Given-When-Then)

**Given** локально есть неопубликованное изменение работы A, удалённо есть
входящее изменение работы B и фильтр-профиля C (описано выше)

**When** пользователь нажимает «Sync now»; пока идёт прогон — сразу
повторно тапает по кнопке; дожидается завершения

**Then** во время прогона подпись кнопки — «Syncing…», повторный тап НЕ
запускает второй параллельный прогон (сетевой перехват показывает ровно
один раунд запросов на этот When)
**And** по завершении показан диалог «Sync complete», перечисляющий через
запятую фактические числа («N works updated», «N filters updated» и т.п.,
соответствующие реально применённым A/B/C)
**And** подпись «Last synced …» обновляется на текущее время

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Локальное изменение | работа A, неопубликованное |
| Входящие изменения | работа B (новее), фильтр-профиль C (новее) |
| Диалог | «Sync complete» + перечисление N works/filters updated |

## Заметки для автоматизации
- Sync-фикстура отсутствует — тот же класс, что кейсы области 1
  (TC-207..217), информация для test-automator, не блокер.
- Повторный тап во время прогона — таймингово чувствительный шаг; на
  реальном устройстве прогон к GitLab достаточно долгий (сетевой round-trip),
  что даёт окно для повторного тапа без искусственных задержек.
