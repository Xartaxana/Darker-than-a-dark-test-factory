# TC-161 — checkPageDensity не срабатывает при infinite_scroll OFF: пользователь остаётся на пустой странице

## Предусловия
- Приложение запущено с чистыми данными; тумблер «Infinite scroll (listing
  pages)» — OFF (установлен явно в Settings ДО навигации); `hide_disliked =
  ON`, `filter_display_mode = hide` (дефолты).
- В Room засеяна работа страницы 1 листинга с рейтингом DISLIKE —
  единственная работа страницы.
- Режим replay.

## Сценарий (Given-When-Then)

**Given** работа страницы 1 листинга помечена DISLIKE (единственная работа
страницы), `hide_disliked = ON`, `infinite_scroll = OFF` (установлен до
навигации)

**When** пользователь открывает страницу 1 листинга и ждёт (бюджет,
сравнимый с TC-159, где при ON автопрыжок наблюдается за ~2с)

**Then** автонавигации НЕТ — `location.href`/query остаются страницей 1 весь
период ожидания
**And** страница показывает ноль видимых work-блёрбов и баннер «Some works
may be hidden by your visibility settings»
**And** нумерованная пагинация видима (штатное поведение OFF, как TC-129)

**Инвариант:** ранний `return` при `infinite_scroll === false`
(`ao3_bridge.js:619`) действует одинаково для ОБОИХ путей вызова
`checkPageDensity` — при загрузке страницы И при live-push фильтрации
(`applyAllFilters:123`); при OFF механизм плотности полностью неактивен
независимо от того, что вызвало проверку — негативная сторона симметрична
позитивным TC-159/TC-160.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| `infinite_scroll` | OFF |
| Работа страницы 1 | единственная, `rating=DISLIKE` |
| Видимых work-блёрбов | 0 |
| Автонавигация | нет — `pathname` держится ВЕСЬ бюджет ожидания |

## Заметки для автоматизации
- Негативный Then держится ВЕСЬ бюджет ожидания (`assert_holds_for`, не
  одноразовое чтение сразу после загрузки) — тот же класс наблюдаемости
  негатива, что TC-129 (`assert_work_blurb_count_holds`): пустой результат
  «автонавигации нет» валиден только если реально дан шанс сработать
  (полноценный бюджет ожидания, сравнимый с измеренным ~2с TC-159, с
  запасом).
- Баннер «Some works may be hidden…» — существующий локатор/степ (CH-006
  протокол называет его как контроль, не находку; здесь — часть Then,
  подтверждающая, что фильтр СРАБОТАЛ, но навигация — нет, т.е. негатив не
  вакуумный: фильтрация состоялась, checkPageDensity — единственное, что
  не сработало).
- Не заблокировано инфраструктурой: `listing_paginated.mitm` уже собран.
- Дельта к TC-129 (та проверяет негатив ПОДГРУЗКИ по скроллу при OFF) — этот
  кейс проверяет негатив АВТОНАВИГАЦИИ по плотности при OFF, другой
  механизм (`checkPageDensity` vs `fetchAndAppend`), общий только гейт
  тумблера.
- **Батарея правил-реакций (оценка применимости):** off-инвариант — САМ
  этот кейс. Остальные пункты — н-п, те же причины, что TC-159 (ретроактивность
  не применима к per-загрузочной проверке; идемпотентность/propagation — нет
  повторов/разделяемого состояния в рамках этого кейса).
