# BUG-060 — Фоновая вкладка на удалённый локальный файл теряет опознаваемость после релонча

## Окружение
- Версия приложения: 1.11 (versionCode 12)
- Режим: replay (`listing_basic.mitm`)
- Тема: не указана (по умолчанию)

## Шаги воспроизведения (Given-When-Then)

**Given**
1. Приложение запущено
2. На вкладке Library (Files) открыта работа со скачанным локальным файлом в фоновой вкладке через «Open in background tab»
   - URL вкладки: `file://…/<ao3id>.html`
   - Вкладка работает, показывает содержимое

**When**
1. Закрыть приложение
2. Удалить скачанный файл через логику приложения (лонг-тап по карточке работы → «Delete downloaded file»)
3. Перезапустить приложение

**Then (ожидалось)**
Вкладка должна либо закрыться, либо показать graceful ошибку с возможностью восстановления, либо пересоздать вкладку на другой ресурс (напр. web-версию работы).

**Actual (фактически)**
1. Вкладка восстанавливается при релонче (по persisted `open_tabs_urls`)
2. При переключении на неё WebView показывает: «Couldn't load this page» + net::ERR_FILE_NOT_FOUND
3. Кнопка Retry присутствует, но не работает (файл удалён, повторная загрузка невозможна)
4. Чип вкладки на TabStrip деградирует до «about:blank» — пользователь не может понять, какая работа в вкладке
5. Вкладку остаётся только закрыть вслепую (без информации о том, что в ней было)

До релонча WebView показывает корректный рендер и заголовок работы в чипе вкладки.

## Анализ
Персистентность вкладок (`BrowserViewModel.kt:286`, `saveTabsToPrefs`) сохраняет `file://`-URL в `open_tabs_urls` без проверки наличия файла. При релонче вкладка восстанавливается по сохранённому URL, но файл больше не существует.

Проблема усугубляется отсутствием fallback-механизма: после показа ошибки нет возможности вернуться на web-версию работы или скачать файл заново. Кроме того, деградация чипа до «about:blank» делает пользовательский опыт особенно плохим — работа становится неопознаваемой.

**Сопутствующая информация:** ни один существующий кейс не покрывает persist `file://`-вкладок:
- TC-025 проверяет persist HTTP-вкладок
- TC-035 удаляет файл, но никогда не открывает его в фоновой вкладке
