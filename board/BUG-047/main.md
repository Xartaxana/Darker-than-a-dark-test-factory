# BUG-047 — Удалённый файл воскрешает работу вторым дублем

## Окружение
- Версия: 1.10 (versionCode 11), commit 63f6aac
- Эмулятор: emulator-5554, API 34
- Режим: replay (listing_basic.mitm)
- Тема: светлая
- Папка загрузок: дефолтная (`getExternalFilesDir("ao3_downloads")`)

## Шаги воспроизведения (Given-When-Then)

**Given**
- Работа скачана дважды (два файла на диск, один ao3Id в Room):
  - `ao3_ЛОКАЛЬНЫЙ заголовок_900000001.html` (старый, сирота)
  - `ao3_A Loved Test Work_900000001.html` (новый, в downloadPath)
- Room: `downloadPath = /storage/…/ao3_A Loved Test Work_900000001.html`
- Карточка Library показывает «Open downloaded»

**When**
- Тап на карточке Library → открыть меню удаления
- Выбрать «Delete downloaded file» (путь TC-035)
- Система удаляет **ровно файл из `downloadPath`**: `ao3_A Loved Test Work_900000001.html`
- На диске остаётся: `ao3_ЛОКАЛЬНЫЙ заголовок_900000001.html`
- Room обновляется: `downloadPath = null`
- Settings → «Scan for downloads»

**Then (ожидалось)**
- Диалог скана: `Found 0 files — relinked 0, added 0 new.` или `Found 1 files — relinked 1, added 0 new.` **без переписи downloadPath**
- Карточка показывает «Download» (работа больше не скачана)
- Файл на диске — сирота (если вообще остался) — НЕ связывается с работой в Room

**Actual (фактически)**
- Диалог скана: `Found 1 files — relinked 1, added 0 new.`
- **`downloadPath` переписывается на старый файл:** `downloadPath = /storage/…/ao3_ЛОКАЛЬНЫЙ заголовок_900000001.html`
- Карточка **снова показывает «Open downloaded»** (работа "воскресла" как скачанная)
- Пользовательский эффект: явно удалённый файл ожил, пользователь считает его удалённым, но файл на диске связан обратно

## Анализ корневой причины

### Место в коде (DownloadRepository.kt, LibraryViewModel.kt)

#### Дверь удаления файла (`:138-150`, метод `deleteDownload`)

```kotlin
fun deleteDownload(aoId: Long) {
    val rating = ratingRepo.getWorkByAoId(aoId)  // Получить запись
    if (rating != null) {
        val path = rating.downloadPath
        if (path != null) {
            // Удалить ровно ЭТ OT файл с диска
            File(path).delete()
        }
        // Если есть другие поля (comment, tags, downloadPath) — строка выживает
        ratingRepo.updateDownloadPath(aoId, null)  // Обнулить только downloadPath
    }
}
```

**Проблема 1:** Метод удаляет ровно **один файл** (указанный в `downloadPath`), но если на диске есть **другие файлы того же ao3Id**, они остаются.

#### Цикл скана (`:108-130`, уже описан в BUG-046)

При повторном сканировании цикл ищет файлы по хвосту `_<ao3Id>.html` и **без разбора** переписывает `downloadPath` на любой найденный файл.

**Проблема 2:** Скан не знает о **явном удалении** пользователем. Если на диске остался старый файл (случайность или результат BUG-046), скан свяжет его с работой.

### Класс дефекта

**Асимметрия между пользовательским намерением и дизайном хранилища:**
- Пользователь (в UI): удаляет **один файл**, ожидая результат «работа больше не скачана»
- Приложение (в коде): удаляет ровно **файл, указанный в `downloadPath`**, но других дубликатов не трогает
- Скан (в коде): на диске **N файлов** → один ao3Id → **перезаписывает `downloadPath`** на последний в `listFiles()`

**Второй уровень:** Если пользователь явно удалил файл из UI и затем запустил скан, скан **переписывает** состояние, игнорируя пользовательское намерение.

### Почему это баг приложения, а не теста

1. **Воспроизведено в чистом состоянии:** clean_state → скачивание → правка заметки (BUG-021) → повторное скачивание → удаление → скан
2. **Состояние на диске сверено:** `adb shell ls` показал остаток файла дважды независимо
3. **Поведение на диске:** файл физически не удален (остаток зафиксирован)
4. **Ожидаемое поведение по UX:** удаление из UI должно означать отсутствие работы на диске (в том числе дубликатов)
5. **Ожидаемое поведение по коду:** `deleteDownload` должен удалить ВСЕ файлы того же ao3Id, или скан должен защитить от переписи `downloadPath` при явном удалении
