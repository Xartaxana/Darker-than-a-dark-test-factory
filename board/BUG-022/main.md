# BUG-022 — Панель рейтинга work-страницы при dispose переписывает рейтинг, воскрешая удалённую запись

## Окружение
- Версия: 1.10 (versionCode 11), commit 63f6aac3
- Эмулятор: emulator-5554, API 34
- Режим: replay (works_multi.mitm)
- Тема: светлая

## Шаги воспроизведения (Given-When-Then)

**Given**
- Страница работы открыта на вкладке Browse (ao3_id 900000001)
- Работа имеет рейтинг в базе: `rating=SAVE`, `timestamp=1785710320972`
- Нижняя навигация закрыта (navExpanded=false)

**When**
- Раскрыта нижняя навигация на work-странице
- WorkRatingPanel композится и показывает текущий рейтинг SAVE
- Переход в Settings → Clear all ratings → запись удаляется из базы
- Возврат на Browse (выбор вкладки Browse, navExpanded=false)
- WorkRatingPanel dispose срабатывает при переходе

**Then (ожидалось)**
- Рейтинг остаётся очищенным (0 строк в work_ratings для ao3Id 900000001)
- Повторное посещение Browse показывает отсутствие рейтинга
- Пользовательский эффект: Clear all ratings необратимо удаляет оценку

**Actual (фактически)**
- При dispose WorkRatingPanel срабатывает dispose-save (guard `if (savedWorkId != null && r != null)` истинен — панель держит стухший SAVE)
- savePanelRating (BrowserViewModel.kt:742-758) выполняет upsert со стухшим значением (rating=SAVE, timestamp до Clear)
- Запись воссоздаётся в базе: `rating=SAVE`, `timestamp=1785710358931` (НОВЫЙ timestamp, но СТАРОЕ значение рейтинга)
- Результат: явно удалённые данные появляются снова — пользовательский эффект «Clear all ratings» частичен (данные ожили)

## Частота
**Всегда, 100%:** Различающий замер test-maintainer 2026-08-02 на replay-фикстуре воспроизвёл регулярно; механизм детерминирован кодом панели.

## Артефакты

### Witness-данные (различающий замер test-maintainer 2026-08-02)
- Фикстура: `works_multi.mitm`
- Чекпоинты SELECT ao3Id|rating|timestamp:
  - **до Clear all:** `900000001|SAVE|1785710320972` ✓
  - **сразу после Clear all:** 0 строк ✓
  - **сразу на возврате в Browse:** `900000001|SAVE|1785710358931` ✗ (НОВЫЙ timestamp = новая запись, не пережившая старая; рейтинг=SAVE)

### Инженерный след

## Анализ корневой причины

### Место в коде (BottomBar.kt, BrowserViewModel.kt)

Панель WorkRatingPanel композится при ЛЮБОМ раскрытии нижней навигации, даже при простом возврате с Browse:

- **BottomBar.kt:99-105** — условие рендера панели: `AnimatedVisibility(visible = selectedTab != BROWSE || navExpanded)` + `if (selectedTab == BROWSE && isWorkPage)`
- **BottomBar.kt:159-167** — dispose-save с guard `if (savedWorkId != null && r != null)`
- **BottomBar.kt:153-157** — комментарий кода обосновывает dispose-save тем, что панель никогда не держит несохранённый рейтинг (пересказ комментария, не цитата); текущее поведение нарушает это намерение, когда свежее значение = «рейтинга нет» (оценка критик-входа, не код)
- **BrowserViewModel.kt:742-758** — savePanelRating, ветка existing != null: немедленный upsert (без проверки актуальности)
- **BrowserViewModel.kt:1027-1044** — onRateWorkRequested, ветка existing == null: отложенный upsert через scrape-JS (также безусловный)

### Суть дефекта

Оба пути записи (`savePanelRating` и `onRateWorkRequested`) **безусловны и не проверяют актуальность** значения `latestRating`. Любое внешнее изменение work_ratings между последним чтением состояния панелью и её dispose **молча откатывается**:

- Clear all ratings → удаление записи
- Удаление из Library
- Смена рейтинга из другой вкладки

**Триггер шире намеренного использования панели:** транзиентный mount+dispose происходит не только на сохранении рейтинга, но и на самом ВОЗВРАТЕ на Browse:
- **MainActivity.kt:426-429** — onSelect ставит selectedTab и navExpanded=false одним апдейтом
- Результат: dispose срабатывает на самом переходе, передавая стухшее значение в запись

### Класс дефекта

**Потеря явно удалённых пользователем данных:** Clear all ratings — явное действие пользователя. Панель, не знающая об этом действии (оно произошло через Settings, вне панели), воскрешает запись при dispose. Пользовательский эффект: удаление не "прилипло".

### Исключения конкурирующего писателя

- onWorkFinished (auto-READ, ao3_bridge.js:1114-1147) исключён эмпирически в witness: rating всегда SAVE, не READ
- **Оговорка:** структурное исключение (нет div#chapters на replay-фикстуре) — свойство replay, на живой AO3 второй писатель существует, но пишет READ
