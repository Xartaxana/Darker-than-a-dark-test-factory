# TC-208 — LWW-слияние: граница равенства timestamp

## Предусловия
- Синхронизация настроена. Работа X засеяна локально: `rating=LIKE`,
  `timestamp=T`.
- Удалённый снимок содержит строку X: `rating=DISLIKE`, `timestamp=T` —
  РОВНО тот же timestamp, что и локальная строка.

## Сценарий (Given-When-Then)

**Given** локальная и удалённая версии работы X имеют РАВНЫЙ `timestamp`, но
разный `rating`

**When** пользователь запускает «Sync now»

**Then** локальная строка X остаётся `rating=LIKE` — удалённая версия
ОТБРОШЕНА (код: `remoteTs <= localTs` → `continue`), карточка/вкладка не
меняются

Инвариант: критерий победителя — СТРОГОЕ `remoteTs > localTs`; при равенстве
(включая случай «оба устройства увидели одно и то же T без новых правок»)
побеждает локальная сторона, что исключает бесконечный пинг-понг замещений
между устройствами при отсутствии реальных новых изменений.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Локально | rating=LIKE, timestamp=T |
| Удалённо | rating=DISLIKE, timestamp=T (равно локальному) |

## Заметки для автоматизации
- Sync-фикстура (мок снимка с ТОЧНО равным timestamp) отсутствует —
  информация для test-automator (не блокер), требует контроля над
  генерацией timestamp мока синхронно с сидингом (тот же timestamp, что
  выставит `seed()`).
- Граничный кейс к TC-207 (там `T2>T1`, здесь `T2==T1`) — не дублирует его:
  разное Given (равенство vs строгое неравенство), разный Then (замена vs
  отбрасывание).
