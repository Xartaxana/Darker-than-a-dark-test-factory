# BUG-061 — CI молчаливо деградирует дизайн подписи: throwaway-keystore вместо общего debug-ключа

## Окружение
- CI-пайплайн: gitlab.com/dyakagreen-group/ao3-wrapper
- Триггер: отсутствие переменной `KEYSTORE_BASE64` в Settings → CI/CD → Variables проекта
- Версия инструментов: AGP 9.1.1, Gradle 9.3.1, Java 21 (eclipse-temurin:21-jdk)

## Шаги воспроизведения (Given-When-Then)

**Given**
1. Проект gitlab.com/dyakagreen-group/ao3-wrapper с коммитом b00a88a (добавление поддержки `KEYSTORE_BASE64`)
2. Переменная окружения `KEYSTORE_BASE64` НЕ задана в Settings → CI/CD → Variables
3. Приложение (versionCode 12) уже установлено на устройство/эмулятор

**When**
1. Запущен CI-джоб `build:debug` или `build:release`
2. Джоб проходит этап `before_script` (строки 49–74 в `.gitlab-ci.yml`)
3. Сборка завершается успешно, APK выкладывается

**Then (ожидалось)**
- Сборки CI подписаны ОДИНАКОВЫМ общим debug-ключом (как задумал коммит b00a88a)
- ИЛИ отсутствие переменной приводит к явному отказу джоба с читаемой ошибкой (например, EXIT 1)

**Actual (фактически)**
1. Джоб проходит с WARNING: `"WARNING: KEYSTORE_BASE64 is not set - this APK will NOT install over an existing one."`
2. Gradle/AGP молчаливо генерирует НОВЫЙ throwaway-keystore для ЭТОго джоба (не переиспользует старый)
3. Каждый последующий джоб генерирует свой throwaway-keystore
4. При попытке установить APK поверх предыдущей сборки:
   - Android отказывает: `INSTALL_FAILED_UPDATE_INCOMPATIBLE` (ключи подписи не совпадают)
   - Требуется `uninstall` + `install` с потерей приложения и его данных (ненужная friction для QA и разработчиков)

## Частота
Всегда (воспроизведено в живом смоке dual-mode 2026-08-10 при переходах между local и CI-сборками; каждый CI-джоб → новая подпись).

## Артефакты
- **`.gitlab-ci.yml` строки 64–70** (точное место молчаливого фолбэка):
  ```yaml
  - |
    if [ -n "$KEYSTORE_BASE64" ]; then
      echo "$KEYSTORE_BASE64" | base64 -d > "$CI_PROJECT_DIR/debug.keystore"
      export KEYSTORE="$CI_PROJECT_DIR/debug.keystore"
    else
      echo "WARNING: KEYSTORE_BASE64 is not set - this APK will NOT install over an existing one."
    fi
  ```
- **Коммит b00a88a** (разработчиков): задумал общий debug-ключ из переменной KEYSTORE_BASE64, но переменная не задана в проекте
- **`build.gradle.kts`** (точка фолбэка Gradle): при отсутствии `KEYSTORE` в окружении AGP использует встроенный (одноразовый) throwaway-keystore без громкого уведомления
- **Живой смок 2026-08-10** (scripts/tasks.ps1, функция `Install-App`): установка CI-билда поверх local-билда → `INSTALL_FAILED_UPDATE_INCOMPATIBLE` → автоматический uninstall+install

## Анализ
**Ядро дефекта:** молчаливая деградация задуманного дизайна (b00a88a). Разработчики внедрили механизм общего debug-ключа (read from `KEYSTORE_BASE64`), но сама переменная НИКОГДА не была задана в CI Settings. Результат:

1. **Контрактная нарушение:** WARNING-сообщение (`"…this APK will NOT install over an existing one"`) ЯВНО предупреждает о проблеме, но оно же — ЕДИНСТВЕННЫЙ симптом. Сборка продолжает проходить молча, хотя должна либо:
   - Завершиться с ошибкой (exit 1) — явно сигнализировать о незаполненной переменной, либо
   - Автоматически использовать переменную (если она где-то задана выше по стеку), либо
   - Явно документировать «это плановое поведение для локальных dev-сборок».

2. **Класс апгрейд-тестирования заблокирован:** тесты, которые проверяют миграцию данных между версиями (N → N+1), требуют установки поверх. С разными подписями это невозможно — требуется `uninstall` после каждой новой версии, что сбрасывает app state и делает test fixture для миграции бесполезным.

3. **Трение для потребителей CI-билдов:** разработчики, пытающиеся установить свой последний CI-билд поверх предыдущего, получают `INSTALL_FAILED_UPDATE_INCOMPATIBLE` без информации о корне проблемы (разные ключи).

**Проблема усугубляется:** комментарий в `.gitlab-ci.yml` строки 60–63 ЯВНО объясняет, ЗА ЧЕМ нужен общий ключ («Sign with the same debug key as local builds»), но метод `export KEYSTORE` не имеет эффекта без заполненной переменной KEYSTORE_BASE64.

## Обсуждение

**[qa @ 2026-08-10T17:05:00Z]** Дефект в CI-пайплайне приложения (решение владельца QA от 2026-08-10).

**Вопрос разработчикам (выбери одну из опций):**

1. **Опция A — Задайте переменную:**
   - Заполните `KEYSTORE_BASE64` в Settings → CI/CD → Variables проекта (QA может передать base64-encoded standard debug-keystore по запросу в комментарии этой карточки — пришлём хэш для проверки).
   - После заполнения все CI-джобы будут использовать один общий ключ, установка поверх будет работать.

2. **Опция B — Измените фолбэк:**
   - Вместо WARNING-строки (которая выглядит как информационное сообщение, но не останавливает сборку) внедрите **явный отказ джоба**: `exit 1` или `error: KEYSTORE_BASE64 not set, cannot build`.
   - Это предотвратит создание невалидных APK и явно потребует заполнить переменную.
   - Убедитесь, что ошибка попадает в логи CI и видна как FAILED в interface GitLab.

3. **Опция C — Задуманное поведение** (если текущее молчаливое изображение throwaway-keystore на каждый джоб НАМЕРЕННО):
   - Обновите комментарии в `.gitlab-ci.yml` и документацию: «Каждый CI-джоб подписан уникальным ключом; установка поверх требует uninstall».
   - Мы введём эту ограничение в регрессионный замок (TC-191+).

**Влияние на QA:**
- **Блокирует класс апгрейд-тестирования** (любые TC, проверяющие миграцию данных: install v1 → install v2; любые TC, требующие переустановки поверх исходной версии).
- **Создаёт трение**: после каждого нового CI-билда требуется `uninstall` перед `install`, что сбрасывает данные приложения.
