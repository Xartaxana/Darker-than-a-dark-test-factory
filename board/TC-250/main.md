# Переключение E-ink mode перезагружает КАЖДУЮ открытую вкладку Browse, теряя позицию скролла и окно пагинации листинга

# TC-250 — Смена E-ink mode перезагружает живые вкладки

## Предусловия
- Открыты ДВЕ вкладки Browse: вкладка A — work-страница, прокрученная
  глубоко вниз (не у начала); вкладка B — листинг, пролистанный на 3-ю
  страницу пагинации (не первую).

## Сценарий (Given-When-Then)

**Given** вкладка A прокручена глубоко на work-странице, вкладка B открыта
на 3-й странице листинга

**When** пользователь переключается на Settings и меняет тумблер E-ink mode
(в любую сторону — палитра bridge читается заново при инициализации КАЖДОЙ
вкладки)

**Then** возвращаясь в Browse, пользователь видит: вкладка A перезагружена
(`reload()`) — позиция скролла ПОТЕРЯНА (страница открывается заново сверху,
не с прежнего места)
**And** вкладка B тоже перезагружена — окно пагинации листинга ПОТЕРЯНО
(возврат к странице 1, не к ранее открытой 3-й)

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Вкладка A | work-страница, глубокий скролл до toggle |
| Вкладка B | листинг, страница 3 пагинации до toggle |
| Действие | переключение E-ink mode один раз |
| Ожидаемый результат | обе вкладки перезагружены, состояние скролла/пагинации потеряно |

## Заметки для автоматизации
- Это НАБЛЮДАЕМОЕ ТЕКУЩЕЕ поведение (не баг, не заводится этим design'ом
  — вопрос владельцу уже вынесен test-strategist в §10 щ), именно оно
  держит риск R-11 в high по оценке стратега; кейс — регрессионный замок
  на текущую границу, а не одобрение UX.
- Блокера нет — открытие двух вкладок и измерение scroll/пагинации уже
  используется существующими tabs-кейсами.
