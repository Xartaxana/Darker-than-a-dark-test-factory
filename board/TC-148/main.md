# Интерактивные цели нативного хрома (панели, тумблеры, чипы TabStrip, кнопки диалогов) не меньше 48dp по bounds accessibility-дерева

# TC-148 — Свип touch-target: нативные интерактивные цели не меньше 48dp

## Предусловия
- Приложение запущено с чистыми данными, работа W засеяна с рейтингом (тот
  же seed, что TC-009/TC-106), открыто >=2 вкладки (для видимого `TabStrip`).
- Плотность экрана устройства ИЗМЕРЕНА непосредственно перед свипом
  (`adb shell wm density`), не взята из памяти/документации — порог 48dp
  переводится в device px через РЕАЛЬНУЮ плотность текущего прогона.
- Маршрут свипа — поимённый и воспроизводимый (тот же порядок, что TC-107):
  **Library -> Browse (work page) -> Settings**, плюс `TabStrip` (виден на
  Browse).
- Все состояния — СТАТИЧЕСКИЕ/стабильные (см. границу «non-goal» ниже);
  side panel рассматривается в ДВУХ статических состояниях — свёрнут
  (handle) и раскрыт (persistent toggle, не транзитный оверлей).

## Сценарий (Given-When-Then)

**Given** плотность экрана измерена (`wm density`), маршрут Library ->
Browse (work page, side panel свёрнут) -> Browse (side panel раскрыт) ->
Settings пройден один раз, `TabStrip` виден с >=2 вкладками

**When** accessibility-дерево читается напрямую через UiAutomator2 на
каждой точке маршрута (без взаимодействия с элементами, только инспекция
`bounds`) для поимённого списка целей нативного хрома:
- Library: чипы табов (Loved/Liked/Read/Disliked/Downloads)
- Browse, side panel свёрнут: handle «Expand panel»
- Browse, side panel раскрыт: переключатель темы (Contrast-иконка), кнопки
  размера шрифта «A-»/«A+»
- Browse: нижняя 20dp полоса-хэндл нижней панели (`BottomBar.kt:56`)
- `TabStrip`: кнопка «New tab», кнопка(и) «Close tab», сам таб-чип
- Settings: кнопки `ThemeModeRow` (Light/Dark/System), `PanelSideRow`
  (Left/Right), `FontSizeRow` (7 кнопок степов)

**Then** для КАЖДОЙ цели поимённого списка `bounds.width >= 48dp` И
`bounds.height >= 48dp`, где `48dp` переведено в device px по РЕАЛЬНО
измеренной плотности текущего прогона (`48 * density/160`, НЕ хардкод
константы из документации)

**Инвариант:** свойство «минимальный размер цели >= 48dp» проверяется КАК
СВОЙСТВО, верное одновременно для ВСЕГО поимённого списка целей маршрута, а
не как единичный пример одной кнопки; находка ниже порога по ЛЮБОЙ цели из
списка — красный результат этого прогона, не повод сужать список выборочно.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Порог | 48dp (Android accessibility guideline), НЕ WCAG |
| Плотность | измеряется `adb shell wm density` на каждом прогоне |
| Уже измеренные кандидаты (docs/01 §9, эталонный AVD) | «Expand panel» 32×32 px (~12dp при dpr 2.625, ниже порога вчетверо); 20dp полоса-хэндл нижней панели |
| Маршрут | Library -> Browse (work page, свёрнут/раскрыт) -> Settings + `TabStrip` |

## Заметки для автоматизации
- Примитив инспекции — тот же, что TC-106/TC-108 (`page_source`/
  `find_elements` по `AppiumBy.ANDROID_UIAUTOMATOR` или XPath, чтение
  `bounds` без взаимодействия) — новой инфраструктуры не требуется.
- **Новый примитив (не блокер, рутинная работа test-automator):** чтение
  плотности экрана — `adb.shell("wm density")` (парсинг `Physical density:
  NNN`), обёртка в `core/adb.py` по образцу существующих `shell()`-вызовов.
  Это НЕ отсутствующая фикстура/сидинг и НЕ неавтоматизируемый штатно
  системный UI (голая adb-команда + парсинг вывода) — по конвенции
  test_debt (`debt_kind: missing_fixture`/`missing_evidence` и т.п.) это не
  подпадает под критерий блокера; test_debt-баг не заводится.
- **Ожидаемый результат по умолчанию — вероятно КРАСНЫЙ на части целей.**
  docs/01 §9 уже называет два измеренных кандидата ниже порога («Expand
  panel» ~12dp, 20dp хэндл). Кейс написан от ОЖИДАЕМОГО (порогового)
  поведения — красный результат прогона триажится штатно (test-reporter/
  bug-reporter по вердикту триажа), сам свип багов не заводит.
- **Non-goal явно (первая итерация, docs/01 §9 требует явного выбора, не
  молчания):** динамические/транзитные состояния НЕ входят в этот прогон —
  раскрытая НИЖНЯЯ панель (модальный nav-drawer со скримом,
  `MainActivity.kt:490-501`, отличная от side panel), fullscreen-режим,
  открытые диалоги/оверлеи (в т.ч. `RatingOverlay`), живые снекбары.
  Раскрытый SIDE PANEL (theme/font controls) в список ВКЛЮЧЁН — это
  персистентный toggle-стейт (не транзитный оверлей), детерминированно
  достижим одним тапом по handle, тот же класс воспроизводимости, что
  свёрнутое состояние.
- Ловушка локатора (CH-001/CH-005/TC-059): раскрытие side panel — тап по
  content-desc «Expand panel», не по координате центра bounds handle
  (координата проваливается в WebView).
- Инвентарь снятых `contentDescription` — см. requirements выше; там, где
  Compose мёрджит семантику с соседним `Text` (как в TC-106), `bounds`
  берутся с ВНЕШНЕГО кликабельного узла (родителя), не с текстового
  потомка — иначе размер занижен искусственно.
