# TC-180 — Rating, выбранный на Files, не теряется при уходе на другую вкладку — виден Last read, но оживает на Files

## Предусловия
- Приложение запущено, вкладка Files прокручиваема
  (`seed_db.seed_with_download`, работы с разными рейтингами, тот же сид, что
  TC-065 — распределение SAVE/LIKE/READ/PENDING/DISLIKE по одному на работу,
  засеяно в порядке, обратном ожидаемому Rating-упорядочиванию).
- Вкладка Favorite засеяна (любой непустой список, прокручиваемость не
  обязательна для этого кейса).

## Сценарий (Given-When-Then)

**Given** активна вкладка Files, выбрана сортировка Rating
(`select_library_sort(driver, "Rating")`), список упорядочен по рангу
рейтинга (LOVED→KUDOSED→READ→PENDING→DISLIKED, тот же порядок, что TC-065)

**When** пользователь переключается на вкладку Favorite (Rating недопустима
вне Files)

**Then** список Favorite отображается в порядке Last read (fallback), И
content-desc иконки-триггера топ-бара показывает «Sort library: Last read»
(`assert_sort_trigger_label`/сверка content-desc) — оба индикатора
согласованно откатились к Last read, а НЕ показывают Rating и не падают с
ошибкой

**When** пользователь возвращается на вкладку Files

**Then** список Files снова упорядочен по Rating (LOVED→KUDOSED→READ→PENDING→
DISLIKED) — выбор НЕ был потерян уходом на другую вкладку, он был только
визуально замещён на время, пока Rating была недопустима

**Инвариант:** выбор сортировки, недопустимый для активной в данный момент
вкладки, НИКОГДА не удаляется из хранимого состояния (`sortBy`) — он
замещается Last read ТОЛЬКО в отображении (список + content-desc иконки)
на вкладках, где недопустим, независимо от того, сколько раз пользователь
переключался между вкладками между выбором и возвратом на Files.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Files | сортировка Rating выбрана, порядок LOVED/KUDOSED/READ/PENDING/DISLIKED |
| Favorite (после перехода) | отображается Last read, content-desc «Sort library: Last read» |
| Files (после возврата) | снова Rating, тот же порядок |

  область получает общую).

  Favorite (готов, `library_steps.py:264-268`) — читает Text-подпись; для
  content-desc топ-бара («Sort library: <label>») нужен ОТДЕЛЬНЫЙ примитив
  (текущий `assert_sort_trigger_label` читает видимый Text триггера сортировки
  Library, а не content-desc иконки MainActivity топ-бара, `:372-373`) —
  рутинное добавление по образцу уже читаемых content-desc в проекте
  (`by_desc`), не блокер: локатор для content-desc «Sort library: …» ранее
  не требовался ни одним кейсом (TC-065 проверяет отсутствие ОПЦИИ в
  выпадающем списке, не подпись триггера MainActivity).
- `assert_cards_in_order`/`assert_sorted_by...`-эквивалент для порядка на
  Files после возврата — тот же приём, что TC-065

- Отличается от TC-065 (содержимое ВЫПАДАЮЩЕГО СПИСКА — опции Rating не видно
  вне Files) — этот кейс проверяет судьбу УЖЕ СДЕЛАННОГО выбора, не список
  опций.
- Блокера автоматизации нет — один рутинный локатор content-desc.
