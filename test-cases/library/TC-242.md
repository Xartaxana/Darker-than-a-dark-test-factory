# TC-242 — Kudos из Library: уходит ТОГДА И ТОЛЬКО ТОГДА, когда вкладка с работой открыта (R-17)

**Поглощает:** TC-243 (П1 spec-p1-dedup v7, docs/tasks/p1-dedup-lead-pass.md Р2:
«kudos уходит тогда и только тогда, когда открыта вкладка с работой. Одно
действие, одно условие, зеркальные ожидания; негатив — несущая проверка и
обязан сохраниться в поглощающем кейсе»).

## Предусловия
- **Позитивная проба kudos (вариант A) — ТОЛЬКО replay** (§5 R-17,
  подтверждено владельцем 2026-08-11) — эмулированная work-страница с кнопкой
  kudos (`#kudo_submit`) в mitm-записи; вариант B (негатив) — replay не
  обязателен (позитивная work-страница не нужна вовсе, раз вкладок нет), но
  устройство под mitm-прокси в режиме наблюдения — обязательно в ОБОИХ
  вариантах (иначе негатив непроверяем).
- Работа W засеяна БЕЗ рейтинга (или с рейтингом, не входящим в
  {LIKE, SAVE}) в обоих вариантах.

## Сценарий (Given-When-Then)

### Вариант A — вкладка с работой открыта → kudos уходит (родной сценарий TC-242)

**Given** работа W не в статусе Kudosed/Favorite, вкладка с её AO3-страницей
уже открыта в фоне (через replay) — пользователь затем переключается на
Library, не закрывая вкладку

**When** пользователь на экране Library оценивает W как «Kudosed» через
«Rate / edit note»

**Then** рейтинг W сохраняется как LIKE
**And** kudos РЕАЛЬНО отправляется на (replay-имитируемый) AO3 — bridge
кликает `#kudo_submit` на фоновой вкладке (перехват mitm подтверждает POST
kudos-транзакции), несмотря на то что пользователь физически не покидал
экран Library

### Вариант B — ни одна вкладка с работой не открыта → kudos НЕ уходит (поглощает TC-243)

**Given** работа W без рейтинга, ни одна открытая вкладка не содержит её
AO3-страницу (вкладок нет вовсе, либо открыты вкладки ДРУГИХ работ)

**When** пользователь на экране Library оценивает W как «Kudosed» через
«Rate / edit note»

**Then** рейтинг W сохраняется как LIKE (сохранение рейтинга произошло —
подтверждает, что When реально случился, различие с вариантом A — не в том,
что действие не сработало)
**And** к AO3 НЕ уходит НИ ОДНОГО kudos-запроса (mitm-перехват показывает 0
POST на `kudo`-эндпоинт за весь сценарий) — контраст с вариантом A: то же
пользовательское действие («Rate / edit note» → Kudosed) даёт
ПРОТИВОПОЛОЖНЫЙ сетевой эффект в зависимости ИСКЛЮЧИТЕЛЬНО от того, открыта
ли вкладка работы

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа W | без рейтинга → LIKE (Kudosed), в обоих вариантах |
| Вариант A: открытые вкладки | work-страница W (replay), в фоне |
| Вариант A: оракул kudos | POST-транзакция на mitm-записи (`#kudo_submit`) — присутствует |
| Вариант B: открытые вкладки | без work-страницы W (пусто или другие работы) |
| Вариант B: ожидаемое число kudos-запросов | 0 |

## Заметки для автоматизации
- Вариант A требует replay-записи work-страницы с kudos-формой —
  переиспользовать существующий приём kudos-проб (см. соседние кейсы
  `rating-entry-*`, если они уже incorporate такую фикстуру; иначе — тот же
  класс, что AT-BUG-071/сеть, информация для test-automator, не блокер
  дизайну, т.к. Given/Then полны).
- Вариант B НЕ требует server-replay work-страницы (позитивная страница не
  нужна вовсе, раз вкладок нет) — только поднятый mitm-прокси в режиме
  наблюдения.
- **Наблюдаемость негативного Then варианта B:** отсутствие kudos-запроса
  проверяется ЧЕРЕЗ mitm-перехват сети за время выполнения When (тот же
  приём, что TC-227/TC-230 в области sync), а не через отсутствие
  UI-подтверждения — если бы гипотетический баг всё же нашёл «чужую»
  открытую вкладку и отправил kudos, тест обязан это увидеть по трафику.
- Это ПРЯМАЯ грань R-17: незапрошенная запись на сторонний сайт достижима
  с экрана, где браузер не виден вовсе (вариант A) — и её отсутствие при
  отсутствии открытой вкладки (вариант B) — это ОДНО условие, доказанное с
  обеих сторон.
- Оба варианта — независимые прогоны ОДНОГО параметризованного теста
  (общее действие «оценить как Kudosed» с разным состоянием открытых
  вкладок) — не journey/чекпойнты, каждый вариант самодостаточен по Given,
  секция «Чекпойнты» не нужна.

      (Kotlin, `tabs.find { ... isWorkPage }` на :795) — решение «отправлять
      kudos или нет» зависит от РЕАЛЬНОГО множества открытых вкладок
      браузера на устройстве, которого в jsdom не существует (jsdom не
      моделирует multi-tab состояние приложения). Вариант A сверх этого
      требует РЕАЛЬНОГО клика по `#kudo_submit` на фоновой WebView-вкладке
      (replay-имитируемая work-страница) с перехватом POST-транзакции через
      mitm — сетевой слой, которого в L2 тоже нет. Вариант B доказывает
      негатив через 0 POST-запросов за весь сценарий на РЕАЛЬНОМ
      mitm-перехвате, а не отсутствием ассерта. Действие «Rate / edit note»
      на экране Library — тоже реальная Compose-иерархия overlay, не
      JS-мост. Ни одно из этих звеньев не сводится к контракту
      `ao3_bridge.js` — L2 физически неприменим, тот же класс обоснования,
      что TC-224/TC-167.
