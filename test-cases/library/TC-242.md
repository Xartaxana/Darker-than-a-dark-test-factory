# TC-242 — Kudos из Library при открытой вкладке работы (R-17 грань)

## Предусловия
- **Позитивная проба kudos — ТОЛЬКО replay** (§5 R-17, подтверждено
  владельцем 2026-08-11) — эмулированная work-страница с кнопкой kudos
  (`#kudo_submit`) в mitm-записи.
- Работа W засеяна БЕЗ рейтинга (или с рейтингом, не входящим в
  {LIKE, SAVE}). Вкладка браузера с work-страницей W УЖЕ открыта (через
  replay) — пользователь затем переключается на Library, не закрывая
  вкладку.

## Сценарий (Given-When-Then)

**Given** работа W не в статусе Kudosed/Favorite, вкладка с её AO3-страницей
уже открыта в фоне

**When** пользователь на экране Library оценивает W как «Kudosed» через
«Rate / edit note»

**Then** рейтинг W сохраняется как LIKE
**And** kudos РЕАЛЬНО отправляется на (replay-имитируемый) AO3 — bridge
кликает `#kudo_submit` на фоновой вкладке (перехват mitm подтверждает POST
kudos-транзакции), несмотря на то что пользователь физически не покидал
экран Library

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа W | без рейтинга → LIKE (Kudosed) |
| Открытые вкладки | work-страница W (replay), в фоне |
| Оракул kudos | POST-транзакция на mitm-записи (`#kudo_submit`) |

## Заметки для автоматизации
- Требует replay-записи work-страницы с kudos-формой — переиспользовать
  существующий приём kudos-проб (см. соседние кейсы `rating-entry-*`,
  если они уже incorporate такую фикстуру; иначе — тот же класс, что
  AT-BUG-071/сеть, информация для test-automator, не блокер дизайну, т.к.
  Given/Then полны).
- Это ПРЯМАЯ грань R-17: незапрошенная запись на сторонний сайт достижима
  с экрана, где браузер не виден вовсе.
