# TC-179 — Сортировка, изменённая вне экрана, сбрасывает скролл целевой вкладки на верх при возврате

## Предусловия
- Приложение запущено, вкладка Favorite прокручиваема (5 `W.ALL` +
  `W.SCROLL_FILLERS`, тот же сид, что TC-030/TC-177).
- Вкладка Files прокручиваема (`seed_db.seed_with_download`, 10-12 работ) —
  нужна как «другая вкладка», на которую переключаются, чтобы Favorite ушла
  вне экрана; сама Files-сортировка в этом кейсе не меняется.

## Сценарий (Given-When-Then)

**Given** активна вкладка Favorite, список прокручен вниз (не на верху),
сортировка Last read (текущая для Favorite)

**When** пользователь переключается на вкладку Files (Favorite уходит вне
экрана и утилизируется пейджером)
**And** НЕ находясь на Favorite, сортировка Favorite меняется на другую
допустимую (напр. Word count, доступна везде) — механизм смены здесь
безразличен: важно, что смена происходит, пока целевая страница НЕ в
композиции
**And** пользователь возвращается на вкладку Favorite

**Then** список Favorite открывается СВЕРХУ (не на прежней прокрученной
позиции и не показывает новый порядок со старым смещением) — `lastSort`
Favorite (Last read) разошёлся с полученным `effectiveSort` (Word count) в
момент, когда страница СНОВА вошла в композицию, `scrollToItem(0)` сработал
именно тогда
**And** список действительно переупорядочен по новой сортировке (Word count),
не по старой

**Инвариант:** сортировка, изменённая вне экрана вкладки, сбрасывает её
скролл на верх ПРИ ВОЗВРАТЕ независимо от того, какая сортировка была
активна раньше и насколько глубоко вкладка была прокручена — сравнение
`lastSort` vs `effectiveSort` в `LaunchedEffect(sort)` срабатывает по факту
несовпадения значений, не по факту «сортировку меняли, пока я смотрел».

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Вкладка под наблюдением | Favorite |
| Сортировка до | Last read, список прокручен вниз |
| Действие вне экрана | смена сортировки на Word count |
| Ожидание при возврате | список наверху, порядок — Word count |

## Заметки для автоматизации
- Смена сортировки, пока Favorite не активна: сортировка Library — общий
  `librarySortBy` в `MainActivity.kt` (не per-tab состояние), поэтому смену
  можно произвести, находясь физически на ЛЮБОЙ вкладке, где нужная опция
  доступна (Word count доступна везде, `librarySortOptionsFor`) — простейший
  путь: переключиться на Files, там же открыть dropdown сортировки и выбрать
  Word count (сортировка Files при этом тоже меняется — это не мешает
  сценарию, т.к. Files-позиция этим кейсом не проверяется), затем
  переключиться на Favorite.
- Оракул — тот же канон TC-030 (`assert_scroll_reset_to_top` + база
  `capture_topmost_card_y`, снятая ДО скролла) + `assert_cards_in_order` для
  проверки нового порядка.
- Отличается от TC-030/TC-063 (там сортировка меняется, пока вкладка
  АКТИВНА — сброс происходит немедленно, тот же визит) и TC-177/178 (там
  сортировка НЕ меняется вовсе — скролл переживает переключение).
- Блокера автоматизации нет — все примитивы существуют.
