# TC-178 — Files-only Rating × переключение вкладок не сбрасывает скролл ни у Files, ни у соседней вкладки

## Предусловия
- Приложение запущено, ОБЕ участвующие вкладки прокручиваемы (обязательное
  предусловие, иначе грань неизмерима):
  - **Files** — `seed_db.seed_with_download` с 10-12 работами
    (`downloadPath != null`, `LibraryViewModel.kt:67`/`:75`);
  - **Favorite** — `seed_db.seed(...)` с 5 эталонными `W.ALL` (рейтинг SAVE) +
    `W.SCROLL_FILLERS`, тот же приём, что TC-030/TC-177.
- На вкладке Files выбрана сортировка **Rating** (`select_library_sort`,
  доступна только на Files) — единственная сортировка, для которой
  `effectiveSort`, передаваемый ВСЕМ страницам пейджера, отличается от
  дефолтной Last read на соседних вкладках.
- Обе вкладки предварительно прокручены вниз, базовые Y-позиции сняты ДО
  скролла (канон TC-030/TC-063: `capture_topmost_card_y` до `scroll_library_down_to`).

## Сценарий (Given-When-Then)

**Given** на Files выбрана сортировка Rating, список Files прокручен вниз
(база снята); на Favorite список тоже прокручен вниз (база снята,
сортировка Favorite — Last read, не менялась)

**When** пользователь переключается Files → Disliked (ближайший сосед) → Files
**And** отдельно (тот же сид, повторный проход) переключается Files → Favorite
(вкладка ДАЛЕКО от Files в пейджере) → Files

**Then** после возврата на Files список стоит на прежней прокрученной позиции
в ОБОИХ проходах — `effectiveSort` (та же Rating) не отличается от
`lastSort` страницы Files, сброса нет
**And** скролл вкладки Favorite (не участвовавшей в смене сортировки) ТОЖЕ не
сброшен после промежуточного визита на Files — несмотря на то, что при
активной странице Files всем страницам пейджера, включая Favorite,
технически передаётся `effectiveSort=Rating`, `lastSort` СОБСТВЕННОЙ
страницы Favorite (Last read) сравнивается только в момент, когда САМА
Favorite активна и получает `effectiveSort` от СВОЕГО контекста
(`tabs[pagerState.currentPage]` в момент композиции Favorite — не Rating,
т.к. Rating недопустим вне Files и туда не передаётся)

**Инвариант:** переключение вкладок Library НЕ сбрасывает скролл ни одной
вкладки (ни текущей, ни целевой, ни ранее посещённой) ни при какой
комбинации допустимых сортировок — свойство ДЕРЖИТСЯ и в критической
комбинации «Files-only сортировка активна + переключение через
непосредственного соседа + переключение через удалённую вкладку», хотя
геометрически `effectiveSort` вычисляется от общего для пейджера состояния
(`LibraryScreen.kt:226-229`, `:252`). Это ИЗМЕРЕННЫЙ факт данной сборки
(CH-009, 8/8 наблюдений в обе стороны), а не логический вывод из кода —
предпосылка «пейджер держит соседние страницы композированными» для этой
сборки НЕВЕРНА (Compose `HorizontalPager` полностью утилизирует off-screen
страницы), и именно эта утилизация, вкупе с `rememberSaveable`-природой
`lastSort`, не даёт `effectiveSort` чужой активной вкладки повлиять на
уже-сохранённую позицию соседних страниц.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Files | 10-12 работ, `downloadPath` заполнен, сортировка Rating |
| Favorite | 5 `W.ALL` + `SCROLL_FILLERS`, сортировка Last read |
| Переход 1 | Files → Disliked (сосед) → Files |
| Переход 2 | Files → Favorite (далёкая) → Files |
| Ожидание | скролл Files и Favorite не сброшен ни в одном переходе |

## Заметки для автоматизации
- Оракул — `assert_scroll_retained` (см. заметки TC-177, тот же новый
  wrapper), применяется дважды: к Files и к Favorite.
- Сидинг Files — `seed_db.seed_with_download`, тот же приём, что TC-065/178
  общий сид с TC-179/180 этой же области (можно переиспользовать одну
  conftest-фикстуру на все четыре кейса области — экономия, не обязательность).
- Порядок оракула — канон TC-030/TC-063 (см. requirements): БАЗА до скролла,
  потом скролл; обратный порядок дал бы ложный негатив на корректном
  поведении.
- **Наблюдаемость:** это ПОЗИТИВНЫЙ Then (сохранение, не сброс) — в отличие от
  негативных сетевых Then (класс AT-BUG-029) наблюдаемость здесь не под
  вопросом: позиция читается напрямую по видимой карточке.
- Не дублирует TC-177 (там — контрольная вкладка БЕЗ активной Files-only
  сортировки, единственный переход, без риска пересечения) и TC-030/TC-063
  (там — Then это САМ сброс при реальной смене сортировки на ТОЙ ЖЕ
  вкладке, не переживание чужой сортировки соседями).
- Блокера автоматизации нет — все примитивы существуют, комбинация лишь
  требует двойного сидинга (Files + Favorite), уже частично описанного в
  Data setup CH-009.
