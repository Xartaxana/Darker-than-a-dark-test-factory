# TC-177 — Скролл вкладки Library переживает переключение на другую вкладку и обратно

## Предусловия
- Приложение запущено, в Room засеяны работы на вкладке Favorite (SAVE) с
  достаточным числом строк для видимого скролла (5 эталонных `W.ALL` +
  `W.SCROLL_FILLERS`, тот же приём, что TC-030) — вкладка Favorite
  прокручиваема.
- Засеяны работы также на вкладке Disliked (LIKE-независимая, любая другая
  вкладка) — достаточно 1-2 строк, не обязана быть прокручиваемой.
- Сортировка Favorite — Last read (дефолт), не менялась.

## Сценарий (Given-When-Then)

**Given** вкладка Favorite активна, список прокручен вниз (не на самом верху),
запомнена верхняя видимая карточка `capture_topmost_card_y`

**When** пользователь переключается на вкладку Disliked (достаточно далеко,
чтобы страница Favorite была утилизирована пейджером) и обратно на Favorite

**Then** список Favorite стоит НА ТОЙ ЖЕ позиции, что и до переключения — та
же карточка первая видимая, тот же Y (в пределах допуска), сортировка
осталась Last read (не менялась, значит, эффект сброса вообще не должен был
сработать)

**Инвариант:** переключение активной вкладки Library само по себе НЕ
сбрасывает скролл ни одной вкладки — единственный триггер сброса
(`LaunchedEffect(sort)` в `LibraryScreen.kt:907-912`) сравнивает ТЕКУЩИЙ
`effectiveSort` с `lastSort`, сохранённым для ЭТОЙ страницы; при неизменной
сортировке сравнение всегда равно, и `scrollToItem(0)` не вызывается —
независимо от того, сколько раз вкладка входила/выходила из композиции.
Это сама фича #28 (`MainActivity.kt` коммит `6f884d97`): раньше (до #28)
`LaunchedEffect(sort)` без сравнения с `lastSort` срабатывал при КАЖДОМ
возврате на вкладку и выбрасывал позицию — TC-030/TC-063 (сброс при РЕАЛЬНОЙ
смене сортировки) продолжают проходить тем же кодом, Then TC-030/063 не
меняется.

## Заметки для автоматизации
- Оракул позиции — канон TC-030/TC-063: `capture_topmost_card_y` (БАЗА, при
  списке на верху) → `scroll_library_down_to` → переключение вкладок →
  повторный `capture_topmost_card_y`/`visible_card_y` той же карточки,
  сравнение с базой (та же карточка, тот же Y в допуске) — это НЕ
  `assert_scroll_reset_to_top` (та проверяет возврат К ВЕРХУ, здесь нужен
  противоположный по смыслу ассерт «осталось где было»): требуется НОВЫЙ,
  но тривиальный по образцу wrapper (`assert_scroll_retained(driver, title,
  baseline_y)` — то же тело, что `assert_scroll_reset_to_top`, только
  сравнение с произвольным `baseline_y`, снятым ПОСЛЕ скролла вниз, а не с
  Y верхней позиции). Рутинное добавление, не блокер.
- Переключение вкладок — `library_steps.open_library_tab_for(driver, rating)`
  (готов).
- «Достаточно далеко, чтобы страница была утилизирована» — переключение на
  ЛЮБУЮ другую вкладку и обратно достаточно (Compose Pager утилизирует
  соседей вне текущего диапазона; прямой переход A→B→A уже покрывает случай
  из CH-009, где утилизация подтверждена измерением).
- Не дублирует TC-030/TC-063 (там Then — сброс при реальной смене сортировки
  внутри одной и той же наблюдаемой вкладки, здесь Then — сохранение при
  переключении вкладок БЕЗ смены сортировки).
- Блокера автоматизации нет.
