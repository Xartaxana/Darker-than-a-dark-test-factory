# TC-234 — Состав публикуемой нагрузки: заявленное, не больше

## Предусловия
- Устройство под mitm-прокси. Локально засеяна работа с рейтингом,
  непустыми `comment`/`tags` и скачанным файлом (заполненный
  `downloadPath`).

## Сценарий (Given-When-Then)

**Given** локальная работа несёт rating/comment/tags/downloadPath (все
поля заполнены)

**When** пользователь запускает «Sync now» (публикующий прогон)

**Then** тело опубликованного JSON содержит для этой работы название,
автора, фандом, рейтинг И дословные `comment`/`tags` пользователя (личные
данные уходят, как и заявлено функцией)
**And** тело JSON НЕ содержит `downloadPath` вовсе (ни поля с этим именем,
ни пути к файлу в любом другом виде) — граница «не больше заявленного»

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа | rating+comment+tags+downloadPath заполнены |
| В теле JSON присутствует | title/author/fandom/rating/comment/tags |
| В теле JSON отсутствует | downloadPath (ключ и значение) |

## Заметки для автоматизации
- Требует того же mitm-перехвата исходящего ТЕЛА запроса, что TC-215
  (область sync) — переиспользовать общий приём/фикстуру, когда она
  появится у test-automator.
- Не дублирует TC-214 (область sync): там оракул — отсутствие
  `downloadPath` на УСТРОЙСТВЕ-ПРИЁМНИКЕ после слияния (Room/Files-вкладка);
  здесь — отсутствие поля в САМОМ СЕТЕВОМ ТЕЛЕ, отправляемом наружу
  (приватность утечки, не корректность слияния).
