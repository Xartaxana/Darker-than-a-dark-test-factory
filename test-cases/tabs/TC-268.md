# TC-268 — регресс-замок BUG-081 (Open): позиция скролла ДОЛЖНА пережить холодный старт без дрейфа (сейчас — красный)

> **Статус замка.** `bugs/BUG-081.md` — `Open` (major, найдено exploratory-charter
> CH-011, 2026-08-20). Этот тест ОЖИДАЕМО ПАДАЕТ до фикса: restore-механизм
> WebView-позиции (`peekScrollRestore`/`onScrollChanged` штатная ветка) по
> гипотезе бага срабатывает ДО полной догрузки infinite-scroll-контента до
> целевой высоты, и промежуточное событие `onScrollChanged` перезаписывает
> сохранённое значение уехавшей величиной. Заголовок и Then сформулированы от
> ОЖИДАЕМОГО (спецификационного) поведения — красный факт живёт здесь, в теле
> кейса, не в заголовке (правило CLAUDE.md, прецедент TC-264). `red_lock`
> пока пуст (кейс не автоматизирован, см. чек-лист) — будет выставлен
> test-automator'ом/test-reviewer'ом вместе с `automated_by` (прецедент TC-139).

## Предусловия
- Приложение запущено с чистыми данными (`clean_state`).
- Replay-режим, `listing_paginated.mitm` (`recording_builder.LISTING_PAGINATED_URL`,
  5 страниц, инфраструктура эвикции `PAGE_WINDOW=3`, уже используется TC-129/130/159).
- **Инфинит-скролл ВКЛЮЧЕНА ДЕЙСТВИЕМ СО СВЕРКОЙ, обязательно** (критик-гейт
  Б6, CH-011): `settings_steps.enable_infinite_scroll(driver)` +
  `settings_steps.assert_infinite_scroll_enabled(driver, True)` — гейт
  `ao3_bridge.js:603` вычисляется ОДИН РАЗ при инъекции страницы (`:698` —
  per-call ветка), тумблер
  обязан быть установлен ДО перехода на листинг. Без этого предусловия дрейф
  НЕ воспроизводится (независимый контрольный прогон критик-гейта: 3 релонча
  при OFF, 42 замера, scrollY неизменен) — не пропускать этот шаг Given.

## Сценарий (Given-When-Then)

**Given** `infinite_scroll` включена и проверена (см. Предусловия); открыт
`listing_paginated.mitm` (`browser_steps.open_listing`); активная вкладка
проскроллена ЗА ГРАНИЦУ первой страницы (инфинит-скролл догрузил страницу 2+,
`browser_steps.trigger_infinite_scroll_load`), затем ещё вглубь свайпами до
позиции в несколько тысяч пикселей (глубина, при которой BUG-081 воспроизведён:
порядка 2000+ px); позиция подтверждена реально сохранённой на диск (опрос
`open_tabs_urls`/`scrollY`, дебаунс `scheduleSave` 500мс) — снимок P0

**When** приложение убито и перезапущено РОВНО ОДИН РАЗ
(`app_steps.restart_app_via_adb_asserting_new_process`) — БЕЗ единого касания
экрана до и после релонча; выдержано окно восстановления (опрос `open_tabs_urls`
каждые ~0.5с в течение ~10с — значение стабилизируется примерно к ~4с и, по
BUG-081, может «прыгнуть» позже, к ~9с — опрос обязан покрывать весь диапазон)

**Then (ожидаемое, спецификационное)** восстановленная позиция вкладки
(`open_tabs_urls`, `scrollY`) совпадает с P0 в пределах допуска
`SCROLL_RESTORE_TOLERANCE = 100px` — та же гарантия персистентности, что уже
даёт `TC-025` для обычных (не infinite-scroll) страниц, распространённая на
infinite-scroll-листинги

**Then (фактическое на этой сборке — КРАСНОЕ, регресс-замок BUG-081)** восстановленная
позиция ДЕТЕРМИНИРОВАННО смещена на `+943px` относительно P0 — вне допуска
±100px, БЕЗ единого касания экрана в промежутке (симптом воспроизведён
BUG-081 трижды подряд: `2144→3087→4030→4973`, шаг ровно +943px на каждый
релонч; для этого TC достаточно ОДНОГО релонча — дрейф воспроизводится с
первого же)

**Инвариант:** сохранённая на диск позиция скролла вкладки после холодного
старта БЕЗ пользовательского касания равна позиции, зафиксированной
непосредственно перед killом (в пределах `SCROLL_RESTORE_TOLERANCE`) — то же
свойство персистентности, что `TC-025` (url/scroll переживают смерть
процесса независимо от содержимого страницы), здесь распространённое на
infinite-scroll-листинги и НАРУШАЕМОЕ детерминированным дрейфом (класс
`BUG-081`): restore-механизм гонится с догрузкой контента, промежуточное
событие скролла перезаписывает истинное значение уехавшей величиной.

## Заметки для автоматизации
- **Готовый, уже воспроизведённый на устройстве рецепт** — `bugs/BUG-081.md`
  (три релонча подряд, дословные величины). Для этого TC — ОДИН релонч,
  цикл (`app_steps.restart_app_via_adb_asserting_new_process` в теле теста
  вместо parametrize) оставлен для возможного будущего усиленного варианта
  (не в скоупе этого кейса).
- Чтение позиции — ТОЛЬКО через закалённого близнеца `adb.run_as_file_or_raise`
  + `app_steps._parse_persisted_tabs` (класс AT-BUG-044/045/055 — «сырой»
  `adb.run_as`/`shell cat` запрещены, глотают returncode, дают ложный «0» вместо
  честной ошибки чтения).
- **Тонкое расширение, НЕ блокер:** готового ассерта именно для `scrollY`
  конкретной позиции вкладки нет (`app_steps.assert_persisted_tab_url_at`
  читает `url`, не `scrollY`) — добавить симметричный
  `read_persisted_tab_scroll_y_at`/`wait_persisted_tab_scroll_y_at` по образцу
  уже существующих позиционных URL-геттеров (`app_steps.py:731-790`). Данные
  `scrollY` УЖЕ присутствуют в каждом объекте `TabSnapshot`, которые парсит
  `_parse_persisted_tabs` — не хватает только тонкой читающей обёртки, не
  новой фикстуры/записи. `debt_kind: missing_fixture` НЕ заводится — это не
  тот класс долга (сами данные уже физически доступны).
- Позиция P0 обязана быть подтверждена как РЕАЛЬНО сохранённая на диск (не
  in-memory снимок «на лету») перед релончем — опрос prefs, тот же приём, что
  `TC-025` (`scheduleSave` debounce 500мс, `am force-stop`/kill ДО истечения
  окна теряет несохранённое состояние безвозвратно).
- `red_lock` пока ПУСТОЕ поле — валидатор допускает его только при непустом
  `automated_by` (живой прецедент TC-139: `status: Automated` + `automated_by`
  заполнен, ТОЛЬКО тогда `red_lock: BUG-015`); до автоматизации красный факт
  несёт заголовок/тело («регресс-замок BUG-081», приём TC-264). Когда
  test-automator закодирует этот кейс, он ОБЯЗАН падать до фикса BUG-081 —
  `red_lock: BUG-081` выставляется ТОГДА (test-automator/test-reviewer), после
  `Fixed+` снимается штатно правилом `rules.yaml`.
- **Наблюдаемость негативного/различающего Then:** дрейф — числовое значение
  `scrollY` в prefs, читаемое напрямую (не сетевой эффект, не короткое
  замыкание штатного кода) — класс `AT-BUG-029`/калибровка Lead 2026-07-30 не
  применим, различие ДОСТИЖИМО и НАБЛЮДАЕМО по построению.
- **Направление негативного Then:** различающий ассерт («P_after ≈ P0» против
  «P_after далеко от P0») достижимо ложен — P0 зафиксирован явным снимком
  НЕПОСРЕДСТВЕННО перед killом на ТОЙ ЖЕ вкладке (позитивный якорь), а
  альтернативная гипотеза «случайное расхождение/шум измерения» исключена
  ДЕТЕРМИНИРОВАННОСТЬЮ уже трижды воспроизведённого BUG-081 шага (+943px
  РОВНО, не диапазон).
- Слой L3, устройство обязательно: дефект — реальная гонка restore-механизма
  WebView против реальной догрузки infinite-scroll-контента; недоступно
  jsdom-харнессу L2 (нет ни реального процесса, ни реального WebView-таймсинга).
