# TC-257 — Journey: открыть скачанный файл → удалить файл → удалить работу

## Обоснование слияния (П1 spec-p1-dedup v7, docs/tasks/p1-e2e-dedup.md Р1)

Поглощает TC-034 (`library-card-open-file`), TC-035 (`library-card-delete-file`),
TC-036 (`library-card-delete-work`) — все три ОДНОГО приоритета (P1), ОДНОГО
риска (R-05), без `red_lock`, без regress-замков `known_issue`/D3, ни один не
входит в `test_cases` открытого бага (BUG-047 — Verified, держит TC-035
контрольным путём верификации, но не открыт), все три replay/офлайн (нет
смешения live/replay). Слой один — L3 (Appium-устройство + локальный
`file://`-контент; в моста-контракт L2 не сводится: сценарий гоняет реальную
Compose-иерархию overlay и WebView, а не только `ao3_bridge.js`).

Общий дорогой Given — ОДИН сид `downloaded_work_seeded` (adb push фикстурного
`.html` + Room-запись rating=SAVE, downloadPath на существующий файл) ДО
создания Appium-сессии. Три исходных Then естественно ложатся в
последовательность мутаций ОДНОЙ работы: открыть → удалить файл (рейтинг
жив) → удалить работу (всё удалено) — то есть чекпойнт 3 требует
пересидинга (файл, удалённый в чекпойнте 2, чекпойнту 3 не нужен — Given
чекпойнта 3 пересобирается тем же дешёвым сидом, БЕЗ новой Appium-сессии),
легального по Р1 («разная СТОИМОСТЬ/природа Given» — не тот случай: сид
внутри одной запущенной сессии на порядок дешевле повторного запуска
приложения). 3 чекпойнта — под потолком ≤5. Ссылка на спеку:
docs/tasks/p1-e2e-dedup.md, разделы Р1/Р4 шаг 1.

## Предусловия
- Приложение запущено (одна Appium-сессия на весь journey), в Room засеяна
  работа W через сид `downloaded_work_seeded`: рейтинг Loved (SAVE),
  `downloadPath` указывает на существующий фикстурный `.html` в
  `ao3_downloads` (adb push, как в TC-034/035/036).
- Открыт экран Library.

## Сценарий (Given-When-Then)

**Given** на вкладке FILES/FAVORITE есть работа W с рейтингом Loved и
скачанным `.html` файлом

**When** пользователь тапает по карточке работы W, затем в отдельном
long-press overlay удаляет файл, затем в overlay удаляет работу целиком
(три последовательных действия над W в рамках одной сессии, см. «Чекпойнты»)

**Then** каждое действие даёт наблюдаемый пользователем эффект своего шага —
см. чекпойнты 1–3; итог journey: работа W и её файл отсутствуют в Library

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа W | фикстурный `.html` (сырой экспорт AO3 без viewport meta), засеяна с rating=SAVE и заполненным `downloadPath` на существующий файл (тот же сид, что у TC-034/035/036) |

## Заметки для автоматизации
- Разделение локаторов overlay критично (унаследовано из TC-035/036):
  «Delete downloaded file» (`library_screen.py:66-68`, точный `.text()`) —
  ТОЛЬКО файл; «Delete work» (`library_screen.py:62-64`) — файл И строка
  `WorkRating` целиком. Перепутать — значит проверить не тот Then на не том
  чекпойнте.
- Пересидинг между чекпойнтами 2 и 3 — НЕ новая Appium-сессия: чекпойнт 3
  стартует с того же экрана Library той же сессии, но Room-состояние под
  капотом пересобирается сидом (см. `docs/tasks/p1-e2e-dedup.md` Р1 —
  «сид дешевле новой Appium-сессии»); конкретный механизм пересидинга
  внутри живой сессии (прямой Room insert через adb / helper фикстуры) —
  решение test-automator на шаге реализации (очередь фабрики, Р4 шаг 4),
  не блокер этого дизайна.
- Приложение не делает сетевых вызовов ни в одном из трёх действий (нет
  обращения к AO3) — годится и live, и replay режим одинаково, как и в
  исходных TC-034/035/036.
- Ревью нового автотеста (F1) обязано поставить по строке `- проба:` в
  разделе «## Красная проба» НА КАЖДЫЙ из трёх чекпойнтов (машинный детектор
  validate_frontmatter.py — Р3 спеки); секция ниже — пустая заготовка,
  заполнит F1 при переводе в Automated.

## Чекпойнты

1. Открыть файл: **Given** работа W на вкладке FILES имеет связанный
   локальный `.html` **When** пользователь тапает по карточке W **Then**
   файл открывается через `file://`/`content://` URL на активной вкладке,
   страница в мобильной ширине (читаемый размер текста), применены стили
   `reader.css` (`meta[name=viewport]` + инжектированный `<style>`/
   `#ao3-reader-css` в DOM) — Then TC-034 дословно.
2. Удалить файл: **Given** работа W (после чекпойнта 1, файл всё ещё на
   диске) **When** пользователь делает long-press по карточке W и в overlay
   выбирает «Delete downloaded file» **Then** файл удалён с диска,
   `downloadPath` W пуст, W остаётся во вкладке FAVORITE с прежним рейтингом
   Loved (строка `WorkRating` НЕ удалена), карточка снова показывает
   download-иконку вместо open-иконки — Then TC-035 дословно.
3. [Пересидинг — легален по Р1: сид дешевле новой Appium-сессии между
   чекпойнтами] Удалить работу: **Given** работа W пересеяна заново с
   рейтингом Loved и скачанным файлом (то же сидирование, что в
   Предусловиях, без новой Appium-сессии) **When** пользователь делает
   long-press по карточке W и в overlay выбирает «Delete work» **Then**
   файл удалён с диска, W полностью исчезает из Library — не отображается
   ни на вкладке FAVORITE, ни на вкладке FILES (проверка по обеим вкладкам —
   единственный косвенный способ убедиться, что строка `WorkRating` удалена
   целиком) — Then TC-036 дословно.
