# TC-153 — Повторный ручной скан при двух файлах одного ao3Id сходится к relinked=0 (идемпотентность, регресс-замок BUG-046)

## Предусловия
- Работа W (`ao3_id 900000001`) в Room с рейтингом SAVE, `downloadPath`
  указывает на файл `ao3_A_900000001.html` — ОДИН из двух файлов группы
  (детерминированный старт «уже привязана», см. «Сценарий»).
- В ТОЙ ЖЕ папке загрузок лежит ВТОРОЙ файл того же `ao3Id`, но с другим
  именем (`ao3_ЛОКАЛЬНЫЙ_900000001.html`) — оба имени матчят
  `WORK_ID_PATTERN` (хвост `_<ao3Id>.html`); оба файла — валидный HTML
  (сверка с фикстурным эталоном, не пустышки).
- Открыт экран Settings.

## Сценарий (Given-When-Then)

**Given** в папке загрузок лежат ДВА файла одного `ao3Id` (900000001), Room
содержит одну строку с `downloadPath`, УЖЕ указывающим на ОДИН из двух файлов
группы (детерминированный старт — см. примечание «Альтернативный старт» ниже)

**When** пользователь трижды подряд нажимает «Scan for downloads» в Settings
(без изменений на диске между нажатиями)

**Then** ПЕРВЫЙ скан выдаёт диалог `Scan complete` / `Found 2 files —
relinked 0, added 0 new.` / `OK` — группа уже «привязана» (Room-строка
указывает на файл из этой же группы файлов), relink не засчитывается
**And** ВТОРОЙ и ТРЕТИЙ сканы (состояние диска не менялось) дают ИДЕНТИЧНЫЙ
диалог `Found 2 files — relinked 0, added 0 new.` — три скана подряд дают
одинаковый результат

**Альтернативный старт (не обязателен для automation, эквивалентный вариант
Given, упомянут для полноты):** если вместо baseline «строка уже привязана»
взять Room-строку с `downloadPath = null` (строка существует, но ни к одному
файлу группы не привязана), ПЕРВЫЙ скан даёт `Found 2 files — relinked 1,
added 0 new.` (устанавливающий relink на детерминированного победителя по
`lastModified`), а ВТОРОЙ и ТРЕТИЙ — снова `Found 2 files — relinked 0, added
0 new.`. Оба старта сходятся к `relinked 0` не позже второго скана; для
автоматизированного теста достаточно ОДНОГО детерминированного варианта —
рекомендуется «строка уже привязана» (0/0/0 на всех трёх сканах, короче и не
зависит от алгоритма выбора победителя).

**Инвариант:** для НЕИЗМЕННОГО состояния файловой системы повторный ручной
скан — идемпотентная операция: при неизменном диске второй и последующие
сканы всегда дают `relinked 0`, а не количество файлов, матчащих `ao3Id`,
целиком на каждый проход; свойство верно для любого N файлов одного
`ao3Id`, кейс проверяет представителя N=2. Подтверждено пост-фиксовым
device-witness'ом fix-verifier (`bugs/BUG-046.md`, запись `fix-verifier @
2026-08-11T16:11:00Z`): 3 живых скана подряд дали `relinked 1 → 0 → 0`
(старт с непривязанной строкой) — второй и третий скан идентичны, счётчик
сошёлся и остался на нуле.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа W | `ao3_id 900000001`, rating=SAVE |
| Файл 1 (в downloadPath с самого начала) | `ao3_A_900000001.html` |
| Файл 2 (второй файл группы) | `ao3_ЛОКАЛЬНЫЙ_900000001.html`, тот же `ao3Id` |
| Число сканов | 3 подряд, без изменений на диске между ними |

## Заметки для автоматизации
- Сетап — SAF-подпапочная техника (НЕ прямой `adb push` в дефолтную
  `getExternalFilesDir("ao3_downloads")`: падает на API 34 «secure_mkdirs
  failed»/«Permission denied» под run-as даже при совпадении UID,
  задокументировано `framework/data/seed_db.py:417-427`). Приём — как в
  `orphan_download_relink_seeded` (`framework/tests/test_downloads.py:648-676`,
  использован TC-038): уникальная SAF-подпапка публичного хранилища
  выбирается через `saf_steps.saf_pick_folder(driver, f"Download/{subfolder}")`
  (`framework/steps/saf_steps.py:187`), файлы кладутся заранее
  `adb.push_external(local_html, remote_path)` (`framework/core/adb.py:289`) с
  именами, матчащими `WORK_ID_PATTERN`. Та же техника использована
  fix-verifier'ом на живом устройстве при D1-верификации BUG-046 (см.
  «Обсуждение»/«Верификация» в `bugs/BUG-046.md`, запись 2026-08-11T16:11:00Z).
- Baseline «строка уже привязана» получить проще технически, чем
  «downloadPath=null, но строка существует»: посадить работу через
  фикстуру, аналогичную `orphan_download_relink_seeded` (Room без
  downloadPath + один orphan-файл), выбрать SAF-папку (silent-скан
  переводит в `relinked 1`, привязывает к файлу 1), ЗАТЕМ добавить файл 2
  через `adb.push_external` и запускать явный «Scan for downloads» ×3
  (`settings_steps.tap_settings_action(driver, "Scan")` +
  `assert_scan_complete_dialog`) — это и есть Given кейса (детерминированный
  старт «уже привязана»).
- `download_oracle` (autouse, conftest.py) наблюдает
  `getExternalFilesDir("ao3_downloads")` — при SAF-технике (папка ВНЕ
  дефолтного каталога) оракул не увидит push'нутые файлы как «новые» через
  этот путь; сверить с текущим поведением оракула на SAF-путях TC-038/TC-039
  (уже зелёные, тот же паттерн) — не блокер, рутинная настройка.
- Дословный текст диалога — существующий паттерн `settings_steps.py`
  (`tap_settings_action(driver, "Scan")` + `assert_scan_complete_dialog`),
  уже использован TC-037/038/039.
- Дельта к TC-037 (0 файлов)/TC-038 (1 файл, relink при смене папки)/TC-039
  (orphan-скан внутри Restore, 1 синтетический файл) — ни один не создаёт ДВА
  файла на один `ao3Id`, что и есть условие ветвления
  `scanForOrphanedDownloads` (`DownloadRepository.kt:94-141`).
- **Класс, НЕ покрытый этим кейсом** (находка критика на критик-входе
  приёмки D1 BUG-046, `logs/routing-log.jsonl` событие `accepted`
  task_id=BUG-046 @ 2026-08-11T16:35:08Z, оговорка (4)): N=2 файла одного
  `ao3Id`, но Room-строки НЕТ ВООБЩЕ (`existing == null`, `:119-131`) — код
  создаёт ОДИН stub-row на детерминированного победителя (`added++` ровно
  один раз, не по числу файлов дублей) — отдельный инвариант («`added` не
  путается с количеством файлов группы»), которого TC-153 не проверяет.
  Кандидат в дельту этого кейса или отдельный design-only кейс — решение
  test-designer, вне скоупа этой правки.
- Область — реконсиляция «множество файлов на диске ↔ одна строка Room»,
  того же класса, что backup/restore (множество записей должно сохраняться
  предсказуемо через операцию) — отсюда явная строка `Инвариант:` выше, а не
  просто пример с конкретными числами.
