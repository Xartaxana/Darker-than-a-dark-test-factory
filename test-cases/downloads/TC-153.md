# TC-153 — Повторный ручной скан при двух файлах одного ao3Id сходится к нулю relinked (ожидаемо-красный, BUG-046)

## Предусловия
- Работа W (`ao3_id 900000001`) в Room с рейтингом SAVE, `downloadPath`
  указывает на файл `ao3_A_900000001.html` в ДЕФОЛТНОЙ папке загрузок
  (`getExternalFilesDir("ao3_downloads")`, устройство:
  `/sdcard/Android/data/<pkg>/files/ao3_downloads`).
- В ТОЙ ЖЕ папке лежит ВТОРОЙ файл того же `ao3Id`, но с другим именем
  (`ao3_ЛОКАЛЬНЫЙ_900000001.html`) — оба имени матчят
  `WORK_ID_PATTERN` (хвост `_<ao3Id>.html`); оба файла — валидный HTML
  (сверка с фикстурным эталоном, не пустышки).
- Открыт экран Settings.

## Сценарий (Given-When-Then)

**Given** в папке загрузок лежат ДВА файла одного `ao3Id` (900000001), Room
содержит одну строку с `downloadPath`, указывающим на один из них

**When** пользователь трижды подряд нажимает «Scan for downloads» в Settings
(без изменений на диске между нажатиями)

**Then** после ПЕРВОГО скана появляется диалог `Scan complete` / `Found 2
files — relinked 2, added 0 new.` / `OK` — это ожидаемо (два файла реально
найдены)
**And** после ВТОРОГО и ТРЕТЬЕГО сканов (состояние диска не менялось) диалог
должен сойтись к `Found 2 files — relinked 0, added 0 new.` (или `relinked 1,
added 0 new.` для второго — идемпотентность: повторный скан без изменений на
диске НЕ должен снова перелинковывать ту же работу на оба файла)

**Инвариант:** для НЕИЗМЕННОГО состояния файловой системы повторный ручной
скан — идемпотентная операция: счётчик `relinked` второго и последующих
сканов ограничен числом путей, РЕАЛЬНО изменившихся с предыдущего скана (при
отсутствии изменений — 0), а не количеством файлов, матчащих `ao3Id`,
целиком на каждый проход; свойство верно для любого N файлов одного `ao3Id`,
кейс проверяет представителя N=2.

**ОЖИДАЕМОЕ ПАДЕНИЕ на текущей сборке:** по коду (`DownloadRepository.kt:
108-130`) цикл идёт по КАЖДОМУ файлу и обновляет `downloadPath`, если он
отличается от текущего пути файла — при двух файлах одного `ao3Id` каждый
следующий скан снова находит расхождение (файл A → `updateDownloadPath`,
`relinked++`; файл B → путь уже совпадает лишь ЧАСТИЧНО из-за порядка
`listFiles()`) и реально рапортует `Found 2 files — relinked 2, added 0 new.`
НА ВСЕХ ТРЁХ сканах подряд, не сходясь к 0. Красный результат триажится как
**APP_BUG/BUG-046**, не как расхождение теста со спекой; ссылка:
`bugs/BUG-046.md`.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа W | `ao3_id 900000001`, rating=SAVE |
| Файл 1 (в downloadPath) | `ao3_A_900000001.html` |
| Файл 2 (сирота) | `ao3_ЛОКАЛЬНЫЙ_900000001.html`, тот же `ao3Id` |
| Число сканов | 3 подряд, без изменений на диске между ними |

## Заметки для автоматизации
- Два файла одного `ao3Id` в ДЕФОЛТНОЙ папке загрузок можно получить БЕЗ
  зависимости от BUG-021 — прямым `adb push` двух файлов с именами,
  матчащими `WORK_ID_PATTERN` (`..._<ao3Id>.html`), в
  `/sdcard/Android/data/<pkg>/files/ao3_downloads`, по образцу техники
  orphan-фикстуры TC-038/TC-039 (`saf_steps`/adb-push перед сканом), НЕ через
  door-инструмент CH-008 (правка заметки → повторное скачивание) — так сетап
  этого кейса не сломается, когда BUG-021 будет исправлен. Один из двух
  файлов кладётся ДО сидинга Room-строки с `downloadPath`, указывающим на
  него (реалистичный baseline «уже привязан»), второй — как orphan рядом.
- `download_oracle` (autouse, conftest.py) наблюдает именно
  `getExternalFilesDir("ao3_downloads")` — тот же каталог; оракул увидит оба
  push'нутых файла как «новые» с точки зрения снимка теста — учесть маркер
  ожидаемого количества (по образцу `@pytest.mark.produces_download`,
  используемого в TC-032/033/114/115), не блокер, рутинная настройка.
  Проверить, различает ли оракул «файл появился ЧЕРЕЗ adb-push сетапа» от
  «файл появился ЧЕРЕЗ downloadWork()» — если различает не сразу, это
  инструментальный вопрос теста, не багом заводить.
- Дословный текст диалога — существующий паттерн `settings_steps.py`
  (`tap_settings_action(driver, "Scan")` + чтение текста алерта), уже
  использован TC-037/038/039.
- Дельта к TC-037 (0 файлов)/TC-038 (1 файл, relink при смене папки)/TC-039
  (orphan-скан внутри Restore, 1 синтетический файл) — ни один не создаёт ДВА
  файла на один `ao3Id`, что и есть условие ветвления цикла
  `DownloadRepository.kt:108-130` (см. `bugs/BUG-046.md`).
- Область — реконсиляция «множество файлов на диске ↔ одна строка Room»,
  того же класса, что backup/restore (множество записей должно сохраняться
  предсказуемо через операцию) — отсюда явная строка `Инвариант:` выше, а не
  просто пример с конкретными числами.
