# TC-207 — LWW-слияние: более свежая удалённая версия побеждает целиком

## Предусловия
- Приложение запущено с чистыми данными, синхронизация настроена (валидные
  instance/token/snippet ID).
- Работа X засеяна локально: `rating=LIKE`, `comment="local note"`,
  `tags=["localtag"]`, `timestamp=T1`, `downloadPath` указывает на реально
  существующий на устройстве файл (`seed_with_comment_and_download`).
- Удалённый снимок (мок GitLab-сниппета) содержит строку для того же `ao3Id`:
  `rating=SAVE`, `comment="remote note"`, `tags=["remotetag"]`,
  `timestamp=T2`, `T2 > T1`, без поля `downloadPath` (протокол никогда его не
  публикует).

## Сценарий (Given-When-Then)

**Given** локальная строка X (LIKE/local note/localtag, T1, файл на диске) и
удалённая строка X (SAVE/remote note/remotetag, T2>T1) настроены как выше

**When** пользователь запускает «Sync now»

**Then** локальная строка X теперь показывает `rating=SAVE`,
`comment="remote note"`, `tags=["remotetag"]` — удалённая версия замещает
локальную целиком по всем полям, КРОМЕ:
**And** `downloadPath` X не изменился — файл по-прежнему открывается (карточка
показывает open-иконку, не download-иконку)

Инвариант: победитель слияния строки определяется исключительно сравнением
timestamp двух версий (remote>local ⇒ remote замещает целиком); `downloadPath`
— единственное поле, которое ВСЕГДА берётся со стороны принимающего
устройства независимо от исхода сравнения timestamp.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| ao3Id | X (любая эталонная работа `works.py`) |
| Локально | rating=LIKE, T1, downloadPath=файл |
| Удалённо | rating=SAVE, T2>T1, downloadPath отсутствует в JSON |

## Заметки для автоматизации
- **Sync-фикстура отсутствует** (информация для test-automator, не блокер
  этому дизайну по указанию диспетчера): в `framework/data/` нет ни
  mitm-записи `/api/v4/snippets/...`, ни сидера удалённого снимка —
  понадобится мок GitLab API аналогично тому, как `recording_builder.py`
  собрал `listing_basic.mitm` для AT-BUG-004.
- Обязательный контраст, о котором дизайн предупреждает автора: Restore из
  бэкапа при коллизии `ao3Id` строку ПРОПУСКАЕТ
  (`settings-restore-merge-skip-existing`, TC-021 folder), а синхронизация её
  ПЕРЕЗАПИСЫВАЕТ — не перепутать при кодировании общих шагов.
- Проверка downloadPath — через `seed_db.read_work_ratings_full()` (уже
  умеет читать `downloadPath`) или прямое открытие файла с карточки.
