# TC-224 — Ручной прогон sync: дословный диалог ошибки по причине сбоя, локальные данные не меняются

**Поглощает:** TC-225 (П1 spec-p1-dedup v7, docs/tasks/p1-dedup-lead-pass.md Р2:
«ручной прогон sync с несуществующим Snippet ID против отклонённого токена.
Один механизм (диалог ошибки + неизменность локальных данных), различие —
вариант ошибки и дословный текст»).

## Предусловия
- Синхронизация настроена; Локально есть оценённая работа X (для проверки
  «данные не изменились») — общий baseline для обоих вариантов.
- Вариант A: Snippet ID указывает на несуществующий сниппет (мок GitLab
  отвечает `404` на `GET /api/v4/snippets/<id>`).
- Вариант B: Snippet ID валиден, но мок GitLab отвечает `401` (или `403`) на
  запрос — симулирует токен без scope `api`.

## Сценарий (Given-When-Then)

### Вариант A — несуществующий Snippet ID → 404 (родной сценарий TC-224)

**Given** Snippet ID указывает на несуществующий сниппет, локально есть
оценённая работа X

**When** пользователь нажимает «Sync now»

**Then** показан диалог «Sync failed» с дословным текстом «Snippet <id> not
found. Check the snippet ID, or clear it to create a new one.»
**And** локальные данные работы X НЕ изменились (рейтинг/вкладка те же, что
до прогона — второй обязательный Then негативного сценария)

### Вариант B — отклонённый токен → 401/403 (поглощает TC-225)

**Given** мок отвечает 401/403 на запрос к сниппету (Snippet ID валиден),
локально есть оценённая работа X (тот же baseline, что вариант A)

**When** пользователь нажимает «Sync now»

**Then** показан диалог «Sync failed» с дословным текстом «GitLab rejected
the token (HTTP <code>). It needs the 'api' scope.», где `<code>` — реально
полученный код (401 или 403) — текст ОТЛИЧАЕТСЯ от варианта A: разные
причины сбоя дают разные сообщения при одном заголовке «Sync failed»
**And** локальные данные работы X НЕ изменились (тот же инвариант, что
вариант A)

**Инвариант:** ручной прогон sync при ЛЮБОЙ причине сбоя (404 — сниппет не
найден, 401/403 — токен отклонён) НЕ мутирует локальные данные ни при каких
обстоятельствах — сбой синхронизации атомарен относительно Room; разные
дословные тексты диалога (доказано двумя вариантами) не маскируют общее
свойство неизменности.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Вариант A: Snippet ID | указывает на несуществующий сниппет |
| Вариант A: ответ мока | 404 |
| Вариант A: диалог | «Snippet <id> not found. Check the snippet ID, or clear it to create a new one.» |
| Вариант B: ответ мока | 401 (вариант прогона — 403) |
| Вариант B: диалог | «GitLab rejected the token (HTTP 401). It needs the 'api' scope.» |
| Локальные данные до/после (оба варианта) | идентичны |

## Заметки для автоматизации
- Sync-фикстура (мок 404-ответа и мок 401/403-ответа) отсутствует —
  информация для test-automator, не блокер (Given/Then кейса полны, оба
  варианта используют одну и ту же инфраструктуру мока GitLab, отличается
  только код ответа).
- Второй Then каждого варианта (данные не изменились) — прямая сверка Room
  до/после через `read_work_ratings_full()`, приём одинаков для A и B.
- Автоматизации варианта B достаточно ОДНОГО из двух кодов (401 ИЛИ 403) как
  представителя ветки — код обрабатывает их идентично
  (`SyncRepository.kt:364-366` не различает 401/403 в тексте сообщения,
  только подставляет фактический код; было `:250-256` — критик-гейт прохода
  11 сверил с HEAD, прежняя ссылка указывала на блок публикации, не на
  ветки ошибок).
- Оба варианта — независимые прогоны ОДНОГО параметризованного теста (общий
  baseline Room, разный код/причина ответа мока) — не journey/чекпойнты,
  каждый самодостаточен, секция «Чекпойнты» не нужна.
