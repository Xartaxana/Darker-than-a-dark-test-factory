# TC-214 — Отсутствующий downloadPath не появляется из слияния

## Предусловия
- Синхронизация настроена. Работа W засеяна БЕЗ `downloadPath` (никогда не
  скачивалась), `rating=LIKE`, `timestamp=T1`.
- Удалённый снимок несёт строку W с ДРУГИМ рейтингом (`rating=SAVE`),
  `timestamp=T2 > T1` — как у любой строки, без поля `downloadPath` в JSON.

## Сценарий (Given-When-Then)

**Given** локальная работа W без скачанного файла и более свежая удалённая
версия W с другим рейтингом

**When** пользователь запускает «Sync now»

**Then** рейтинг W обновляется до SAVE (подтверждает, что слияние
произошло)
**And** W по-прежнему НЕ появляется на вкладке Files Library — `downloadPath`
остаётся отсутствующим, слияние не могло его создать «из ниоткуда»

Инвариант: `downloadPath` никогда не приходит с удалённой стороны — ни
отсутствие, ни наличие скачанного файла НА ДРУГОМ устройстве не влияют на
его значение после слияния на этом устройстве (парный случай — TC-207, где
УЖЕ существующий локальный `downloadPath` при этом ПЕРЕЖИВАЕТ победу
удалённой строки).

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа W | без downloadPath, rating=LIKE, T1 |
| Удалённая версия | rating=SAVE, T2>T1, downloadPath отсутствует в JSON |

## Заметки для автоматизации
- Sync-фикстура отсутствует — тот же класс, что предыдущие кейсы области.
