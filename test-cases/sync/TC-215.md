# TC-215 — Публикация полного состояния после слияния

## Предусловия
- Синхронизация настроена. Локально есть хотя бы одна оценённая работа и
  один фильтр-профиль (произвольные данные), удалённый снимок (мок) пуст
  или отличается от локального состояния.

## Сценарий (Given-When-Then)

**Given** локальное состояние содержит хотя бы одну работу и один
фильтр-профиль, требующие публикации (текст снимка не совпадает с локально
рассчитанным)

**When** пользователь запускает «Sync now»

**Then** приложение отправляет запрос на запись сниппета (создание либо
`PUT`, перехвачено mitm-прокси), тело которого — JSON с `version: 3` и
тремя массивами: `works`, `filterProfiles`, `tombstones` — все локальные
работы/профили/надгробия представлены

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Локальное состояние | ≥1 работа, ≥1 фильтр-профиль |
| Ожидаемая форма тела запроса | `{"version":3,"works":[...],"filterProfiles":[...],"tombstones":[...]}` |

## Заметки для автоматизации
- Требует mitm-перехвата ИСХОДЯЩЕГО тела запроса (не только ответа) — техника
  отличается от обычного `server-replay` (там подставляется готовый ответ, а
  не проверяется отправленное тело); понадобится либо запись через
  proxy-в-режиме-capture, либо серверная заглушка, сверяющая полученный JSON.
  Информация для test-automator, не блокер этому дизайну.

## Чек-лист качества (test-designer проходит перед `Review`)
- [x] Один сценарий — один кейс
- [x] Given воспроизводим фикстурами

- [x] Приоритет/область/источник указаны
- [x] Независим от порядка других кейсов
- [x] Область не комбинаторная в смысле банка C4 для ЭТОГО кейса — он

      (свойство сходимости — отдельный кейс TC-216)
