# TC-209 — Входящее надгробие удаляет работу и файл целиком

## Предусловия
- Синхронизация настроена. Работа Y засеяна локально: `rating=SAVE`,
  непустые `comment`/`tags`, `timestamp=T1`, `downloadPath` указывает на
  реально существующий на устройстве файл (`seed_with_comment_and_download`).
- Удалённый снимок несёт НАДГРОБИЕ для того же `ao3Id` с `deletedAt=T2`,
  `T2 > T1` (более свежее, чем локальная строка).

## Сценарий (Given-When-Then)

**Given** локальная работа Y с заметкой/тегами/скачанным файлом и более
свежее входящее надгробие для Y настроены как выше

**When** пользователь запускает «Sync now»

**Then** работа Y исчезает из ВСЕХ рейтинговых вкладок Library
**And** скачанный файл Y физически удалён с диска устройства (проверка ПУТЁМ
— `adb shell ls <downloadPath>` возвращает «нет такого файла», а не только
отсутствием open-иконки в UI) — удаление ведёт себя как «Delete work», не
«убрать строку», локальные заметка/теги Y работу НЕ спасли
**And** локальное надгробие Y теперь несёт удалённый `deletedAt` (T2)

Инвариант: победа входящего надгробия над строкой не зависит от богатства
локального состояния строки (наличие/отсутствие заметки, тегов, файла) —
`hasOtherState` захардкожен `false`, то есть удаление всегда полное
(семантика «Delete work»), для ЛЮБОГО состава локальных полей.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа Y | comment+tags+downloadPath, T1 |
| Удалённое надгробие | deletedAt=T2>T1 |

## Заметки для автоматизации
- Sync-фикстура (мок снимка с надгробием) отсутствует — информация для
  test-automator, не блокер этому дизайну.
- **Наблюдаемость негативного факта «файла больше нет»:** проверка ОБЯЗАНА
  идти прямым запросом к файловой системе устройства (путь известен из
  `seed_with_comment_and_download`), а не только по смене иконки на
  карточке — иначе гипотетический баг «карточка перерисована, но файл
  физически остался» останется незамеченным.
- Грань R-01+R-16 для дизайна области 2 (авто-триггер): на автоматическом
  пути это же разрушительное действие происходит без единого сообщения —
  см. TC-231.
