# TC-119 — Тап по кнопке в теле работы НЕ запускает зональное действие (whitelist блокирует, replay)

## Предусловия — БЛОКЕР (заведён test_debt-багом AT-BUG-030 в этом же ходе)
- Приложение запущено с чистыми данными, `tap_to_scroll` включён в Settings
  (`prefs.tap_to_scroll = true`).
- Открыта replay work-страница (`framework/data/recording_builder.py::
  render_work_page_html`) — **фикстура СЕЙЧАС НЕ содержит ни одного `<button>`
  в теле страницы** (только `h2/h3/h5/a/ul/li/p`) — нужен фикстурный `<button>`
  с любым видимым JS-эффектом собственного обработчика (например, инкремент
  текстового счётчика в `data-tap-marker`), расположенный в СРЕДНЕЙ трети
  viewport после скролла к началу страницы (см. AT-BUG-030).
- Нижняя панель свёрнута, открыто >=2 вкладок, высота документа >= 3×
  `innerHeight` (`pathname ^/works/\d` соблюдён самой work-страницей).

## Сценарий (Given-When-Then)

**Given** приложение открывает replay work-страницу с `tap_to_scroll=ON`;
нижняя панель свёрнута, >=2 вкладки, документ высокий (>=3×`innerHeight`); в
теле страницы присутствует фикстурный `<button data-tap-marker>` с собственным
`click`-обработчиком, расположенный в средней трети текущего viewport

**When** пользователь тапает по этому `<button>` (координата попадает на сам
элемент, средняя треть экрана, не ниже `wv.y + wv.height + 53`)

**Then** зональное действие СРЕДНЕЙ трети (`Android.toggleFullscreen()`) НЕ
вызывается — TabStrip/системные бары остаются в исходном состоянии (не
переключились)
**And** собственный обработчик кнопки СРАБАТЫВАЕТ (`data-tap-marker`
инкрементирован/изменился ожидаемым образом) — действие узла НЕ перехвачено
guard'ом (`closest()`-проверка `ao3_bridge.js:1155` возвращает управление ДО
любой из веток `scrollBy`/`toggleFullscreen`/`preventDefault`), просто не
породило зонального эффекта. Формулировка уточнена ревью F1 2026-07-29 (тот
же класс, что TC-121): `dispatchEvent` адресует событие узлу напрямую, минуя
hit-testing, поэтому «тап физически дошёл до узла» этот ассерт не доказывает

**Инвариант:** решение guard'а (подавить зональное действие или пропустить его)
— функция ТОЛЬКО от того, входит ли `e.target.closest(...)` в whitelist
тегов/role, и НЕ зависит от наличия у узла собственного обработчика; этот
кейс держит «есть собственный обработчик» = true и варьирует «в whitelist» =
true, сиблинг TC-120 держит то же «есть обработчик» = true и варьирует
«в whitelist» = false — вместе пара доказывает, что различие Then вызвано
именно тегом/role, а не наличием обработчика самого по себе.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Тумблер | `tap_to_scroll` = ON |
| Целевой узел | фикстурный `<button data-tap-marker>` (whitelisted тег) |
| Зона тапа | средняя треть viewport |
| Ожидаемый Then | toggleFullscreen НЕ вызван; собственный обработчик кнопки вызван |

## Заметки для автоматизации — БЛОКЕР (заведён test_debt-багом AT-BUG-030 в этом же ходе, историческая версия)
- **Суть блокера:** `recording_builder.py::render_work_page_html` не несёт ни
  одного `<button>` в теле страницы (`ul.work.navigation.actions` содержит
  только `<a>`-ссылки download-списка) — без фикстурного узла кейс физически
  невыполним ни в каком виде. Подробности и критерий готовности —
  `bugs/AT-BUG-030.md` (bundled с TC-120 — тот же фикстурный пробел).
- До готовности фикстуры кейс не диспатчится в автоматизацию — `status:
  Review` (не `Blocked`: дизайн полон, ограничена только автоматизация, тот
  же паттерн, что TC-115/AT-BUG-029).
- **Позиционирование узла в СРЕДНЕЙ трети — обоснование ИСПРАВЛЕНО доработкой
  attempt 3 (критик-вход D1; прежняя формулировка «чтобы избежать
  интерференции со scrollBy» была неверна и расходилась с `bugs/AT-BUG-030.md`,
  который в attempt 2 утверждал обратное — «средняя треть не обязательна
  геометрически»).** Корректно работающий guard блокирует whitelisted-узел
  независимо от координаты тапа (`ao3_bridge.js:1155` — `closest()`-проверка
  идёт ДО вычисления третьей) — средняя треть НЕ нужна для того, чтобы guard
  сработал. Она нужна для ДИАГНОСТИЧЕСКОЙ СИЛЫ негативного Then этого кейса:
  Then ассертит ТОЛЬКО «`toggleFullscreen` не вызван». Если бы узел стоял в
  верхней/нижней трети, а guard сломался регрессией (перестал распознавать
  whitelisted-класс), клик провалился бы в зональную логику
  (`ao3_bridge.js:1156-1158`) и вызвал бы `scrollBy`, а не `toggleFullscreen` —
  Then прошёл бы ЛОЖНО-ЗЕЛЁНЫМ, неотличимо от корректной работы guard'а.
  Средняя треть — единственная зона, где сломанный guard дал бы именно
  `toggleFullscreen` (наблюдаемое расхождение с ожиданием), поэтому обязательна
  для диагностической силы негатива, не для физической достижимости узла
  (подробности — `bugs/AT-BUG-030.md`, раздел «Геометрия узлов 1 и 2»,
  согласовано обоими файлами).
- `tap_to_scroll` включается через штатный Settings-тумблер
  (`SettingsScreen.kt:699`) — рутинная автоматизация, не блокер.
- Сиблинг TC-120 — тот же режим replay, НЕ-whitelisted узел с собственным
  обработчиком: получает ОБА эффекта (контраст с этим кейсом). TC-118 — живая
  числовая проба предпосылки (сколько таких НЕ-whitelisted узлов есть на
  реальном AO3), интерпретируется вместе с этой парой.
