# TC-121 — Тап по ссылке скачивания (whitelisted тег, БЕЗ собственного обработчика) не запускает зональное действие

## Предусловия
- Приложение запущено с чистыми данными, `tap_to_scroll` включён в Settings
  (`prefs.tap_to_scroll = true`).
- Открыта replay work-страница фикстуры `work_with_download.mitm`
  (`framework/data/recording_builder.py::render_work_page_html` +
  `_download_list_html`, TC-032/033) — download-список УЖЕ содержит
  `<a href=".../<id>/<slug>.html?updated_at=0">HTML</a>` внутри
  `li.download > ul.download-list` (существующая фикстура, никакого нового
  узла заводить не нужно — **не блокер**, в отличие от TC-119/120/122). Именно
  `work_with_download.mitm`, а НЕ `listing_basic.mitm`, — только у первой в
  `.mitm` записан ВТОРОЙ flow под самим download-URL (`build_work_with_download`,
  `scripts/build_replay_recordings.py:68-80`), поэтому клик по ссылке
  безопасно резолвится через server-replay, а не уходит в непокрытый URL.
- Нижняя панель свёрнута, открыто >=2 вкладок (общие предусловия области per
  DoD дизайна — см. заметку ниже: для ЭТОГО Then геометрия/зона не влияют).

## Сценарий (Given-When-Then)

**Given** приложение открывает work-страницу фикстуры `work_with_download.mitm`
с `tap_to_scroll=ON`; нижняя панель свёрнута, >=2 вкладки; в теле страницы
присутствует `<a href="…/<id>/<slug>.html?…">HTML</a>` — ссылка скачивания без
собственного JS-обработчика (обычный `href`, штатное поведение браузера)

**When** пользователь тапает по этой ссылке (координата попадает на сам
элемент — в естественном месте документа, БЕЗ требования к средней трети, см.
заметку ниже)

**Then** зональное действие (ни `scrollBy`, ни `Android.toggleFullscreen()`) НЕ
вызывается — состояние TabStrip/системных баров и позиция скролла остаются
исходными непосредственно в момент клика (guard's `closest()`-проверка
отсекает тап ДО вычисления третьей, независимо от координаты)
**And** дефолтное действие ссылки ПРОИСХОДИТ — WebView навигирует на
скачиваемый `.html`-документ (`render_downloaded_work_html`, записан в том же
`.mitm`) — используется как ПОЗИТИВНОЕ доказательство, что тап физически дошёл
до целевого узла (клик не проглочен панелью/чем-либо ещё), не просто
«ничего не произошло»

**Инвариант:** решение guard'а — функция ТОЛЬКО от членства `e.target.
closest(...)` в whitelist тегов/role, НЕ от наличия у узла собственного JS
`onclick`-обработчика. Эта ячейка (whitelist=true, обработчик=false) замыкает
2×2-матрицу, которую вместе объявляют TC-119 (whitelist=true, обработчик=true)
и TC-120 (whitelist=false, обработчик=true): без неё утверждение «решение
guard'а зависит только от тега/role» не доказано — можно было бы (ошибочно)
предположить, что срабатывание зависит от КОМБИНАЦИИ «тег + обработчик», а не
от одного лишь тега.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Тумблер | `tap_to_scroll` = ON |
| Целевой узел | `<a href="…/<id>/<slug>.html?…">HTML</a>` (whitelisted тег `a`, БЕЗ onclick) |
| Фикстура | `work_with_download.mitm` (обязательно эта, не `listing_basic.mitm` — см. предусловия) |
| Ожидаемый Then | toggleFullscreen/scrollBy НЕ вызваны; дефолтная навигация ссылки происходит |

## Заметки для автоматизации
- **Позиция тапа не завязана на среднюю треть.** Guard проверяет
  `e.target.closest(whitelist)` ПЕРЕД вычислением `third = innerHeight/3`
  (`ao3_bridge.js:1155-1156`) — для whitelisted-узла ранний `return`
  срабатывает независимо от координаты клика. Поэтому в отличие от TC-119/120
  этому кейсу НЕ нужна специальная геометрия/margin — координата берётся из
  естественного положения ссылки в DOM (сразу после `#workskin` preface, до
  филлер-контента). Общие предусловия тап-зон (нижняя панель, >=2 вкладки)
  оставлены для консистентности per DoD дизайна области, высота документа
  (>=3×innerHeight) на ЭТОТ Then не влияет — не завожу как обязательное
  предусловие ИМЕННО этого кейса (в отличие от TC-119/120/122, где она нужна
  общим требованием области; здесь это было бы избыточно строгим требованием
  без функциональной причины).
- **Навигация — намеренная часть Then, не побочный шум.** После тапа WebView
  переходит на скачиваемый `.html`; следующий шаг теста (если есть) должен
  учитывать смену страницы. Если фреймворку нужен чистый выход из теста —
  можно завершать assert сразу после проверки состояния TabStrip/скролла
  (проверяется синхронно на этом же кадре/сразу после события), не дожидаясь
  стабилизации новой страницы.
- Сиблинг: TC-119/TC-120 (2×2-матрица whitelist×обработчик по средней трети),
  TC-122 (closest по потомку). TC-118 — числовая проба предпосылки на живом
  AO3, не проверяет guard напрямую.
- Маркер: без `@pytest.mark.live` (полностью replay/детерминированный).
- Не блокер: фикстура (`work_with_download.mitm`, `_download_list_html`) уже
  существует и Verified (AT-BUG-004 инкремент 3) — `bugs/AT-BUG-030.md` этот
  кейс НЕ покрывает и покрывать не должен.
