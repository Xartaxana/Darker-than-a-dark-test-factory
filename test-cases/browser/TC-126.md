# TC-126 — Тап по верхней трети work-страницы скроллит страницу вверх

## Предусловия
- Приложение запущено с чистыми данными; `tap_to_scroll = ON` (routine-настройка
  через Settings — сама проверка тумблера не в скоупе этого кейса, см. TC-123/124).
- Открыта replay work-страница, документ высокий (>= 3×`innerHeight` — общий
  блокер с `bugs/AT-BUG-030.md`, узел 3).
- Страница предварительно проскроллена ВНИЗ (например, программным
  `scrollTo` или предшествующим тапом по нижней трети) так, чтобы
  `window.scrollY > 0.95 × innerHeight` — иначе тап вверх упрётся в границу
  `scrollY=0` и Then неотличим от «зона не сработала».
- Нижняя панель свёрнута, >=2 вкладки, не fullscreen.

## Сценарий (Given-When-Then)

**Given** `tap_to_scroll = ON`; work-страница открыта и предварительно
проскроллена вниз (`scrollY = S`, `S > 0.95 × innerHeight`)

**When** пользователь тапает по верхней трети экрана (координата `clientY <
innerHeight/3`, цель — неинтерактивный узел)

**Then** `window.scrollY` уменьшается примерно на `0.95 × innerHeight`
(измерение CH-005: `dy ≈ -1710` при `innerHeight=1800`) — страница
скроллится к началу документа

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Зона тапа | верхняя треть (`clientY < innerHeight/3`) |
| `scrollY` до тапа | `S` (> `0.95×innerHeight`) |
| `scrollY` после тапа | `S - 0.95×innerHeight` (± допуск на границу/анимацию) |

## Заметки для автоматизации
- **Блокер общий с `bugs/AT-BUG-030.md`** (узел 3, высота документа) — тот же
  класс, что TC-123/TC-124/TC-125/TC-127. Кейс добавлен в `test_cases`
  AT-BUG-030 этим же ходом; узлы 1/2 (button/div[onclick]) этому кейсу не
  нужны — тап целится в обычный текстовый узел (`<p>`), НЕ по интерактивному
  элементу (иначе сработает guard тап-зон, `bridge-tap-zone-guard`, вне owns
  этого кейса).
- Предварительный скролл вниз — либо через `execute_script("window.scrollTo(0,
  ...)")` (детерминированно, не эмулирует жест), либо тапом по нижней трети
  (см. сиблинг TC-127) как естественная предпосылка — оба варианта легальны,
  выбор за test-automator; `execute_script`-вариант дешевле и не создаёт
  зависимости TC-126 от TC-127.
- Порог допуска дельты — страница не бесконечно длинная, верхняя граница
  скролла (0) не должна быть достигнута ДО тапа (иначе тест вырождается,
  см. предусловие выше); длина филлер-контента общего с AT-BUG-030 узла 3
  (>= 3×`innerHeight`) достаточна с запасом.
- **Инвариант (добровольно, C4 формально не применяется, но пара TC-126/TC-127
  квантифицирует над зоной):** знак `dy` — функция ТОЛЬКО от того, в какую
  треть (верх/низ) пришёлся тап, величина `|dy|` одна и та же
  (`0.95×innerHeight`) для обеих зон; сиблинг TC-127 держит ту же настройку
  ON и варьирует только зону (низ), доказывая, что различие в Then — знак
  дельты, а не наличие эффекта вообще.
- **Ограничение синтетического тапа (тот же класс, что TC-119/120/122,
  AT-BUG-018):** `dispatch_synthetic_viewport_tap` даёт честный hit-testing
  через `document.elementFromPoint` (целевой узел — реальный, не хардкод), но
  событие — синтетический `MouseEvent`/`dispatchEvent`, не Selenium `.click()`
  и не физический нативный тап; `dispatchEvent` бьёт напрямую в
  JS-обработчик `ao3_bridge.js`, минуя нативный Android touch-стек.
