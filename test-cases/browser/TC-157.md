# TC-157 — Гейт infinite-scroll на границе навигации пересчитывается заново на КАЖДОЙ полной загрузке (оба направления переключения)

**Поглощает:** TC-158 (П1 spec-p1-dedup v7, docs/tasks/p1-dedup-lead-pass.md Р2:
«гейт infinite-scroll на границе навигации в двух направлениях тумблера
(ON→OFF→Next и OFF→ON→Next). Механизм один: гейт пересчитывается на КАЖДОЙ
загрузке страницы. Риск отмечаю явно: у направлений разные ожидания
(пагинация видима/скрыта, скролл подгружает/нет), поглощающий кейс обязан
сохранить оба направления отдельными проверками, иначе слияние = потеря
покрытия»). Оба направления ниже сохранены как ПОЛНОСТЬЮ отдельные
Given-When-Then с противоположными Then — ни один из них не выведен из
другого.

## Предусловия
- Приложение запущено с чистыми данными; режим replay; открыта replay
  листинговая страница `listing_paginated.mitm`, страница 1 из 5 (1
  work-блёрб на страницу, нумерованная пагинация скрыта при ON / видима при
  OFF, `Next →` остаётся в обоих случаях).
- Начальное состояние тумблера «Infinite scroll (listing pages)» —
  ПРОТИВОПОЛОЖНОЕ между вариантами (вариант A стартует с ON, вариант B
  стартует с OFF) — это и есть предмет различия, названо явно в Given
  каждого варианта.

## Сценарий (Given-When-Then)

### Вариант A — ON→append→OFF→Next: новая страница загружается БЕЗ подписки (родной сценарий TC-157)

**Given** `infinite_scroll = ON` установлен до навигации; открыта страница 1
`listing_paginated.mitm`

**When** пользователь делает ПРИЦЕЛЬНЫЙ (не до самого низа документа) скролл,
достаточный для ОДНОЙ подгрузки — `ids` после скролла = `['900000001',
'900000002']` (страница 2 добавлена, эвикция/каскад ещё не наступили)
**And** пользователь переходит в Settings и выключает «Infinite scroll
(listing pages)» ПОСЕРЕДИНЕ текущей загрузки, возвращается на ту же (не
перезагруженную) вкладку
**And** пользователь тапает по ссылке «Next →»

**Then** ссылка «Next →» уводит ПОЛНОЙ навигацией (смена `pathname`/query на
`page=2`) — сама навигация штатна для AO3 и не является предметом этого
кейса (расхождение содержимого ссылки — известный отдельный баг BUG-018, не
переопроверяется здесь)
**And** на НОВОЙ (только что загруженной) странице 2 нумерованная пагинация
ВИДИМА (`display != none` у номерных пунктов «1»/«2»/«3») — гейт `:530`
пересчитан заново при инъекции скрипта на этой загрузке и увидел ТЕКУЩЕЕ
(OFF) значение тумблера, а не значение, действовавшее на момент запуска
приложения
**And** дальнейший скролл к концу страницы 2 НЕ подгружает работу страницы 3
— `ol.work.index.group` несёт РОВНО 1 `li[id^="work_"]`, сетевого фонового
запроса не происходит

### Вариант B — OFF→ON→Next: новая страница загружается С подпиской (поглощает TC-158)

**Given** `infinite_scroll = OFF` установлен до навигации; открыта страница 1
`listing_paginated.mitm` (нумерованная пагинация видима, `Next →` доступен)

**When** пользователь переходит в Settings и включает «Infinite scroll
(listing pages)» ПОСЕРЕДИНЕ текущей загрузки страницы 1, возвращается на ту
же (не перезагруженную) вкладку
**And** пользователь тапает по ссылке «Next →»

**Then** нумерованная пагинация на ЭТОЙ (странице 1) загрузке остаётся
видимой — включение тумблера ПОСЕРЕДИНЕ уже загруженной страницы не
подключает подписку ретроактивно (симметричный non-goal TC-129/TC-130,
сторона ON→OFF того же факта проверена вариантом A этого кейса)
**And** тап «Next →» уводит ПОЛНОЙ навигацией на страницу 2
**And** на НОВОЙ странице 2 нумерованная пагинация СКРЫТА (`display:none`) —
гейт `:530` пересчитан заново на этой загрузке и увидел ТЕКУЩЕЕ (ON) значение
тумблера — ПРЯМАЯ ПРОТИВОПОЛОЖНОСТЬ Then варианта A (там на стр.2 пагинация
ВИДИМА, здесь — СКРЫТА)
**And** скролл к концу страницы 2 подгружает следующие страницы фоновым
запросом (без смены `pathname`) — множество `id` блёрбов растёт, что
подтверждает активную подписку на НОВОЙ загрузке — ПРЯМАЯ ПРОТИВОПОЛОЖНОСТЬ
Then варианта A (там скролл НЕ подгружает)

**Инвариант:** гейт `infinite_scroll` — НЕ персистентное per-сессионное
состояние подписки, а значение, считываемое ЗАНОВО при КАЖДОЙ инъекции
скрипта (то есть при каждой полной загрузке страницы листинга); переключение
тумблера ПОСЕРЕДИНЕ уже загруженной страницы не действует на неё
ретроактивно (non-goal TC-129/TC-130) ни в одном направлении (доказано ОБОИМИ
вариантами: A — ON→OFF на текущей загрузке не отключает уже активную
подписку статьи, B — OFF→ON на текущей загрузке не включает подписку задним
числом), но КАЖДАЯ последующая ПОЛНАЯ навигация (в т.ч. через «Next →»)
подхватывает ТЕКУЩЕЕ значение корректно в ОБА направления — свойство
симметрично, вариант A доказывает сторону ON→OFF, вариант B — сторону
OFF→ON; ни один вариант не выводим из другого (Then варианта B — не
логическое отрицание Then варианта A, а отдельно измеренное поведение с
эвикцией/каскадом `PAGE_WINDOW=3`, которого нет в варианте A).

## Заметки для автоматизации
- **Не заблокировано инфраструктурой** — тот же вывод, что TC-129/TC-130:
  `listing_paginated.mitm` уже собран.
- Прицельный скролл (вариант A) — переиспользовать формулу TC-130
  (`Math.max(1, ol.getBoundingClientRect().bottom - (innerHeight +
  SCROLL_MARGIN) + 1)`), не скролл-до-низа: скролл к самому низу рискует
  зацепить каскад/эвикцию (`PAGE_WINDOW=3`) ещё ДО переключения тумблера —
  вне цели варианта A (та же ловушка, что явно названа в TC-130).
- Переключение тумблера (оба варианта) — существующий Settings-степ
  (`settings_steps.disable_infinite_scroll` для A, `settings_steps.
  enable_infinite_scroll` для B, использованы TC-129/TC-130), без
  выгрузки/повторного открытия вкладки Browse (тот же приём document-identity,
  что TC-124 — вкладка не должна быть закрыта/переоткрыта, иначе теряется
  смысл «переключение ПОСЕРЕДИНЕ»).
- Тап «Next →» (оба варианта) — существующий локатор `PAGINATION_NEXT_LINK`
  (`framework/web/selectors.py`, использован TC-129 негативно, здесь — как
  реальное действие); смена `pathname`/query —
  `assert_webview_location_changed` (образец TC-129).
- Нумерованная пагинация видима/скрыта — `assert_pagination_numbered_items_
  visible` (существующий шаг TC-129), применяется в обоих направлениях
  (утверждение видимости в A, отсутствия видимости — как `display:none` — в
  B).
- Негатив «скролл к низу стр.2 не подгружает» (вариант A) — тот же паттерн,
  что TC-129 Then (`assert_work_blurb_count_holds(1)`, `assert_holds_for`
  весь бюджет, не единичное чтение).
- Позитив «скролл на стр.2 подгружает» (вариант B) — переиспользовать
  шаг/ассерт TC-130 (`trigger_infinite_scroll_load`/`assert_infinite_scroll_
  appended_new_unique_blurbs`) без изменений; вариант B НЕ проверяет
  эвикцию как отдельный Then (см. non-goal TC-130) — если каскад дойдёт до
  эвикции внутри бюджета ожидания, это не нарушает Then («множество id
  растёт» держится ассертом роста, не точным числом, тем же способом, что
  TC-130 обходит эту неопределённость).
- Оба варианта — независимые прогоны ОДНОГО параметризованного теста
  (общая фикстура `listing_paginated.mitm`, общий сценарный каркас
  переключить-посреди-загрузки-и-Next, разное начальное/конечное состояние
  тумблера) — не journey/чекпойнты (варианты не мутируют общее состояние
  друг для друга, каждый начинает с чистых данных), секция «Чекпойнты» не
  нужна.
- **Батарея правил-реакций (оценка применимости, справедлива для обоих
  вариантов):** edge-vs-level — ПРИМЕНИМО и это ядро кейса: гейт — предикат,
  вычисляемый заново на событии «загрузка страницы» (не персистентный флаг
  подписки), оба варианта это доказывают с противоположных сторон.
  off-инвариант — покрыт (And-пункт про негатив на стр.2 варианта A; первый
  And-пункт варианта B тоже негативен — пагинация НЕ становится скрытой на
  текущей загрузке). Ретроактивность — н-п в обе стороны: тумблер НЕ
  действует ретроактивно на УЖЕ загруженную страницу ни при ON→OFF (non-goal
  TC-129/TC-130, сторона A), ни при OFF→ON (первый Then варианта B) — оба
  направления сохранены явными Then, не пропущены. Идемпотентность/
  propagation — н-п: нет фонового состояния, разделяемого несколькими
  потребителями (каждая вкладка независима, как в TC-130), справедливо для
  обоих вариантов.
