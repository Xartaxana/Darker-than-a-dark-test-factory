# TC-123 — Tap to scroll OFF: тап по любой трети work-страницы не скроллит и не переключает fullscreen

## Предусловия
- Приложение запущено с чистыми данными; тумблер «Tap to scroll (work pages)» в
  Settings — в состоянии по умолчанию **OFF** (`prefs.tap_to_scroll` отсутствует
  → `false`, `SettingsScreen.kt:76`).
- Открыта replay work-страница (`pathname` соответствует `^/works/\d`); документ
  высокий (>= 3×`innerHeight` — иначе тест диагностически бессилен, см. «Заметки
  для автоматизации», блокер шарится с `bugs/AT-BUG-030.md`).
- **Страница предварительно проскроллена к зафиксированной позиции `scrollY =
  S`, ОБЕИМИ границами: `0.95×innerHeight < S < maxScroll − 0.95×innerHeight`**
  (`maxScroll = document.scrollHeight - innerHeight`). Диапазон непуст при
  высоте документа >= 3×`innerHeight` (узел 3 AT-BUG-030 уже даёт этот запас:
  `maxScroll >= 2×innerHeight`, окно вокруг `S ≈ innerHeight` существует).
  **Без ЭТОГО предусловия негативный Then («`scrollY` не меняется») истинен и
  при корректно работающем гейте, и при СЛОМАННОМ** — если бы `S=0`, вызов
  `scrollBy(-0.95×innerHeight)` от сломанного (пропускающего) гейта клампится
  браузером обратно к 0 и неотличим от «гейт сработал»; симметрично для
  нижней трети при `S=maxScroll`. Фиксация `S` в обоих направлениях — та же
  идея, что собственное предусловие TC-126 («предварительно проскроллена
  ВНИЗ... иначе тап вверх упрётся в границу `scrollY=0`»), и процедура CH-005
  (`exploratory-charters/CH-005.md` R1.3 — скролл к середине ПЕРЕД
  возмущением, R1.6 — тап от зафиксированной непограничной позиции).
- Нижняя панель свёрнута, открыто >=2 вкладок (общие предусловия тап-зон,
  docs/01 §9).
- Приложение НЕ в fullscreen.

## Сценарий (Given-When-Then)

**Given** `tap_to_scroll = OFF`; открыта replay work-страница, документ высокий,
страница предварительно проскроллена к позиции `scrollY = S` (`0.95×innerHeight
< S < maxScroll − 0.95×innerHeight`, см. предусловия — НЕ у верхнего и НЕ у
нижнего края), нижняя панель свёрнута, >=2 вкладки, не fullscreen

**When** пользователь тапает по верхней трети экрана (не по интерактивному
элементу — `<p>`/пустой области тела)

**Then** `window.scrollY` остаётся равным `S` (не меняется) — значимо именно
потому, что `S` НЕ у верхней границы: у сломанного гейта `scrollBy(-0.95×
innerHeight)` дал бы наблюдаемое `scrollY = S - 0.95×innerHeight ≠ S`, не
замаскированное клампом к 0

**When** пользователь тапает по средней трети экрана

**Then** fullscreen не включается (TabStrip остаётся видимым, состояние
`isFullscreen` не переключилось)

**When** пользователь тапает по нижней трети экрана

**Then** `window.scrollY` остаётся равным `S` (не меняется) — симметрично: у
сломанного гейта `scrollBy(+0.95×innerHeight)` дал бы `scrollY = S + 0.95×
innerHeight ≠ S`, не замаскированное клампом к `maxScroll`

**Инвариант:** при `tap_to_scroll=OFF` ни одна из трёх третей work-страницы не
производит наблюдаемого эффекта — единственный гейт (`ao3_bridge.js:1153`)
применяется ДО вычисления координаты тапа, поэтому решение не зависит от того,
в какую треть пришёлся тап. Сиблинги TC-124 (та же зона верх/низ, тумблер ON,
живой push) и TC-126/TC-127/TC-128 (зоны при ON) держат тот же обработчик и
варьируют ТОЛЬКО значение тумблера/зону — совпадение всех остальных условий
делает различие Then приписываемым именно значению тумблера, а не побочному
фактору окружения.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Тумблер `tap_to_scroll` | OFF (дефолт) |
| Стартовая позиция `scrollY = S` | `0.95×innerHeight < S < maxScroll − 0.95×innerHeight` (НЕ у края) |
| Треть 1 (верх) | tap → `scrollY` остался `S` (не `S − 0.95×innerHeight`) |
| Треть 2 (середина) | tap → fullscreen не переключился |
| Треть 3 (низ) | tap → `scrollY` остался `S` (не `S + 0.95×innerHeight`) |

## Заметки для автоматизации
- **Предскролл к позиции `S` — обязательный шаг ДО первого тапа** (доработка
  attempt 2, критик-вход B1): `execute_script("window.scrollTo(0,
  Math.round(window.innerHeight));")` — детерминированное значение `S ≈
  innerHeight` лежит строго внутри окна `(0.95×innerHeight, maxScroll −
  0.95×innerHeight)` при высоте документа >= 3×`innerHeight` (узел 3
  AT-BUG-030 гарантирует `maxScroll >= 2×innerHeight`, так что `innerHeight`
  всегда в допустимом диапазоне с запасом). Тот же приём предскролла, что уже
  несёт TC-126 (предпосылка «страница проскроллена вниз... `S >
  0.95×innerHeight`») и измеренная процедура CH-005 R1.3 («скролл к середине,
  зафиксирован видимый маркер») — не изобретается заново для этого кейса.
  Сверка после предскролла — `execute_script("return window.scrollY;")` перед
  первым `When`, само значение `S` попадает в отчёт автотеста для
  воспроизводимости.
- **Блокер автоматизации разделён с `bugs/AT-BUG-030.md` (не заводится новый
  тикет — правило 4 воркфлоу test-designer: перед заведением проверить
  существующие покрывающие баги; этот и есть тот случай).** Текущий
  `recording_builder.py::render_work_page_html` короче `innerHeight` — без
  фикса узла 3 (высота >= 3×`innerHeight`, уже часть критерия готовности
  AT-BUG-030) тест диагностически бессилен: `scrollBy` от `scrollY=0` при
  короткой странице и так остаётся на 0 независимо от того, сработал ли гейт
  тумблера — негативный Then был бы истинен ВСЕГДА, даже если бы `OFF` не
  гасил эффект (тот же класс проблемы, что у TC-119/TC-120). Кейс добавлен в
  `test_cases` `AT-BUG-030.md` этим же ходом (узел 3, НЕ узлы 1/2 — тем не
  нужны для этого кейса).
- До готовности фикстуры кейс остаётся `status: Review` (не `Blocked`) — тот
  же паттерн, что TC-115/TC-119/TC-120 (`schemas/transitions.yaml`, `test-case
  initial: [Draft, Review]`).
- Средняя треть (fullscreen) проверяется тем же пиксельным прокси, что TC-058
  (`top_chrome_avg_luma` / видимость `TabStrip`), не accessibility-состоянием
  системных баров.
- Тап по координате — стандартный W3C-actions клик по точке `(x, third_y)`
  внутри WebView; целиться в текстовый узел (`<p>`), не в `<a>`/`<button>` —
  иначе guard тап-зон (canary-область `bridge-tap-zone-guard`, вне owns этого
  кейса) исказит результат независимо от значения `tap_to_scroll`.
