# TC-124 — Tap to scroll ON: включение тумблера действует без перезагрузки страницы и переживает reload темы

## Предусловия
- Приложение запущено с чистыми данными; тумблер «Tap to scroll (work pages)» —
  OFF (дефолт).
- Открыта replay work-страница, документ высокий (>= 3×`innerHeight` — общий
  блокер с `bugs/AT-BUG-030.md`, узел 3).
- Нижняя панель свёрнута, >=2 вкладки, не fullscreen.

## Сценарий (Given-When-Then)

**Given** `tap_to_scroll = OFF`; work-страница уже открыта в активной вкладке
(НЕ будет перезагружаться/заново навигироваться в течение сценария, кроме
явного reload от темы на втором шаге)

**When** пользователь переходит в Settings, включает тумблер «Tap to scroll
(work pages)» и возвращается на ту же (не перезагруженную) вкладку, затем
тапает по нижней трети экрана

**Then** страница скроллится вниз (`window.scrollY` увеличивается на величину,
согласующуюся с `0.95 × innerHeight`, с учётом верхней границы документа) — эффект
применился БЕЗ reload и БЕЗ повторной навигации, то есть именно реактивным
push (`LaunchedEffect(tapToScroll)`), а не переинъекцией при загрузке страницы

**When** пользователь возвращается в Settings и переключает тему на Dark
(вызывает `wv.reload()` для существующих WebView), возвращается на ту же
вкладку и тапает по нижней трети ещё раз

**Then** страница снова скроллится вниз — тумблер пережил reload (реинъекция
`window.__ao3TapToScroll=true` в `onPageFinished`, `BrowserScreen.kt:603`, а не
сброс к дефолту `false`)

**Инвариант:** значение `window.__ao3TapToScroll` на живой WebView всегда равно
текущему значению тумблера Settings в течение сессии — синхронизация
достигается ЛИБО реактивным push для уже открытых вкладок (первый When), ЛИБО
инъекцией при (пере)загрузке страницы (второй When), и наблюдаемый эффект тапа
идентичен независимо от того, какой из двух путей синхронизации сработал.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| `tap_to_scroll` до | OFF |
| `tap_to_scroll` после включения (без reload) | ON — тап скроллит |
| `tap_to_scroll` после reload темы | ON — тап всё ещё скроллит |

## Заметки для автоматизации
- **Блокер общий с `bugs/AT-BUG-030.md`** (узел 3, высота документа) — тот же
  класс, что TC-123/TC-126/TC-127; кейс добавлен в `test_cases` этого бага этим
  же ходом, отдельный тикет не заводится.
- Переключение темы Dark — переиспользует шаг из TC-047/TC-050 (`select_theme`/
  контраст-иконка); важно, чтобы шаг НЕ закрывал и не открывал заново саму
  work-вкладку (иначе second When теряет смысл — стал бы неотличим от обычной
  инъекции при первой загрузке).
- Чтение `window.scrollY` — тот же паттерн, что уже используется в
  `framework/steps/browser_steps.py` (`execute_script("return window.scrollY;")`,
  строки ~161-164) для табов; для work-страницы новый шаг переиспользует ту же
  идею.
- Новый Settings-степ «включить тумблер Tap to scroll» — рутинная
  автоматизация по образцу `set_hide_rating`/`set_auto_download`
  (`framework/steps/settings_steps.py`), не инфраструктурный блокер.
