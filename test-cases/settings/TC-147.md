# TC-147 — Позиция side panel: обе стороны зеркалятся, персистятся и пишут одни prefs

## Предусловия
- Приложение запущено с чистыми данными, `panel_side = LEFT` (дефолт), на
  вкладке Browse открыта страница AO3, side panel виден свёрнутым (handle на
  левом крае).
- Открыт экран Settings, виден ряд «Side panel» с кнопками «Left»/«Right».
- Режим прогона: replay либо live-smoke.

## Сценарий (Given-When-Then)

**Given** `panel_side = LEFT`, handle side panel («Expand panel») виден на
левом крае экрана Browse

**When** пользователь в Settings выбирает «Right», возвращается на Browse,
раскрывает панель (по content-desc «Expand panel», НЕ по координате центра —
см. ловушку в заметках) и переключает тему на Dark и увеличивает шрифт
кнопкой «A+»

**Then** handle side panel отображается на ПРАВОМ крае экрана (зеркальная
позиция, тот же размер 32×32 px, та же вертикальная координата, что и слева);
раскрытая панель с правого края реагирует на тапы (тема и шрифт меняются)
**And** значения `theme_mode`/`font_size_step`, записанные из правой позиции,
совпадают с тем, что писала бы панель из левой позиции (тот же общий
`SharedPreferences`, что TC-054) — Settings отражает Dark и увеличенный шрифт

**When** пользователь полностью перезапускает приложение (kill + relaunch,
`force-stop`, НЕ `pm clear`)

**Then** `panel_side` остаётся RIGHT после рестарта — handle снова на правом
крае, позиция не сбросилась к дефолту

**When** пользователь возвращает позицию на «Left» в Settings, перезапускает
приложение ещё раз

**Then** handle снова на левом крае, позиция RIGHT->LEFT также пережила
рестарт — обе позиции симметрично персистентны, а не только дефолтная LEFT

**Инвариант:** `panel_side` — двухпозиционная настройка (LEFT/RIGHT), для
КАЖДОЙ из двух позиций одновременно верно: (1) handle и раскрытая панель
зеркалятся геометрически без потери кликабельности; (2) панель пишет ТЕ ЖЕ
prefs (`theme_mode`, `font_size_step`), что и из другой позиции; (3) позиция
переживает kill+relaunch — ни одно из трёх свойств не проверено только для
LEFT (дефолт), проверка симметрична для RIGHT->LEFT так же, как LEFT->RIGHT.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Контрол | `PanelSideRow` на экране Settings, LEFT/RIGHT |
| Геометрия (измерено CH-005) | handle 32×32 px, x=5 (LEFT) <-> x=1043 (RIGHT), тот же `y` |
| Персистентность | переживает `force-stop` + relaunch в ОБЕИХ позициях |
| Prefs | `theme_mode`, `font_size_step` — идентичны независимо от позиции |

## Заметки для автоматизации
- **Ловушка локатора (CH-001, подтверждена CH-005, повторена в заметках
  TC-059):** тап по координате центра заявленной clickable-области handle
  НЕ отзывчив (проваливается в WebView) — надёжен только тап по узлу с
  content-desc «Expand panel»/«Collapse panel» (`find_element` по
  content-desc, не coordinate-тап по центру bounds). Одинаково применимо к
  ОБЕИМ позициям (LEFT и RIGHT) — content-desc не меняется при зеркалировании.
- Персистентность — `adb shell am force-stop` + relaunch (не `pm clear`,
  иначе сотрутся все настройки, не только позиция) — тот же приём, что
  TC-051.
- Измерение геометрии (x=5/x=1043, размер 32×32, тот же `y`) — из CH-005,
  живой замер на эталонном AVD; таргет-плотность density см. docs/01 §9
  (дублировать сюда не нужно, эталон уже зафиксирован там).
- Блокера автоматизации нет: навигация Settings, kill+relaunch,
  content-desc-локатор и чтение `SharedPreferences`/визуальной позиции —
  существующие примитивы (TC-051, TC-054, TC-059).
- **Non-goal явно (не молчаливое исключение):** комбинация «поворот экрана ×
  `panel_side`» НЕ входит в этот кейс — измерено docs/01 §9 как блокер среды
  (эмулятор `ao3_test_api34` отклоняет программную смену ориентации через
  UiAutomator2), пересекается с TC-111 (E3); отдельного кейса под поворот
  эта область не требует (решение уже зафиксировано в §9, не изобретаю
  заново).
