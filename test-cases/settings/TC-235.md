# TC-235 — Контрол формата загрузки: применение и персистентность

## Предусловия
- Приложение запущено с чистыми данными, дефолт формата — HTML (эталонный
  AVD, `Build.MANUFACTURER != "ONYX"` — граница чёрного ящика, EPUB-дефолт
  на ONYX-устройствах здесь не проверяется).

## Сценарий (Given-When-Then)

**Given** формат загрузки — HTML (дефолт на AVD), Settings открыт

**When** пользователь переключает сегментированный контрол на EPUB — БЕЗ
перезапуска приложения открывает работу и скачивает её; затем перезапускает
приложение (kill+relaunch) и снова открывает Settings

**Then** скачивание, выполненное СРАЗУ после переключения (без рестарта),
уже идёт в формате EPUB (см. TC-236 для деталей эффекта скачивания)
**And** после перезапуска сегментированный контрол в Settings по-прежнему
показывает выбранным EPUB — выбор пережил рестарт

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Дефолт (AVD) | HTML |
| Выбор | EPUB |
| Ожидаемое поведение | применяется без рестарта, переживает рестарт |

## Заметки для автоматизации
- Граница чёрного ящика (называется явно, не блокер): ONYX-дефолт (EPUB по
  умолчанию) на эталонном AVD не воспроизводим — `Build.MANUFACTURER`
  подменить чёрным ящиком нельзя; здесь проверяется только явное
  переключение пользователем, не вычисляемый дефолт.
- Сам факт «скачивание пошло в EPUB» — см. TC-236 (там же и фикстурный
  долг на скачивание). Для ЭТОГО кейса достаточно косвенного наблюдения
  (например, расширение сохранённого файла или MIME при открытии) без
  необходимости фиксировать все детали.
