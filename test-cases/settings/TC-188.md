# TC-188 — Show copy-URL button: обе стороны, live-переключение без reload, кнопка не перекрыта тап-зонами

## Предусловия
- Приложение запущено с чистыми данными, replay-режим (`work_with_download.mitm`
  или `listing_basic.mitm` — любая работающая work-страница).
- Тумблер «Show copy-URL button» в Settings — дефолт **OFF**.
- `tap_to_scroll` — **ON** (нужно для последней грани Then — guard тап-зон).

## Сценарий (Given-When-Then)

**Given** тумблер «Show copy-URL button» — OFF, открыта replay work-страница

**Then** плавающая кнопка «Copy URL» (`position:fixed; bottom:12px;
left:12px`) НЕ ВИДНА пользователю (узел присутствует в DOM с
`display:none` — это деталь реализации; наблюдаемый Then — кнопка
недоступна для тапа/не видна на скриншоте/`is_displayed()==False`)

**When** пользователь, НЕ покидая эту же страницу, переключает тумблер
«Show copy-URL button» в ON (через side panel/Settings, без reload
WebView)

**Then** кнопка «Copy URL» появляется НЕМЕДЛЕННО, без перезагрузки страницы
(`window.setDebugCopyUrl` вызывается реактивно, `BrowserScreen.kt:182`) —
наблюдаемо как переход `is_displayed()` False→True БЕЗ промежуточной
навигации/reload маркера

**When** пользователь тапает по кнопке «Copy URL»

**Then** (наблюдаемое ЯДРО, автоматизируемое; переформулировано по решению
ESC-032 путь (б.1)) клик доходит до DOM-узла кнопки, и `navigator.clipboard.
writeText(location.href)` реально ВЫЗЫВАЕТСЯ — позитивное свидетельство
вызова в ТЕКУЩЕЙ тестовой среде (`ao3_test_api34`, System WebView Chromium
113.0.5672.136): `driver.get_log('browser')` содержит `DOMException: Write
permission denied` — это исключение ДОКАЗЫВАЕТ, что исполнение дошло до
Clipboard API (не вакуумный негатив: есть позитивный артефакт-якорь в
логе, не отсутствие сигнала). **На среде, где запись в буфер РАЗРЕШЕНА,
тому же ядерному факту («вызов состоялся») соответствует ОТСУТСТВИЕ этого
исключения в логе — формулировка Then не ломается при смене WebView/AVD-
образа.**
**Then** (продуктовый контракт; НЕ ассертится в текущей среде — заблокировано
`bugs/AT-BUG-068.md`, критерий готовности «Fixed» не закрыт: путь (а)
архитектурно недостижим на этом AVD — `DOMException` бросается permission-
слоем Blink ДО Android `ClipboardManager`, appops-слой не участвует) подпись
кнопки меняется на «Copied!», спустя ~1.5с возвращается к «Copy URL», и URL
реально оказывается в буфере обмена — верификация этой части откладывается
до независимого изменения тестовой среды (иной WebView/AVD-образ),
критерий готовности `bugs/AT-BUG-068.md`
**And** та же ошибка на проде глотается МОЛЧА (`bugs/BUG-069.md`):
`ao3_bridge.js:1077-1080` не несёт `.catch()`, поэтому на устройствах с
аналогичным ограничением Clipboard API пользователь не получает НИКАКОЙ
обратной связи — кнопка навсегда остаётся «Copy URL» без индикации отказа;
после фикса BUG-069 (добавление `.catch()` с UI-фидбеком) у кейса появится
наблюдаемый error-путь («Copy failed» или аналог) — кандидат на доработку
продуктового Then выше при верификации BUG-069
**And** (грань `nf-a11y-interactive-overlap`) тап по кнопке НЕ запускает
зональный эффект `tap_to_scroll` (страница не скроллится, fullscreen не
переключается), несмотря на то, что кнопка физически может лежать в
верхней/нижней трети экрана — узел `<button>` входит в whitelist guard'а
тап-зон (`ao3_bridge.js:1155`), тот же контракт, что уже верифицирован
TC-119 на другом `<button>`-узле

**When** пользователь переключает тумблер обратно в OFF (та же страница,
без reload)

**Then** кнопка «Copy URL» немедленно скрывается

**Инвариант:** видимость кнопки полностью определяется ТЕКУЩИМ значением
тумблера в любой момент на любой открытой странице — переключение не требует
навигации/reload, и оба направления (показать/скрыть) симметрично мгновенны.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Тумблер (дефолт) | OFF |
| Кнопка при OFF | не видна |
| Кнопка при ON | видна |
| Тап (ядро, автоматизируемо) | клик доходит до узла, `writeText` вызывается (`DOMException` в browser log — позитивный якорь в текущей среде) |
| Тап (продукт, deferred) | «Copied!» → «Copy URL» ~1.5с, URL в буфере — НЕ ассертится в этой среде, `bugs/AT-BUG-068.md` |
| Тап при `tap_to_scroll=ON` | зональный эффект НЕ срабатывает |

## Заметки для автоматизации
- Локатор тумблера — рутинный XPath `following::` по образцу
  `_TAP_TO_SCROLL_SWITCH`/`_AUTO_DOWNLOAD_SWITCH`
  (`settings_screen.py:91-132`): `(//*[@text="Show copy-URL button"]/
  following::*[@checkable="true"])[1]` — секция DEBUG идёт ПОСЛЕДНЕЙ на
  экране, `swipe_to_text` перед поиском обязателен (тот же паттерн, что
  `is_tap_to_scroll_checked`).
- Кнопка «Copy URL» — обычный WebView-элемент, видимость через `contexts.
  in_webview` + `execute_script("return getComputedStyle(document.
  querySelector('button')).display")` ЛИБО через сам `is_displayed()`
  Selenium/Appium по `by_xpath`/тексту «Copy URL» внутри WebView-контекста —
  выбор конкретного приёма (JS vs Appium-локатор) на усмотрение реализации,
  оба технически достижимы (кнопка — обычный DOM-узел, не Shadow DOM).
- **Ядро (автоматизируемо сейчас):** факт вызова `writeText` — поллинг
  `driver.get_log('browser')` на запись `DOMException: Write permission
  denied` (позитивный артефакт-якорь в текущей среде) ЛИБО, на среде без
  этого ограничения, поллинг подписи узла на «Copied!» — приём
  `wait_until`/`assert_holds_for`, НЕ `sleep(1.5)`.
- **Продуктовый контракт (deferred, НЕ реализовывать в этой среде):**
  подпись «Copied!»/таймер 1.5с/содержимое буфера — заблокировано
  `bugs/AT-BUG-068.md` (`type: test_debt`, `debt_kind: broken_environment`,
  `blocked_reason: environment`, критерий готовности «Fixed» не закрыт).
  Блокер УЖЕ заведён этим тикетом — новый test_debt-баг заводить не нужно
  (сверено: единственный покрывающий тикет, `test_cases: ["TC-188"]`).
- Связанный продуктовый баг: `bugs/BUG-069.md` (`ao3_bridge.js:1077-1080`
  без `.catch()` — молчаливый отказ кнопки на устройствах с тем же
  ограничением Clipboard API). После его фикса у кейса появится
  наблюдаемый error-путь — кандидат на доработку продуктового Then (см.
  `And` в сценарии).
- Guard тап-зон — переиспользовать ПРИЁМ TC-119 (координатный/синтетический
  тап по known bounding rect кнопки, проверка ОТСУТСТВИЯ скролла/fullscreen
  через уже существующие `assert_scroll_unchanged`/
  `assert_top_chrome_not_darkened`), не копировать сам тест — здесь другой
  целевой узел (инжектированная кнопка, не фикстурный `data-tap-marker`).
- **Не требует `bugs/AT-BUG-030.md`** — кнопка «Copy URL» инжектируется
  `ao3_bridge.js` НЕЗАВИСИМО от `render_work_page_html` (не является одним
  из узлов 1/2/3 того бага), присутствует на ЛЮБОЙ replay work-странице уже
  сейчас — блокера нет.
