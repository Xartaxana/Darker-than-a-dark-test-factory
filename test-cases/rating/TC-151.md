# TC-151 — Deselect на панели work-страницы сохраняет downloadPath/тег/заметку скачанной работы

## Предусловия
- Работа W (`ao3_id 900000001`) засеяна с ОТЛИЧАЮЩИМИСЯ от фикстурной страницы
  метаданными (`title="ЛОКАЛЬНЫЙ заголовок"`, `fandom="Мой фандом"`,
  `wordCount=777777`) и уже скачанным файлом (`downloadPath` указывает на
  реально существующий файл на диске) — рейтинг `SAVE` (Favorite).
- Через панель work-страницы к строке добавлены личная заметка `"note A"` и
  личный тег `"tagA"` (панель, ветка `existing != null`, `existing.copy(...)`,
  `downloadPath` при этой достройке не тронут) — итоговая строка: `rating=SAVE,
  comment="note A", tags=["tagA"], downloadPath != null`, метаданные локальные.
- Открыта страница работы `/works/900000001`, панель `RatingMenu` раскрыта и
  показывает Favorite выбранным.
- Режим replay (`listing_basic.mitm`); тумблер `auto_download_saved` выключен
  (не влияет на этот сценарий, но сверяется, чтобы не спутать эффект с BUG-014).

## Сценарий (Given-When-Then)

**Given** работа W скачана, имеет рейтинг Favorite, личную заметку `"note A"`
и личный тег `"tagA"`; панель work-страницы раскрыта, Favorite показан
выбранным

**When** пользователь повторно нажимает уже выбранную кнопку Favorite на
панели (deselect)

**Then** рейтинг снимается (`rating → null`), но строка `work_ratings` НЕ
удаляется (выживает благодаря непустым `comment`/`tags`/`downloadPath`)
**And** `downloadPath` остаётся НЕИЗМЕННЫМ — тем же путём на тот же файл
**And** личный тег `"tagA"` и заметка `"note A"` остаются без изменений
**And** `title`/`fandom`/`wordCount` остаются ЛОКАЛЬНЫМИ значениями (НЕ
перезаписываются скрейпом страницы — ветка `existing.copy` их не трогает)
**And** работа исчезает из вкладки FAVORITE Library, но продолжает быть видна
на вкладке FILES с иконкой «Open downloaded» (строка жива, файл цел)

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа W | `ao3_id 900000001`, локальные `title/fandom/wordCount`, отличные от фикстурной страницы |
| Заметка | `"note A"` |
| Тег | `"tagA"` |
| downloadPath | реальный файл на диске (внутренняя песочница сидинга, `seed_db.seed_with_download`) |

## Заметки для автоматизации
- **Companion-кейс TC-152** (та же операция, дверь overlay листинга вместо
  панели) — пара образует door-parametrized сравнение из follow-up CH-008
  («личные ТЕГИ и downloadPath переживают снятие рейтинга … параметризовать
  по ДВЕРИ»). Этот кейс — ПОЗИТИВНАЯ (не-красная) половина пары: панель
  сохраняет всё, это и есть измеренный CH-008 контроль (находка 5, R3/R4).
- **БЛОКЕР (test_debt) для чистой автоматизации** — заведён
  `bugs/AT-BUG-046.md` в этом же ходе: (а) `seed_db.read_work_ratings()`
  (`framework/data/seed_db.py:234-`) не отдаёт `title`/`author`/`downloadPath`
  — ассерт по ВСЕМ полям строки, который требует этот кейс, нуждается либо в
  расширении функции, либо в собственном SELECT (образец —
  `exploratory-charters/attachments/CH-008/` пробы); (б) `seed_with_comment`/
  `seed_with_download` не умеют засеять комбинацию `comment`+`tags`+
  `downloadPath` ОДНОЙ строкой (взаимно перезаписывают друг друга,
  `INSERT OR REPLACE`) — baseline из предусловий строится ДВЕРЯМИ панели под
  измерением (как в CH-008), что делает сетап кейса зависимым от panel-write
  пути, который сам частично является предметом проверки. `test_cases:
  [TC-151, TC-152, TC-155]` в баге.
- Построение baseline — по образцу CH-008 seed 1 (`R2`/`R3`): `seed_with_download`
  для базовой строки (rating=SAVE, downloadPath, локальные метаданные) →
  панель → добавить заметку → снимок → панель → добавить тег → снимок
  (baseline A).
- Deselect на панели — существующий `rating_steps.rate_current_work(driver,
  "SAVE")` повторно (тот же приём, что TC-008/TC-016).
- Видимость на FILES — `library_steps.assert_work_in_tab(driver, work,
  tab="FILES")` + иконка `by_desc("Open downloaded")` (образец TC-035).
- Область НЕ комбинаторная (точечный сценарий одной двери/точки кода —
  панель × deselect, не фильтр/сортировка/рейтинг-видимость/backup/tabs/
  темы) — строка `Инвариант:` не требуется (тот же прецедент формулировки,
  что TC-115).
- Область НЕ содержит правило-реакцию в смысле батареи CLAUDE.md (deselect —
  прямое пользовательское действие, не авто-триггер на событие/условие) —
  батарея правил-реакций не применяется, н-п.
