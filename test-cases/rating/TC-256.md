# TC-256 — Дочитывание скачанной работы без рейтинга проставляет READ, сохраняя downloadPath и локальные метаданные

## Предусловия
- Работа W (`ao3_id 900000001`, baseline A — тот же приём, что TC-151/TC-152)
  засеяна `seed_db.seed_with_comment_and_download` ОДНОЙ строкой:
  `rating=None`, личная заметка `"note A"`, личный тег `"tagA"`, локальные
  `title="ЛОКАЛЬНЫЙ заголовок"`, `fandom="Мой фандом"`, `wordCount=777777`
  (нарочно ОТЛИЧАЮТСЯ от канонических значений фикстурной work-страницы —
  `"A Loved Test Work"`/`"Fandom Alpha"`/`4200`), реальный скачанный файл на
  диске (`downloadPath` указывает на него).
- Открыта страница работы `/works/900000001` (`rating_steps.open_work_page`),
  режим replay (`listing_basic.mitm`, тот же baseline-flow, что TC-151/TC-152).
  **Работа НЕ имеет рейтинга** — RatingMenu панели показывает НИЧЕГО
  выбранным.
- **Предпосылка фикстуры (БЛОКЕР, см. «Заметки для автоматизации»):**
  work-страница несёт `<div id="chapters">` с `.userstuff.module`-контентом
  (для срабатывания JS auto-mark-as-read), `dd.fandom a` и `dd.words`
  (реальные узлы, которые скрейпит `onScroll`, отличные от preface-only
  `h5.fandom.tags`, которую `render_work_page_html` несёт сегодня) — на
  момент дизайна этого кейса фикстура их НЕ содержит (`AT-BUG-074`).

## Сценарий (Given-When-Then)

**Given** работа W скачана (`downloadPath` на реальный файл), рейтинг НЕ
выставлен, личная заметка `"note A"` и тег `"tagA"` присутствуют, локальные
`title`/`fandom`/`wordCount` отличаются от live-страницы; страница работы
открыта, конец `#chapters` ещё не виден в вьюпорте

**When** пользователь скроллит страницу работы до конца — последний
`.userstuff.module` внутри `#chapters` целиком попадает в вьюпорт и ссылки
«Next Chapter →» на странице нет (одностраничная работа) — JS-обработчик
`onScroll` (`ao3_bridge.js:1184-1194`) скрейпит `title`/`author`/`fandom`/
`wordCount` со страницы и вызывает `Ao3JsBridge.onWorkFinished`

**Then** рейтинг работы W становится `READ`
**And** `downloadPath` остаётся НЕИЗМЕННЫМ — тем же путём на тот же файл на
диске (связь строка↔файл не рвётся операцией, которая файла не касается)
**And** личная заметка `"note A"` и тег `"tagA"` остаются без изменений
**And** `title`/`fandom`/`wordCount` остаются ЛОКАЛЬНЫМИ значениями — скрейп
со страницы их НЕ перезаписывает (`backfillMetadata` дозаполняет только
ПУСТЫЕ поля; у этой строки все три уже непустые)
**And** работа продолжает быть видна на вкладке FILES Library (файл цел,
`downloadPath` жив) И появляется на вкладке READ (новый рейтинг)

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа W | `ao3_id 900000001`, локальные `title/fandom/wordCount`, отличные от фикстурной страницы |
| Заметка | `"note A"` |
| Тег | `"tagA"` |
| downloadPath | реальный файл на диске (`seed_db.seed_with_comment_and_download`) |
| rating (Given) | `null` |
| rating (Then) | `READ` |

## Заметки для автоматизации

- **БЛОКЕР (test_debt) — заведён `bugs/AT-BUG-074.md` в этом же ходе.**
  `framework/data/recording_builder.py::render_work_page_html` (потребитель —
  `listing_basic.mitm`, та же запись, что использует Given TC-151/TC-152) не
  несёт: (а) `<div id="chapters">`/`.userstuff.module` — без него JS-хук
  `onScroll` выходит на `:1171` (`if (!chaptersDiv) return`), событие не
  собирается ВООБЩЕ (сверено `CH-008` находка 8, `PERTURBATIONS.md:503-513` —
  `#chapters=False` измерено живым прогоном, а не только чтением кода); (б)
  `dd.fandom a`/`dd.words` — `onScroll` скрейпит ИМЕННО эти узлы (`ao3_bridge.
  js:1191-1192`), а не preface `h5.fandom.tags`, которую функция несёт сегодня
  для листинга/download-flow. Сосед `render_work_metadata_page_html`
  (AT-BUG-061) уже несёт `dd.fandom.tags a`/`dd.words` для ДРУГОГО потребителя
  (`SettingsScreen.fetchAo3WorkPage`) — образец разметки для переиспользования,
  не готовая фикстура (не несёт `#chapters`, замкнута на другой URL-паттерн
  `works/<id>?view_adult=true`). Без фикстуры сценарий физически недостижим ни
  в replay, ни безопасно на живом AO3 (синтетический `ao3_id 900000001` не
  существует на реальном archiveofourown.org — класс `AT-BUG-029`/калибровки
  Lead 2026-07-30, «синтетические id на живом AO3 дают 404»). `test_cases:
  ["TC-256"]` в баге.
- **Наблюдаемость Then про `downloadPath`/`timestamp`:** оба поля читаются
  НАПРЯМУЮ из Room (`seed_db.read_work_ratings_full()`, AT-BUG-046) — не
  вакуумно-зелёный класс `AT-BUG-029`/калибровки Lead 2026-07-30 (эффект —
  запись в БД, не полагается на короткое замыкание сетевого штатного кода).
  При автоматизации использовать различающий оракул `timestamp` (тот же приём,
  что требование [2]/O1 `TC-152.md`) — инвариантный ассерт «поле осталось тем
  же значением» даёт ложно-зелёный результат, если `onScroll`/upsert вообще не
  сработал (например, геометрия фикстуры не привела нижнюю границу
  `.userstuff.module` в вьюпорт).
- **Companion-класс TC-151/TC-152** (тот же класс дефекта — «пересборка
  `WorkRating` конструктором теряет `downloadPath`/метаданные», BUG-021/
  BUG-048/BUG-067) — но ДРУГАЯ дверь: не пользовательский тап по рейтингу, а
  JS-событие дочитывания (`Ao3JsBridge.onWorkFinished`). ESC-026 (R1) явно
  называет этот сайт НЕ закрытым партией TC-151/TC-152 — этот кейс закрывает
  именно его.
- **Область не комбинаторная** (точечный сценарий одной двери/точки кода —
  onWorkFinished, не фильтр/сортировка/рейтинг-видимость/backup/tabs/темы) —
  строка `Инвариант:` не требуется (тот же прецедент формулировки, что
  TC-115/TC-151/TC-152).
- **Батарея правил-реакций (CLAUDE.md, калибровка №4)** — область содержит
  правило-реакцию («на событии E [дочитывание] при условии C [`rating==null`]
  — побочный эффект S [проставить READ + записать метаданные]»):
  - **edge vs level**: единственный триггер этого правила — само JS-событие
    «дочитано» (нет отдельного «пересохранения без перехода» пути в рамках
    ЭТОГО кейса, в отличие от BUG-014-класса с общим save-путём); повторное
    срабатывание на УЖЕ `READ`-работе — см. пункт «идемпотентность» ниже, не
    здесь.
  - **ретроактивность включения**: **н-п** — правило безусловно активно для
    ЛЮБОЙ работы с `rating==null`, независимо от того, когда она была
    скачана/оценена; нет отдельного «состояния до/после включения»
    (в отличие от, например, `settings-auto-download-favorite`).
  - **off-инвариант**: **н-п** — у механизма НЕТ тумблера ON/OFF в Settings
    (в отличие от `settings-auto-download-favorite`/`background-auto-kudos-
    trigger`); условие срабатывания — только `existing?.rating == null`
    (код-константа, не пользовательская настройка).
  - **идемпотентность**: гвард `if (existing?.rating != null) return@launch`
    (`BrowserViewModel.kt:1296`, НЕ тронут фиксом BUG-067 — существовал и в
    дефектной версии) не даёт повторному срабатыванию `onScroll` (например,
    после скролла вверх-вниз ещё раз) переписать уже проставленный `READ`.
    Этот гвард — самостоятельная грань поведения, независимая от предмета
    ЭТОГО регресс-замка (потеря `downloadPath`/метаданных при ПЕРВОМ
    срабатывании), отдельный кейс на неё вне скоупа этого дизайн-хода
    (регрессия BUG-067 не переопределяла этот гвард) — **н-п: за пределами
    мандата этого хода** (регрессионный кейс на конкретный фикс, не полный
    аудит области); кандидат для отдельного дизайн-прохода, см. отчёт.
  - **propagation**: код фикса вызывает `refreshActiveTabRating`/
    `broadcastRatingChange` (`:1321-1323`) — рассылка в открытые вкладки
    (класс BUG-012). Отдельный сценарий с ДВУМЯ открытыми вкладками требует
    собственного Given/When — **н-п: за пределами мандата этого хода**
    (кандидат для отдельного дизайн-прохода по области `bridge-badge-sync-
    multi` применительно к auto-READ, см. отчёт).
- **`features` — связь ПРИБЛИЗИТЕЛЬНАЯ** (тот же приём, что область
  `performance`, см. `test-cases/README.md`): `rating-metadata-backfill-
  blank-only` описывает ТОТ ЖЕ код-механизм (`backfillMetadata`, копирование
  вместо пересборки), но её title буквально говорит «с листинга»
  (`applyRating:846-855`/`:893-903`) — ДРУГАЯ дверь, чем `onWorkFinished`
  этого кейса. Реестр не несёт отдельной записи под дверь `onWorkFinished`
  (проверено — ни `chapters`, ни `onWorkFinished`, ни «дочит»/«auto-read» не
  встречаются в `docs/feature-registry.yaml`). Не заявление, что этот кейс
  проверяет Then записи `rating-metadata-backfill-blank-only` целиком —
  находка для test-strategist (владелец реестра) вынесена в отчёт отдельным
  пунктом.
