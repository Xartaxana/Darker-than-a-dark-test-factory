# TC-192 — Первая оценка orphan-строки заполняет пустые метаданные и делает работу видимой в фильтре по фандому

## Предусловия
- ДО скана в Room засеяны (`seed_db.seed`) ДВЕ БРАКЕТИРУЮЩИЕ референсные
  работы, рейтинг Favorite (`SAVE`): `PENDING` (`framework/data/works.py`,
  `ao3_id 900000004`, `wordCount=12000`) и `KUDOSED` (`ao3_id 900000002`,
  `wordCount=1500`). Их word count окружает канонический `wordCount=4200`
  работы W (`12000 > 4200 > 1500`) — критик-вход rework (B2): без соседей
  единственная работа в списке даёт тривиальную позицию независимо от
  значения; с бракетирующими соседями позиция после backfill становится
  различимым оракулом (см. Then). Строки W в `work_ratings` пока нет.
- В папку загрузок устройства (SAF Download) ДО скана положен orphan
  HTML-файл, чьё имя оканчивается на `_900000001.html`
  (`app_steps.place_file_in_download_folder`, `WORK_ID_PATTERN` —
  `DownloadRepository.kt:182`).
- Тумблер `auto_download_saved` ВЫКЛЮЧЕН (сверен в prefs — тот же образец,
  что TC-151/TC-152): переход `null → SAVE` при первой оценке взводит
  `onRatingTransition` (`BrowserViewModel.kt:788-790`), который при
  включённом тумблере запускает `downloadWork` — посторонний вызов уронил бы
  Then «downloadPath неизменен» по несвязанной причине.
- В Settings нажата «Scan for downloads» (ручной триггер, `saf_steps.
  tap_settings_action(driver, "Scan")`) — приложение находит файл и
  создаёт STUB-строку `work_ratings` (`ao3Id=900000001`, `title=""`,
  `author=""`, `downloadPath=<путь файла>`, `rating=null`, `fandom=null`,
  `wordCount=null` — `DownloadRepository.kt:119-131`, ветка `existing ==
  null`); диалог результата скана подтверждён и закрыт.
- Открыт листинг (replay `listing_basic.mitm`,
  `recording_builder.LISTING_BASIC_URL`), содержащий блёрб той же работы
  (`ao3_id 900000001`, каноническая карточка `title="A Loved Test Work"`,
  `fandom="Fandom Alpha"`, `wordCount=4200` — листинг статичен, не знает о
  пустой Room-строке).
- До оценки работа НЕ найдена в фильтр-панели по фандому: список фандомов не
  содержит `"Fandom Alpha"` (поле `fandom` пока `NULL`) — часть Given.

## Сценарий (Given-When-Then)

**Given** работа W скачана (orphan-скан создал stub-строку с пустыми
`title`/`author`/`fandom`/`wordCount`, живым `downloadPath`, без рейтинга);
на листинге видна её каноническая карточка; в Library уже присутствуют две
бракетирующие референсные работы (PENDING `wordCount=12000`, KUDOSED
`wordCount=1500`), обе Favorite

**When** пользователь Rate-кнопкой карточки открывает overlay и впервые
нажимает Favorite — код-путь `applyRating(rating=SAVE, comment=null,
dismiss=false)` → `existing.backfillMetadata(work).copy(...)`
(`BrowserViewModel.kt:891-919`, ветка `:897`, `existing != null`, т.к.
stub-строка уже есть); overlay сам НЕ закрывается (`BrowserScreen.kt:350-351`
— и `onSave`, и `onSaveNote` вызывают `applyRating(..., dismiss = false)`
БЕЗУСЛОВНО, независимо от того, какая кнопка нажата) → пользователь явно
закрывает overlay тапом вне карточки (`RatingOverlay.dismiss()`) →
переключается на вкладку Library

**Then** `title`/`author`/`fandom`/`wordCount` строки ЗАПОЛНЕНЫ
каноническими значениями со страницы листинга (`"A Loved Test Work"` /
соответствующий author / `"Fandom Alpha"` / `4200`) — `read_work_ratings_full()`
**And** `downloadPath` остаётся НЕИЗМЕННЫМ — тем же путём на тот же
orphan-файл (backfill не трогает поле, отсутствующее в аргументах `copy`)
**And** сортировка Library «Word count (high to low)» размещает три карточки
СТРОГО в порядке `PENDING(12000) → W(4200) → KUDOSED(1500)` — Y-координата
карточки W (`LibraryScreen.visible_card_y`) СТРОГО МЕЖДУ Y PENDING и Y
KUDOSED, а НЕ ПОСЛЕДНЕЙ в списке. Бракет референсными работами делает
позицию различимым оракулом: если backfill не сработал бы и `wordCount`
остался `NULL`, работа W ушла бы в хвост списка НЕЗАВИСИМО от направления
сортировки (AT-BUG-010) — то есть оказалась бы ПОСЛЕ KUDOSED, а не между
соседями
**And** (ПОСЛЕДНЯЯ проверка кейса, после сортировочной) работа ВПЕРВЫЕ
появляется в фильтр-панели по фандому под `"Fandom Alpha"` (пикер теперь
содержит этот пункт; применение фильтра показывает карточку работы на
вкладке FAVORITE)

**ПОРЯДОК КЛАУЗ Then ОБЯЗАТЕЛЕН (критик-вход rework, B4):** проверка
сортировки трёх карточек идёт ДО проверки фандом-фильтра, а фандом-фильтр —
ПОСЛЕДНЯЯ проверка кейса и НЕ сбрасывается. Причина: применение фильтра
МУТИРУЕТ видимый список — работы других фандомов скрываются (эмпирика
`framework/tests/test_library_filters.py:87-95`, `assert_work_not_in_tab`), а
бракетирующие соседи несут ДРУГИЕ фандомы (PENDING — `Fandom Delta`,
KUDOSED — `Fandom Beta`), поэтому после применения `"Fandom Alpha"` на
экране остаётся ТОЛЬКО карточка W: проверка порядка трёх карточек дала бы
ЛОЖНЫЙ КРАСНЫЙ («карточки не видны», `visible_card_y` → `None`), не вычислив
сам оракул word count. Сброса фильтра существующим примитивом нет:
`LibraryScreen.open_fandom_picker` тапает `by_text("All fandoms")`, а после
применения триггер пикера показывает выбранный фандом (`LibraryScreen.kt:630`
— `draftFandom ?: "All fandoms"`). Проверка пикера в Предусловиях («до оценки
`"Fandom Alpha"` в списке нет») мутацию НЕ вносит — там пикер только
ОТКРЫВАЕТСЯ для чтения списка, фильтр не применяется. Перестановка клауз
Then обратно ломает кейс — автоматизатору менять их порядок нельзя.

- Фандом-фильтр/сортировка — `library_steps.apply_fandom_filter`/

- **Бракетирующие референсные работы (критик-вход rework, B2):** тот же
  приём, что TC-191 — `PENDING`(`12000`)/`KUDOSED`(`1500`) окружают
  канонический `4200`; без них единственная работа в списке (было в attempt
  1) давала тривиальную позицию независимо от значения `wordCount`.
- **Границы `backfillMetadata` (две точки вызова, критик-вход rework):**
  метод применяется в `BrowserViewModel.kt:849` (ветка `rating == null`) и

  ТОЛЬКО `:897`; негативная сторона `:849` уже покрыта `TC-152`; позитивная
  сторона `:849` (пустые поля заполняются при save-note/deselect БЕЗ выбора
  рейтинга) этим проходом НЕ покрыта — граница названа явно, не молчание.

  семантике»: stub-строка создана ДО первой оценки (`existing == null` на
