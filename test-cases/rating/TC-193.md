# TC-193 — Набранная заметка на панели work-страницы переживает закрытие панели без тапа Save

## Предусловия
- Работа W (`ao3_id 900000001`) уже оценена Favorite (`rating=SAVE`), без
  заметки и тегов (`seed_db.seed`).
- Открыта страница работы `/works/900000001`, нижняя навигация раскрыта
  (`BottomNav.ensure_visible()`) — панель `WorkRatingPanel` смонтирована,
  Favorite показан выбранным, поле заметки свёрнуто (пусто).
- Режим replay (`listing_basic.mitm`, не влияет на панель, сверено для
  единообразия окружения с TC-151/TC-155).

## Сценарий (Given-When-Then)

**Given** работа W оценена Favorite, панель work-страницы раскрыта, поле
заметки пусто и свёрнуто

**When** пользователь раскрывает поле заметки (`RatingOverlay.toggle_comment()`)
и вводит текст `"note flushed on dispose"` (`onCommentChange` взводит
`hasUnsavedEdits=true`) — БЕЗ тапа «Save note» и БЕЗ повторного тапа по
рейтингу — после чего переключается на вкладку Library
(`BottomNav.open("Library")`): `WorkRatingPanel` демонтируется,
`DisposableEffect(currentWorkId).onDispose` срабатывает при guard'е
`savedWorkId != null && r != null && hasUnsavedEdits` = `true`

**Then** строка `work_ratings` работы W несёт `comment="note flushed on
dispose"` — заметка сохранена в Room БЕЗ явного тапа Save
(`read_work_ratings_full()` сразу после переключения вкладки)
**And** `rating` строки остаётся `SAVE` — dispose-save пишет ТЕКУЩЕЕ (не
устаревшее) значение рейтинга, видимое на панели в момент закрытия
(`rememberUpdatedState(currentPageRating)`)
**And** `timestamp` строки ИЗМЕНИЛСЯ относительно baseline (различающий
оракул — подтверждает реальный upsert через dispose-save, а не отсутствие
эффекта)

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Работа W | `ao3_id 900000001`, `rating=SAVE`, без заметки/тегов (baseline) |
| Набранный текст | `"note flushed on dispose"` |
| Триггер dispose | переключение вкладки Browse → Library (панель демонтируется) |

## Заметки для автоматизации
- **Пограничная оговорка (задокументирована как ГРАНИЦА, не проверяется
  этим кейсом):** если бы во время набора заметки рейтинг работы изменился
  ИЗВНЕ (другая вкладка/Settings) — dispose всё равно допишет заметку, но с
  ТЕКУЩИМ видимым на панели рейтингом, а не с внешним изменением
  (сознательный выбор разработчика в пользу несохранения набранного текста
  пользователя — dev-комментарий в обсуждении `bugs/BUG-022.md`: «если
  пользователь набрал заметку И параллельно запись изменили извне, dispose
  допишет заметку с видимым на панели рейтингом»). Отдельного сценария под
  эту границу не заводится (не запрошено назначенным пунктом §9, не
  расширяю scope — D-0037).
- Раскрытие поля заметки/ввод текста — `RatingOverlay` (ОБЩИЙ composable
  `RatingMenu` для панели и листингового overlay, `BottomBar.kt` комментарий)
  через `BottomNav.ensure_visible()` + `RatingOverlay.toggle_comment()` +
  `RatingOverlay.enter_comment(text)`, БЕЗ вызова `save_note()` (тот вызвал
  бы явное сохранение, что не тестирует dispose-путь) — начальное поле
  заметки ПУСТОЕ, поэтому известный дефект-собрат `enter_comment.clear()`
  на НЕпустом Compose `BasicTextField` (находка fix-verifier BUG-048,
  `rating_overlay.py:104-108`, задокументирована в TC-152) здесь не
  задействован — выбор Given намеренно обходит его, не полагаясь на починку.
- Триггер dispose — переключение вкладки (`BottomNav.open("Library")`),
  тот же класс демонтирования, что использует `AT-BUG-042`/BUG-022 репро
  (уход с `selectedTab == BROWSE`).
- Оракул — `seed_db.read_work_ratings_full()` (AT-BUG-046, Fixed) — читает
  без остановки приложения, вызывается сразу после переключения вкладки.
- **Батарея правил-реакций (CLAUDE.md) — dispose-save панели квалифицируется
  как правило-реакция (событие E = demount панели, условие C =
  `hasUnsavedEdits`, эффект S = upsert заметки/тегов):**
  - **позитивный путь** — этот кейс (эффект срабатывает при C=true).
  - **edge vs level / off-инвариант** — companion-кейс TC-194 (эффект НЕ
    срабатывает без правок, он же регресс-замок BUG-022); оба bank-пункта
    здесь совпадают в ОДНОМ и том же предикате `hasUnsavedEdits`, поэтому
    покрыты ОДНИМ companion-кейсом, не дублируются.
  - **идемпотентность** — н-п отдельным сценарием: `hasUnsavedEdits`
    детерминированно сбрасывается ТОЛЬКО `onRatingTap` (`:238`), НЕ самим
    dispose — после первого flush повторный dispose БЕЗ нового
    `onCommentChange` неизбежно застаёт `hasUnsavedEdits=false` тем же кодом,
    что доказывает TC-194; отдельного прогона не требуется.
  - **ретроактивность** — н-п: `hasUnsavedEdits` не сеттинг с историей
    (не «включили функцию, объекты размечены раньше»), а посессионный флаг
    текущего инстанса composable — понятие ретроактивности к нему не
    применимо.
  - **propagation** — н-п в скоупе этого пункта §9: узнают ли ДРУГИЕ
    открытые вкладки/консьюмеры о новой заметке без reload — отдельный
    механизм (`broadcastRatingChange`), пересекающийся с `BUG-012`
    (виджет не обновляется без reload), НЕ упомянут в назначенном пункте
    §9 и не переопроектируется этим ходом (не расширяю scope — D-0037).
- Область НЕ комбинаторная (панель × dispose — одна дверь/точка кода, не
  фильтр/сортировка/рейтинг-видимость/backup/tabs/темы) — строка
  `Инвариант:` не требуется.
- Блокеров автоматизации не обнаружено.
