# TC-168 — Restore пустого файла: «Restore failed» с отдельным текстом, данные не изменились

## Предусловия
- Приложение запущено, в Room засеяны работы с рейтингами/заметками/тегами
  и 1 filter-профиль (тот же ненулевой baseline, что TC-167).
- Подготовлен файл `restore_probe_empty.json` — 0 байт; лежит в корне
  `/sdcard/Download`.
- SAF file picker доступен.

## Сценарий (Given-When-Then)

**Given** в Room есть непустой набор работ с рейтингами/заметками/тегами и
1 filter-профиль; подготовлен ПУСТОЙ файл `restore_probe_empty.json` (0
байт)

**When** пользователь выполняет «Restore from backup» и выбирает
`restore_probe_empty.json`

**Then** появляется диалог с заголовком «Restore failed» и текстом «End of
input at character 0 of » (дословно, по измерению CH-007) — ОТЛИЧНЫМ от
текста для не-JSON контента (TC-167): пользователь получает РАЗНЫЕ
сообщения для «файл не того формата» и «файл пуст», хотя оба ведут к
одному и тому же заголовку ошибки
**And** состав Room (`read_work_ratings()`/`read_filter_profiles()`) ПОСЛЕ
попытки Restore идентичен состоянию ДО (та же атомарность, что TC-167)

**Инвариант:** тот же, что TC-167 — отказ Restore атомарен относительно
Room независимо от ПРИЧИНЫ отказа парсинга; этот кейс — второй
representative-случай (пустой ввод вместо валидного-но-не-JSON), доказывающий,
что атомарность не зависит от конкретной причины ошибки.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Файл для Restore | `restore_probe_empty.json` (0 байт) |
| Диалог | «Restore failed» / «End of input at character 0 of » |
| Состав Room до/после | идентичен |
| Текст ошибки vs TC-167 | отличается (разные причины парсинга) |

## Заметки для автоматизации
- Не заблокировано инфраструктурой — та же, что TC-167.
- Файл — 0 байт, создаётся `adb shell touch` (или `echo -n "" >`), кладётся
  в корень `/sdcard/Download`, `rm` до и после теста.
- Явно НЕ дублирует TC-167: разные входные данные дают разные тексты
  ошибки — оба текста явно названы в Then соответствующего кейса, чтобы
  регрессия «оба случая стали показывать одинаковый неинформативный текст»
  была поймана (иначе один кейс с обобщённым «показывает какую-то ошибку»
  замаскировал бы такую регрессию).
- Сверка Room до/после — тот же приём, что TC-167.
- Наблюдаемость негатива — тот же довод, что TC-167 (эффект — состояние
  Room, читается напрямую, класс AT-BUG-029 не относится).
- Батарея правил-реакций — н-п (прямое действие пользователя).
