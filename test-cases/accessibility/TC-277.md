# TC-277 — E-ink DOM-палитра: бейдж/note-кнопка/фон страницы меняются на насыщенные/сплошные/чисто-белые при включении

## Предусловия
- Приложение запущено в replay-режиме на `listing_basic.mitm`; работа
  `LOVED` (`900000001`) засеяна рейтингом `SAVE` и непустым комментарием ДО
  первого рендера (`seed_db.seed_with_comment`, тот же приём, что TC-149) —
  на её блёрбе в листинге отрисованы Rate-бейдж (`data-ao3-rate-btn`,
  `BADGE.SAVE`) и Note-кнопка (`data-ao3-note-btn`).
- Тема — Light (дефолт); E-ink mode OFF (дефолт эталонного AVD).
- Листинговая страница открыта на Browse.
- **Находка дедупа (доклад, не самослияние):** этот Given — ТА ЖЕ пара
  фикстур (`listing_basic.mitm` + LOVED SAVE+comment seed), что уже
  использует `test-cases/accessibility/TC-149.md` (contrast-свип), только
  с другим тумблером (E-ink вместо темы) и другим Then (насыщенность/
  сплошность рамки/фон страницы, не WCAG-ratio). TC-149 уже `Approved` —
  вне манифеста этого дизайна, я его не трогаю и не сливаю сам (П1 dedup:
  «дубль Approved-кейса — доклад координатору, не самослияние»); возможный
  кандидат на объединение в journey — решение Lead/координатора.

## Сценарий (Given-When-Then)

**Given** приложение открыто в replay-режиме на листинговой странице
(`listing_basic.mitm`, Light-тема, E-ink OFF); на блёрбе засеянной работы
`LOVED` видны Rate-бейдж (`data-ao3-rate-btn`) и Note-кнопка
(`data-ao3-note-btn`)

**When**
1. на E-ink OFF (baseline) через `execute_script` читается
   `getComputedStyle` трёх целей: `document.body` (`background-color`),
   Rate-бейдж `LOVED` (`background-color`/`color`/`border-width`), Note-
   кнопка (`border-color` — конкретно её alpha-канал);
2. в Settings включается тумблер «E-ink mode» (тема остаётся Light) —
   приложение САМО перезагружает открытую вкладку листинга
   (`LaunchedEffect(einkMode)`, без отдельного шага теста); тест дожидается
   оседания перезагрузки (тот же барьер, что использует существующий
   reload-путь темы, напр. `wait_ao3_loaded`/эквивалент на CURRENT_URL);
3. на E-ink ON (та же вкладка, тот же `.mitm`-сеанс, свежий рендер после
   reload) те же три цели читаются повторно

**Then**
- `document.body` background-color: OFF → `rgb(250,247,242)` (#faf7f2,
  тёплый) / ON → `rgb(255,255,255)` (#ffffff, чисто белый)
- Rate-бейдж `LOVED` (рейтинг SAVE): OFF → `background-color=#f5ede4`,
  `color=#7a5a42`, `border-width=1px` (приглушённая палитра, тонкая рамка)
  / ON → `background-color=#fff0b3`, `color=#7a5200`, `border-width=2px`
  (насыщенная палитра, вдвое толще рамка)
- Note-кнопка: OFF → `border-color` парсится как `rgba(144,0,0,0.22)`
  (alpha СУЩЕСТВЕННО < 1 — полупрозрачная рамка) / ON → `border-color`
  парсится как `rgb(68,68,68)` (#444444, alpha = 1 — полностью
  непрозрачная сплошная рамка)

**Инвариант:** свойство «палитра/рамка/фон переключаются на eink-вариант»
верно ОДНОВРЕМЕННО для ВСЕХ ТРЁХ целей (фон страницы, бейдж, note-кнопка)
при включении настройки И для ВСЕХ ТРЁХ откатывается при выключении —
проверено в ОБЕ стороны в одном прогоне (OFF-измерение — не предположение,
а реальный замер той же породы, что и ON-измерение), не единственный
пример. Тот же класс инварианта «свойство верно для каждого члена
семьи», что банк C4 «смена темы...» — здесь семья {eink: off/on} ×
{цель: body/badge/note}.

## Проверяемые данные
| Цель | OFF (regular) | ON (eink) |
|---|---|---|
| `document.body` bg | `#faf7f2` | `#ffffff` |
| Rate-бейдж LOVED (SAVE) bg/fg/border-width | `#f5ede4`/`#7a5a42`/`1px` | `#fff0b3`/`#7a5200`/`2px` |
| Note-кнопка border alpha | `rgba(144,0,0,0.22)` (< 1) | `#444444` (alpha = 1) |
| Работа | `LOVED` / `900000001` |
| Фикстура | `listing_basic.mitm` |

## Заметки для автоматизации
- Примитив `execute_script`/`getComputedStyle` — тот же, что TC-149
  (уже отработан, новой инфраструктуры не требует).
- E-ink-тумблер — см. заметку TC-276 (новый `find_row_sibling`-локатор,
  рутина, не блокер).
- **Реализация парсинга alpha из `rgba(...)` — новый код, не блокер:**
  тривиальный парсинг четвёртого компонента CSS `rgba()`-строки,
  возвращаемой `getComputedStyle` — та же категория «рутина поверх уже
  читаемых значений», что формула WCAG-контраста TC-149.
- **Барьер ожидания reload:** приложение перезагружает WebView САМО
  (`BrowserScreen.kt:171-180`), тест не вызывает `reload()` руками — но
  обязан дождаться оседания (иначе гонка того же класса, что
  TC-057/«cannot determine loading status», см. заметки TC-057) — barrier
  по `current_url`/DOM-маркеру после переключения тумблера, до повторного
  чтения `getComputedStyle`.
- **Граница с TC-250:** судьба скролла/пагинации при этом reload уже
  отдельно и полностью покрыта `test-cases/browser/TC-250.md` (P1,
  Approved) — ЭТОТ кейс её не переоткрывает и не ассертит, наблюдает
  только палитру/рамку/фон.
- **Non-goal явно:** цвета остальных рейтингов (LIKE/READ/PENDING/DISLIKE
  в `BADGE`), tag-индикатор (`TAG_FG/TAG_BG/TAG_BORDER`) и tooltip-палитра
  (`getTooltip`) — тот же механизм `pal()`, дрейф между ними и SAVE
  маловероятен (единый источник), но НЕ измерены этим кейсом; чужая
  вёрстка archiveofourown.org — вне скоупа (та же граница §8, что TC-149).
- **Разрешение конфликта фикстуры с TC-149** (доклад, не решение за
  координатора): формально это ТОТ ЖЕ Given, что TC-149 — из П1 dedup
  «не копируй Given ради разных Then, можно один тест подлиннее» этот
  кейс писан бы ВНУТРИ TC-149, но TC-149 уже `Approved` и вне манифеста
  этого дизайна (Граница манифеста, слово Lead 2026-08-20) — редактировать
  чужой Approved-файл нелегально. Кейс оставлен отдельным файлом,
  находка — в отчёте.
