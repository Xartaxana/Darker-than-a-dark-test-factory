# TC-149 — Свип контраста: инжектированные bridge-элементы и наши фикстуры держат WCAG-порог

## Предусловия
- Приложение запущено с чистыми данными, работа W засеяна с рейтингом
  (тот же seed, что TC-009/TC-108) — на странице работы отрисован
  инжектированный Rate-бейдж и Note-кнопка (комментарий у работы засеян).
- Страница работы открыта из НАШЕЙ replay-фикстуры (не живой AO3 — см.
  границу scope ниже).
- Тема приложения переключаема (side panel toggle, тот же примитив, что
  TC-108).

## Сценарий (Given-When-Then)

**Given** страница работы W открыта в Light-теме, видны инжектированные
Rate-кнопка/бейдж (`data-ao3-rate-btn`) и Note-кнопка (`data-ao3-note-btn`),
заголовок работы (`h2.title.heading`) и текстовый узел тела фикстуры
(`.wrapper p`)

**When** для каждого из перечисленных узлов через `execute_script`
вычисляется `getComputedStyle(el).color` против ЭФФЕКТИВНОГО
`background-color` (поднимаясь по родителям до первого непрозрачного фона,
если у самого узла фон прозрачный) и переводится в WCAG-контраст-ratio;
затем тема переключается на Dark (side panel), вычисление повторяется для
тех же узлов

**Then** в Light для КАЖДОГО из перечисленных узлов вычисленный ratio
>= 4.5:1 (обычный текст) либо >= 3:1 (крупный текст — по классификации
`font-size`/`font-weight` узла); та же проверка в Dark даёт тот же результат
для тех же узлов

**Инвариант:** свойство «вычисленный контраст держит свой WCAG-порог»
верно ОДНОВРЕМЕННО для ВСЕХ перечисленных узлов (инжектированные
bridge-элементы + наши фикстурные узлы) И для ОБОИХ системных вариантов
темы (light и dark) — та же тема-семья C4-банка («смена темы не меняет...»),
что TC-108/TC-059; здесь дополнительно проверяется НЕЗАВИСИМОСТЬ свойства
от конкретного узла внутри каждой темы (не только от темы).

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Порог | WCAG 4.5:1 (обычный текст) / 3:1 (крупный текст) |
| Инжектированные узлы | Rate-кнопка/бейдж (`data-ao3-rate-btn`), Note-кнопка (`data-ao3-note-btn`) |
| Фикстурные узлы (НАШИ) | `h2.title.heading` (заголовок), `.wrapper p` (тело) |
| Темы | Light и Dark (обе стороны) |

## Заметки для автоматизации
- Примитив исполнения JS в WebView (`execute_script`) уже применялся в
  протоколе CH-005; переключение темы и скриншот-примитивы уже используются
  TC-047..049/TC-059/TC-108 — новой инфраструктуры не требуется.
- Инжектированные элементы задают цвет ИНЛАЙНОВЫМ `style.cssText`
  (`ao3_bridge.js:191-193,291-292`, сверено с HEAD fdd3f728, было
  148-151/248-252), не через внешний stylesheet/CSS custom
  properties — `getComputedStyle` резолвит их без дополнительных шагов;
  явных селекторов для контраст-проверки НЕ хватает — они уже есть
  (`data-ao3-rate-btn`/`data-ao3-note-btn` — атрибуты, назначенные при
  создании кнопки, стабильны).
- **Реализация формулы контраста — новый код (не блокер):** относительная
  яркость по формуле W3C (sRGB -> linear -> luminance) и подъём по DOM
  до первого непрозрачного `background-color` — рутинная реализация поверх
  уже читаемых `getComputedStyle`-значений, не отсутствующая
  фикстура/сидинг и не неавтоматизируемый штатно UI; test_debt-баг не
  заводится.
- **Граница scope (обязательна, docs/01 §9 — «чужая вёрстка вне скоупа»):**
  свип идёт ТОЛЬКО по нашим инжектированным элементам и по узлам НАШЕЙ
  replay-фикстуры (`build_replay_recordings.py`/`recording_builder.py`), не
  по вёрстке archiveofourown.org — контраст чужого текста живого AO3 НЕ наш
  дефект и не находка этого кейса. Live-режим прогона для ЭТОГО кейса не
  предусмотрен (только replay), чтобы граница выполнялась структурно, а не
  по вниманию исполнителя.
- **dp/px и viewport-масштаб:** контраст — цветовое свойство, не размерное,
  прямой зависимости от `devicePixelRatio`/`textZoom` нет; тем не менее если
  `textZoom` (см. TC-051/TC-145) на момент прогона отличается от 100%,
  классификация «крупный текст» (3:1 вместо 4.5:1) обязана учитывать ТЕКУЩИЙ
  отрендеренный `font-size`, а не номинальный CSS-размер фикстуры — иначе
  порог для одного и того же узла может быть выбран неверно при
  нестандартном `fontSizeStep`. Given этого кейса фиксирует `fontSizeStep`
  на дефолте (0) — комбинация с font-scale вне scope первой итерации.
- **Non-goal явно:** контраст НАТИВНОГО Compose-слоя (кнопки/панели вне
  WebView) остаётся testability gap TC-108 (a11y-дерево не отдаёт цвета) —
  этот кейс его не закрывает и не дублирует TC-108 (тот — luma-sanity
  нативных зон bottom bar/заголовка, не вычисленный WCAG-ratio DOM).
  Динамические состояния (открытый диалог/оверлей, живой снекбар) — вне
  scope, страница работы в обычном (не fullscreen, без открытых оверлеев)
  состоянии.
- **БЛОКЕР (test-automator, 2026-08-20, не test_debt — премиса кейса
  расходится с кодом, не отсутствие фикстуры/тулинга): Given этого кейса
  физически недостижим ОДНИМ открытием страницы.** `data-ao3-rate-btn`/
  `data-ao3-note-btn` инжектируются `ao3_bridge.js` ТОЛЬКО в узлы
  `li[id^="work_"].work.blurb` (см. «Initial injection» :930-955 и
  `fetchAndAppend` :630-654 — оба прохода фильтруют строго по этому
  селектору) — то есть ТОЛЬКО на LISTING-страницах
  (`recording_builder._blurb_html`). Одиночная work-страница
  (`/works/{id}`, `render_work_page_html`) НЕ содержит `li.work.blurb` и
  НЕ получает ни одной инжектированной кнопки ни от JS-бриджа, ни от
  Kotlin-стороны (grep по `app-under-test/.../java` на `data-ao3-rate-btn`/
  `makeRateButton` — 0 совпадений); рейтинг на work-странице отражён
  ТОЛЬКО нативной Compose-панелью (`BrowserViewModel.savePanelRating`,
  см. `app-under-test/CLAUDE.md` «work-page embedded panel»), не WebView
  DOM. Одновременно `h2.title.heading`/`.wrapper p` (WORK_PAGE_CONTENT_
  MARKERS) существуют ТОЛЬКО в `render_work_page_html`, НЕ в `_blurb_html`
  (там заголовок — `h4.heading`). Given требует ОБА набора маркеров на
  ОДНОЙ открытой странице — структурно невозможно при текущей разметке
  фикстур/bridge (сверено чтением `ao3_bridge.js`/`recording_builder.py`
  на HEAD fdd3f728, не только гипотеза). Требуется решение test-designer/
  координатора: либо Given переписывается на ДВЕ точки маршрута (listing
  с блёрбом работы W — Rate/Note-контраст; work-страница — title/body-
  контраст) в рамках одной темы, либо оракул сужается. Test-automator не
  решает это самостоятельно (недоопределённое требование, п.11а
  routing) — TC оставлен `Approved`, `automated_by` пуст.
