# TC-278 — E-ink: side panel открывается мгновенно, без анимационной задержки

## Предусловия
- Приложение запущено с чистыми данными (`clean_app`), вкладка Browse
  активна (любая открытая страница — контент нерелевантен, только сам
  факт, что панель Browse доступна).
- E-ink mode OFF (дефолт эталонного AVD).

## Сценарий (Given-When-Then)

**Given** вкладка Browse активна, side panel свёрнута, E-ink mode OFF

**When** (позиционный зонд — критик-фикс Б2 2026-08-21, БЕЗ замера
времени; старый разностный тайминг T_off/T_on снят целиком, см. заметки
«почему снят замер времени» ниже)
1. на E-ink OFF: панель РАЗВОРАЧИВАЕТСЯ и УСТАКАНИВАЕТСЯ штатным
   `side_panel.expand()` (полный wall-clock запас достаточен, чтобы 200мс
   tween гарантированно завершился) — читается `rect` стабильного
   внутреннего узла панели (`icon_button_container(HOME_DESC)`, см.
   заметки) и запоминается как `rect_expanded_off` (ЭТАЛОН конечного
   развёрнутого положения для OFF); панель сворачивается обратно
   (`collapse()`) и УСТАКАНИВАЕТСЯ (аналогично, `rect` в свёрнутом виде —
   `rect_collapsed_off`, для контроля, что зонд вообще видит разницу
   между состояниями);
2. **зонд OFF:** элемент панели НАХОДИТСЯ ЗАРАНЕЕ (кэшированная ссылка,
   без повторного XML-дампа дерева на каждое чтение), затем выполняется
   СЫРОЙ клик по ручке разворота (`.click()` НАПРЯМУЮ, БЕЗ обёртки
   `element_to_be_clickable`/`tap()`) и НЕМЕДЛЕННО (без ожидания) читается
   `rect` того же кэшированного узла — `rect_probe_off`; панель
   доводится до устойчивого состояния и сворачивается обратно (штатно,
   `collapse()`) для чистоты следующего шага;
3. в Settings включается E-ink mode; пользователь возвращается на Browse;
4. на E-ink ON: тем же способом (`expand()`→settle→`rect_expanded_on`,
   `collapse()`→settle) получается ЭТАЛОН конечного развёрнутого
   положения для ON;
5. **зонд ON:** та же процедура сырого клика + немедленного чтения —
   `rect_probe_on`

**Then**
- (позитивный контроль, доказывает достижимость — ЖЁСТКИЙ ассерт, не
  warning) `rect_probe_off` СУЩЕСТВЕННО ОТЛИЧАЕТСЯ от `rect_expanded_off`
  (зонд, снятый сразу после клика, застаёт панель ЕЩЁ НЕ доехавшей до
  конечного положения — tween ещё в процессе). Если `rect_probe_off`
  совпал с эталоном — тест ОБЯЗАН упасть ИМЕННО на этом ассерте с
  диагностируемой причиной «зонд не успел поймать промежуточный кадр»
  (см. «Достижимость» в заметках — первая гипотеза: не снижен idle-гейт),
  а НЕ продолжать к следующему шагу с этим фактом как молчаливым
  предупреждением.
- `rect_probe_on` РАВЕН `rect_expanded_on` (в пределах пиксельного
  допуска, напр. ±2px) — зонд, снятый сразу после клика, УЖЕ застаёт
  панель в конечном положении, потому что `snap()` перескакивает на
  целевое значение в ТОМ ЖЕ кадре, что и клик, без промежуточных кадров

**Инвариант:** различающая развилка («зонд сразу после клика показывает
конечное положение или нет») ДОСТИЖИМА и НЕ вакуумна ПОТОМУ, что шаг 2
(OFF) — позитивный контроль ТОГО ЖЕ зонда: если бы зонд технически не
мог поймать промежуточное состояние (round-trip клика+чтения медленнее
200мс на конкретной машине), это стало бы ВИДНО уже на OFF-измерении
(`rect_probe_off == rect_expanded_off`, то есть зонд «не успел» —
диагностируется как недостоверность ИНСТРУМЕНТА, а не как «snap
работает одинаково с tween»), а не было бы молча пропущено — см. норму
«направление негативного Then выбирается в дизайне».

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Действие | сырой клик по ручке разворота side panel (`Expand panel` handle), без обёртки-ожидания |
| Зонд | `rect` кэшированного `icon_button_container(HOME_DESC)`, читается НЕМЕДЛЕННО после клика |
| Эталон OFF | `rect_expanded_off` — после штатного `expand()`+settle |
| Эталон ON | `rect_expanded_on` — после штатного `expand()`+settle (E-ink ON) |
| Ожидаемо OFF (tween 200мс) | `rect_probe_off` ≠ `rect_expanded_off` (позитивный контроль) |
| Ожидаемо ON (snap) | `rect_probe_on` = `rect_expanded_on` (±2px) |

## Заметки для автоматизации
- **Почему снят замер времени (критик-фикс Б2, координатор 2026-08-21):**
  первоначальный дизайн мерил `T_off`/`T_on` через `time.time()` вокруг
  `side_panel.expand()` — ДВА независимых дефекта делали этот прибор
  недостоверным: (1) `expand()`
  (`framework/screens/side_panel.py:31-35`) таплю по РУЧКЕ панели, чьё
  `element_to_be_clickable`-ожидание относится к САМОЙ РУЧКЕ (она
  кликабельна сразу), а НЕ к развёрнутому содержимому панели —
  `el.click()` возвращается ДО старта анимации разворота, замер её не
  ловит вовсе; (2) `is_expanded()` = `is_present(by_desc("Collapse
  panel"), timeout=2)`, а в СВЁРНУТОМ состоянии этого узла НЕТ
  (`BrowseSidePanel.kt:154`) — вызов выжигал бы полные 2с таймаута КАЖДЫЙ
  раз, замер тонул бы в шуме таймаута (T_off≈T_on≈2с). Отдельно от этих
  двух — `framework/core/waits.py:26` (`poll_frequency=0.4с`) грубее
  самой измеряемой величины (200мс tween) — разностный замер времени
  через опрос СТРУКТУРНО не тот класс прибора для такой малой величины.
  Заменено на позиционный зонд (вариант (а) из критик-фикса): читает
  `rect` СРАЗУ после клика, без ожидания и без замера времени вообще —
  при tween зонд ловит промежуточное положение, при snap — уже конечное.
- **Зонд — `icon_button_container(HOME_DESC)` (`side_panel.py`, УЖЕ
  существует, TC-057):** контент панели (включая Home-иконку) ПРИСУТСТВУЕТ
  в дереве и в свёрнутом, и в развёрнутом состоянии (докстринг модуля:
  «узел по-прежнему присутствует... не кликабелен, пока анимация не
  завершится») — то есть `rect` этого узла читаем В ЛЮБОЙ момент, не
  только когда кликабелен; смещение узла (его `x`) СЛЕДУЕТ за
  `animateDpAsState`-офсетом панели, что и делает его подходящим зондом
  положения. Элемент находится (`find_element`) ОДИН РАЗ ДО клика и
  кэшируется — повторное чтение `.rect` на уже найденном `WebElement`
  дешевле, чем повторный XML-дамп дерева по локатору, что минимизирует
  round-trip между кликом и чтением.
- **ОБЯЗАТЕЛЬНЫЙ пред-шаг зонда — `app_steps.set_fast_idle_timeout`
  (критик-фикс, 2-й раунд 2026-08-21):** UiAutomator2 по умолчанию ждёт
  «покоя» дерева перед КАЖДЫМ запросом к элементу — измеренный в этом же
  репозитории эффект: дефолтный `waitForIdleTimeout` подвесил
  `find_elements` на 12.9-13.7с во время анимации снекбара
  (`framework/steps/app_steps.py:165-172`, `TC-176.md`). Настройка НЕ
  глобальная (единственный вызов во фреймворке — `test_tabs.py:987`) —
  БЕЗ явного вызова `set_fast_idle_timeout(driver, ms=100)` ПЕРЕД зондом
  чтение `.rect` по умолчанию упрётся в тот же idle-гейт и вернётся,
  скорее всего, уже ПОСЛЕ 200мс tween: `rect_probe_off` систематически
  совпадёт с `rect_expanded_off` — не потому, что зонд «медленный», а
  потому что idle-гейт не снижен.
- **Достижимость — явная обязанность автоматизатора (вариант (в)
  критик-фикса, если (а) на практике не сработает ДАЖЕ с
  `set_fast_idle_timeout`):** если `rect_probe_off` СОВПАДАЕТ с
  `rect_expanded_off` систематически ПОСЛЕ снижения idle-гейта
  (round-trip клика+чтения стабильно превышает 200мс уже без
  idle-задержки — зонд физически не успевает поймать промежуточный
  кадр), Then недостоверен СТРУКТУРНО (см. Инвариант) — автоматизатор
  ОБЯЗАН явно перевести кейс в `Blocked` (`blocked_reason: environment`)
  с указанием замеренного round-trip, а НЕ подгонять допуск/повторять
  попытки до случайного совпадения. Первая гипотеза отказа — НЕ снижен
  idle-гейт (проверить это ДО диагноза «машина медленная»). Тихий обход
  этой развилки — нарушение нормы «достижимость различающего Then».
- **Хрупкость самого приёма (желательно учесть, не блокер):** (а)
  закэшированный элемент может протухнуть при рекомпозиции разворота
  (`StaleObjectException`/stale element на `.rect`) — при такой ошибке
  автоматизатор перезаходит on попытку целиком (новый `find_element` +
  новый клик), а НЕ «перенаходит и сравнивает» тот же зонд постфактум
  (это был бы уже поздний зонд, эквивалент старой сломанной схемы); (б)
  UiObject2 отдаёт ВИДИМЫЕ (обрезанные экраном) bounds — свёрнутая
  панель может иметь отрицательную `x` за левым краем экрана, сравнивать
  нужно клипнутые прямоугольники, не «слой-координаты» узла.
- **E-ink-тумблер** — см. заметку TC-276 (новый `find_row_sibling`-локатор
  «E-ink mode», рутина, не блокер).
- Открытие/закрытие панели переиспользует `side_panel.expand()`/
  `.collapse()`/`.is_collapsed()` — уже существующие примитивы
  (TC-057/058/094/148) — ИСПОЛЬЗУЮТСЯ здесь ТОЛЬКО для достижения
  устойчивых settled-состояний (эталоны `rect_expanded_*`), НЕ как
  измерительный инструмент (их непригодность для тайминга — см. первую
  заметку выше); их собственная функциональная корректность («в итоге
  панель разворачивается») этим не оспаривается.
- **Non-goal явно (остаток вне скоупа, не блокирует закрытие фичи):**
  `einkTween` имеет ЕЩЁ ДВА потребителя ВНЕ `BrowseSidePanel.kt` —
  `MainActivity.kt` scrim-затемнение под Library-меню сортировки
  (`einkTween(150)`) и scrim под side panel (`einkTween(200)`,
  РАЗДЕЛЬНЫЙ от офсета/альфы самой панели узел). Оба используют ТОТ ЖЕ
  код-путь `einkTween` (`snap()` при `LocalEinkMode.current`) — код
  общий, дрейф между потребителями структурно маловероятен, но ЭТОТ
  кейс зондирует ТОЛЬКО панель Browse (пункт с уже готовым стабильным
  внутренним узлом-зондом, `icon_button_container(HOME_DESC)`);
  scrim-затемнения (`Box` с чистым `.background()`, без дочерних
  кликабельных узлов внутри) не имеют аналогичного узла, чей `rect`/
  видимость можно было бы зондировать тем же приёмом — потребовался бы
  alpha-через-скриншот зонд, другой примитив; отдельный кейс/находка для
  test-strategist/test-automator, не
  заводится этим design'ом как блокер (это не отсутствующая
  фикстура/сидинг — это отсутствие удобного измерительного крючка,
  другой класс).
- Ripple-подавление (`Theme.kt:166-172,199-208`, оракул 2 области) и
  overscroll WebView (`BrowserScreen.kt:176,600`, оракул 4 области) —
  этим кейсом НЕ покрыты (за рамками DoD этого дизайн-захода на минимум
  «палитра + snap»), остаются 0 кейсов у `eink-no-ripple-indication` и
  `eink-webview-no-overscroll` — см. финальный отчёт и правку метки §9.

## Чек-лист качества (test-designer проходит перед `Review`)
- [x] Один сценарий — один кейс (один позиционный зонд перехода,
  повторённый для двух состояний тумблера — не два сценария)
- [x] Given описывает полное состояние, воспроизводимое `clean_app`
- [x] Then проверяет наблюдаемое поведение (реальное положение узла
  панели сразу после клика), а не реализацию (не читает `LocalEinkMode`/
  код напрямую, не полагается на `element_to_be_clickable` как таймер —
  критик-фикс Б2)
- [x] Заголовок сформулирован от ожидаемого поведения
- [x] Указаны приоритет, область и источник требования
- [x] Кейс независим от порядка выполнения других кейсов
- [x] Область НЕ комбинаторная в смысле банка C4 (не фильтр/сортировка/
  рейтинг/backup/tabs/тема-персистентность) — но семья {eink: off/on}
  всё же даёт две ветви одного свойства, обе измерены (см. Инвариант
  выше, по духу того же класса, что банк C4, хотя формально вне
  перечисленных категорий)
- [x] Достижимость различающего Then обеспечена ПОЗИТИВНЫМ зондом OFF
  (`rect_probe_off` vs `rect_expanded_off`) в ТОМ ЖЕ прогоне (норма
  «направление негативного Then», см. Инвариант) — не голословное «в
  eink анимации нет»; недостижимость на конкретной машине — явный
  `Blocked`, не молчаливый обход (см. заметки)
- [x] Слой **L3**, «почему не L2» (критик-фикс Б3 — забытая строка):
  оракул — РЕАЛЬНОЕ положение (`rect`) реально отрендеренного Compose-
  узла в момент, определяемый настоящим `animateDpAsState`/`snap()`
  движком анимации Android runtime, зафиксированное настоящим Appium/
  UiAutomator2 round-trip; device-free L2-гарнизон (jsdom) не рендерит
  Compose вовсе и не имеет анимационного движка/кадров, которые можно
  было бы зондировать — L2 структурно неприменим, тот же класс
  аргумента, что TC-276 (native, не только дороже)
