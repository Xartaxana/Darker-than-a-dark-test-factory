# TC-185 — OFF: применение фильтра кнопкой панели не снимает только что выбранный профиль

## Предусловия
- Приложение запущено, replay-режим (`listing_basic.mitm`).
- Фикстура `filter_profile_applied_seeded` — профиль «My saved search» ЕЩЁ
  НЕ активен (`activeFilterId == null` на старте).
- Тумблер «Auto-apply on navigation» — **OFF**.
- Активная вкладка на `LISTING_BASIC_URL` без параметров фильтра, FilterPanel
  раскрыта.

## Сценарий (Given-When-Then)

**Given** тумблер Auto-apply — OFF, активного профиля нет, вкладка на
`LISTING_BASIC_URL`, FilterPanel раскрыта

**When** пользователь ВЫБИРАЕТ профиль «My saved search» из FilterPanel
(`select_filter_option` — это и есть кнопка применения, вызывает
`applyFilter`, который взводит `pendingFilterApplication` при OFF ПЕРЕД
навигацией)

**Then** URL активной вкладки становится `LISTING_FILTERED_URL` (фильтр
ПРИМЕНИЛСЯ — это прямое, ручное действие пользователя, не авто-применение,
и тумблер OFF ему не мешает — `applyFilter` не проверяет `autoApplyFilter`
вовсе)
**And** ПОСЛЕ этой навигации активный профиль ОСТАЁТСЯ «My saved search» —
`pendingFilterApplication`, взведённый самим `applyFilter`, потребляется
`onPageLoaded` БЕЗ вызова `setActiveFilter(null)` — FilterPanel продолжает
показывать «My saved search» как активно применённый
(`assert_active_filter_shown`), в отличие от TC-184, где та же по форме
навигация (загрузка филируемой страницы при OFF) СНИМАЕТ активный профиль

**Инвариант:** флаг `pendingFilterApplication` различает ДВА внешне похожих
события «страница загрузилась при OFF с активным профилем» — навигацию,
инициированную САМИМ применением фильтра (профиль остаётся), и ЛЮБУЮ другую
навигацию (профиль снимается, TC-184); флаг одноразовый — потребляется РОВНО
на следующей загрузке и не защищает последующие переходы.

## Проверяемые данные
| Параметр | Значение |
|---|---|
| Тумблер | OFF |
| Действие | выбор профиля из FilterPanel (кнопка применения) |
| URL после | `LISTING_FILTERED_URL` |
| Активный профиль после | «My saved search» (НЕ снят) |

## Заметки для автоматизации
- Инфраструктура та же, что TC-041/182 — готова.
- Отличие от TC-041: TC-041 не фиксирует состояние тумблера явно (дефолт ON
  для того кейса не создаёт развилки, т.к. `applyFilter` не проверяет
  `autoApplyFilter`); здесь тумблер OFF ЯВНО выставлен и является предметом
  проверки — без этого не отличить TC-185 от TC-041 по сути.
- **Дискриминатор от TC-184** (важно для реализации автотеста): оба кейса
  проверяют состояние ПОСЛЕ загрузки филируемой страницы при OFF, но
  TC-184 — навигация БЕЗ выбора профиля кнопкой (обычный переход/повтор
  URL), TC-185 — навигация, СОЗДАННАЯ самим выбором профиля. Общий
  вспомогательный шаг `select_filter_option` в TC-185 обязателен ДО
  проверки, в TC-184 — отсутствует.
- Блокера автоматизации нет.

## Заметки: батарея правил-реакций
- **edge** внутри OFF-ветки — предмет ИМЕННО этого кейса (исключение из
  общего off-инварианта TC-184); полная раскладка батареи — TC-182.
