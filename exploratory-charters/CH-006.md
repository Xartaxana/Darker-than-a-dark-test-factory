# CH-006 — Пагинация как возмущение

## Mission

Проход /qa-loop 2026-07-30 закрыл ПРЯМЫЕ пути infinite-scroll двумя
scripted-кейсами (TC-130 ON-подгрузка, TC-129 OFF-инвариант) и тем самым
СНЯЛ фикстурный блокер, который дважды останавливал эту зону в
exploratory-очереди (CH-004: «infinite_scroll — БЛОКЕР фикстур»; CH-005
mission_leftover: «infinite_scroll НЕ ТРОНУТ»). Гипотеза сессии: **самое
непокрытое в механизме пагинации — не подгрузка, а его ВТОРИЧНЫЕ контуры,
которые scripted-кейсы объявили non-goal**: (а) эвикция окна
(`PAGE_WINDOW=3`, `ao3_bridge.js:513`, `:594-605` — физическое удаление
DOM-узлов старейшей страницы; явный non-goal TC-130); (б) автопрыжок
плотности (`checkPageDensity`/`navigateEffective`, `ao3_bridge.js:617-629`
— если ВСЕ работы страницы скрыты фильтром и есть next, приложение САМО
уходит на следующую страницу ПОЛНОЙ навигацией; ноль scripted-кейсов, ноль
exploratory-проходов — seam-пара «visibility hide-set × infinite scroll»
из PERTURBATIONS была заблокирована фикстурой); (в) семантика гейта `:530`
на РЕАЛЬНОЙ границе навигации (mid-session переключение тумблера объявлено
Intended-не-живым для ТЕКУЩЕЙ загрузки — но что происходит на СЛЕДУЮЩЕЙ
странице после Next/автопрыжка, не проверял никто). Вторая половина миссии
— остатки CH-005, расшитые ТЕМИ ЖЕ новыми фикстурами: Г7 (live-push
`tap_to_scroll` на СТАРЫХ вкладках — нужны были несколько разных
work-страниц `^/works/\d`, теперь есть `works_multi.mitm`) и ёмкость
снапшотов закрытых вкладок (максимум 5, `BrowserViewModel.kt:330-332` —
фон BUG-016/R-16-кандидата: тихая потеря на границе). Рисковый якорь пуст
сознательно (пути пересекают R-06 видимость, R-08 вкладки, R-11
панель/рендер, R-16-кандидат «тихая потеря ввода/функции» — риск находки
называется в самой находке, прецедент CH-003/004/005).

- **Out:** прямые пути TC-129/TC-130 (только что заскриптованы — анти-дубль);

## Риски и гипотезы

- **Эвикция теряет пользовательское состояние молча (R-16-класс):** rate/note
  на блёрбе страницы N, страница N эвиктится окном — что видит пользователь,
  скролля вверх? Дыра в DOM без перезагрузки? Скачок scroll-позиции
  (scroll anchoring при удалении узлов ВЫШЕ вьюпорта)?
- **Автопрыжок плотности — незапрошенная навигация (R-17-класс по духу):**
  пользователь открыл страницу 1, фильтр скрыл её единственную работу —
  приложение молча увело на страницу 2. Цепочка из 2+ подряд пустых страниц
  — каскад полных навигаций? История back после автопрыжка? Взаимодействие
  с гейтом OFF (`checkPageDensity` гейтится ли `__ao3InfiniteScroll` — по
  коду проверить ДО прогона, вживую подтвердить).
- **Гейт на границе навигации — edge-vs-level:** ON→подгрузка→OFF в
  Settings→Next: новая страница обязана загрузиться БЕЗ подписки (номерная
  пагинация видима «1»/«2»; ловушка: `.next`/`.previous` не прячутся НИ В
  КАКОМ состоянии, различают только номерные пункты). Обратно OFF→ON→Next:
  новая страница подписана. Расхождение = баг гейта, невидимый обоим
  scripted-кейсам (они ставят тумблер ДО первой навигации).
- **Live-push в старые вкладки (Г7):** `LaunchedEffect(tapToScroll)`
  циклится по ВСЕМ живым WebView (`BrowserScreen.kt:187-192`) — но
  подтверждено действием только на активной вкладке. Старая вкладка,
  открытая ДО включения, обязана получить флаг без reload.
- **Ёмкость снапшотов = 5:** 6-е закрытие подряд тихо выталкивает старейший
  снапшот (`BrowserViewModel.kt:330-332`) — undo-цепочка обрывается без
  сообщения (тот же критерий владельца, что BUG-016: «есть сообщение — всё
  норм», нет сообщения — дефект).

## Эвристики / туры

- **Эвикция-тур** (seed 1): infinite ON, листинг стр.1 → подгрузка до
  4-5 страниц (скролл к низу МАКСИМИЗИРУЕТ каскад — заметка TC-130,
  здесь это инструмент, не помеха) → наблюдать `onListingPageAdvanced`,
  состав `_loadedPages`, скачок scrollY при эвикции, дыру при скролле
  вверх; ДО эвикции поставить rate на блёрб стр.1, ПОСЛЕ — оценить, что
  видит пользователь; дабл-тап по Rate-кнопке ПОДГРУЖЕННОГО блёрба
  (остаток seed 4 CH-005 «Нетерпеливый» — там кнопка существует).
- **Плотность-тур** (seed 2): seed_library: работа стр.1 → disliked;
  `hide_disliked` ON ДО навигации → открыть стр.1 → автопрыжок на стр.2
  (полная навигация, pathname/query сменились)? Затем цепочка: disliked
  работам стр.1 И стр.2 → двойной каскад? Поведение back. Тот же заход при
  infinite OFF — гейтится ли density-прыжок. Live-push скрытия ПОСРЕДИ
  открытой страницы (механизм #1 CH-004) → повторная проверка плотности
  срабатывает или прыжок только на загрузке?
- **Граница-навигации-тур** (seed 3): ON→append→OFF→Next и OFF→ON→Next
  (см. гипотезу 3); опорный ассерт — номерные пункты пагинации + снимок
  множества work-id (приёмы TC-129/130 переиспользовать, не изобретать).
- **Старые-вкладки-тур** (seed 4, Г7): `works_multi.mitm`, открыть work-1
  ПЕРВОЙ вкладкой (sticky-контекст Appium прилипает к вкладке-0 — ДИЗАЙН
  сида: старая вкладка = вкладка-0 = attached, наблюдение штатно), work-2
  второй; `tap_to_scroll` OFF→ON из Settings; вернуться на СТАРУЮ
  вкладку-0: `window.__ao3TapToScroll === true` без reload (маркер
  идентичности документа — приём TC-124, `mark_document_identity`) и тап
  по нижней трети реально скроллит.
- **Снапшот-тур** (seed 5): `tab_markers.mitm`, открыть 7+ вкладок,
  закрыть 6 подряд → undo-цепочка: сколько восстановимо, что с 6-м
  (старейшим), есть ли сообщение при выталкивании; граница жизни снекбара
  «Tab closed» — попутный замер (открытый вопрос CH-005 leftover).
- **Бонус-проба** (seed 6, дёшево): открыть СКАЧАННЫЙ локальный файл
  (путь TC-034) при `tap_to_scroll` ON → тап-зоны мертвы (гейт `pathname
  ^/works/\d`, `ao3_bridge.js:1154`, локальный файл не матчится) — жест
  молча отобран на поверхности, где пользователь его ожидает?
  R-16-класс, вердикт — человеку.

## Ловушки (перенос из протоколов/ревью)

- Sticky WEBVIEW-контекст при >1 WebView прилипает к вкладке-0 (класс
  AT-BUG-018/019/022; докстринг `test_tap_zone_guard.py`) — сиды
  спроектированы так, чтобы наблюдаемая вкладка БЫЛА вкладкой-0; для
  нативных действий на других вкладках — координатные тапы/TabStrip.
- `.next`/`.previous` НЕ прячутся ни в одном состоянии тумблера
  (`ao3_bridge.js:541-545`) — свидетель режима только номерные пункты.
- Скролл к самому низу максимизирует каскад подгрузок (заметка TC-130) —
  в эвикция-туре это желаемый инструмент, в границе-навигации-туре
  использовать прицельный `Math.max(1, …)`-скролл (приём TC-130).
- Снекбар «Tab closed» протухает ~2.0-2.7 с (CH-005) — undo жать сразу.
- Пиксельный оракул нижней панели отсутствует (a11y-дерево теряет
  BottomBar при открытой side panel — CH-005 Г1в) — выводы о нижней
  панели только по косвенным свидетелям, не по a11y.
- `wait_document_identity_changed`/`mark_document_identity`
  (`browser_steps.py`) — готовые якоря reload/no-reload, переиспользовать.
